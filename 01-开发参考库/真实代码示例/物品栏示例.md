# 物品栏示例

## 概述

26.1.2 玩家物品栏的槽位索引是**固定整型**，Meteor 封装在 `meteordevelopment.meteorclient.utils.player.SlotUtils`：

| 常量 | 值 | 含义 |
| --- | --- | --- |
| `SlotUtils.HOTBAR_START` / `HOTBAR_END` | 0 / 8 | 快捷栏 9 格（含主手） |
| `SlotUtils.MAIN_START` / `MAIN_END` | 9 / 35 | 背包 27 格 |
| `SlotUtils.ARMOR_START` / `ARMOR_END` | 36 / 39 | 四件护甲 |
| `SlotUtils.OFFHAND` | 40 | 副手 |

查找、交换、移动物品统一走 `InvUtils`（返回 `FindItemResult`）。注意「槽位索引（index）」和「槽位 ID（id）」是两套体系：`SlotUtils.indexToId(int)` 负责把玩家物品栏索引翻译成**当前打开容器**里服务端要的 slot id（不同容器翻译表不同），往容器里收发物品必须用 id。

## 示例 1：槽位常量与索引→ID 翻译

出处：`Meteor原始源码/meteordevelopment/meteorclient/utils/player/SlotUtils.java`（第 23-37 行、第 52-88 行）

```java
public static final int HOTBAR_START = 0;
public static final int HOTBAR_END = 8;
public static final int MAIN_START = 9;
public static final int MAIN_END = 35;
public static final int ARMOR_START = 36;
public static final int ARMOR_END = 39;
public static final int OFFHAND = 40;

public static int indexToId(int i) {
    if (mc.player == null) return -1;
    AbstractContainerMenu handler = mc.player.containerMenu;

    return switch (handler) {
        case InventoryMenu _ -> survivalInventory(i);
        case ChestMenu chestMenu -> genericContainer(i, chestMenu.getRowCount());
        case EnchantmentMenu _ -> enchantmentTable(i);
        case AnvilMenu _ -> anvil(i);
        // ... 其余容器 ...
        default -> -1;
    };
}

private static int survivalInventory(int i) {
    if (isHotbar(i)) return 36 + i;
    if (isArmor(i)) return 5 + (i - 36);
    if (i == OFFHAND) return 45;
    return i;
}
```

要点：
- 玩家物品栏「索引」是 0~40 连续；但**开容器后发给服务端的 slot id 完全不同**（生存物品栏快捷栏是 36+i、副手 45）。
- `indexToId` 按当前 `mc.player.containerMenu` 的类型 switch，误用会换错格甚至丢物品。

## 示例 2：查找物品 & 结果判断（FindItemResult）

出处：`Meteor原始源码/meteordevelopment/meteorclient/utils/player/InvUtils.java`（第 86-126 行）、`FindItemResult.java`（第 16-45 行）

```java
public static FindItemResult findInHotbar(Item... items) {
    return findInHotbar(isOneOf(items));
}

public static FindItemResult findInHotbar(Predicate<ItemStack> isGood) {
    if (testInOffHand(isGood)) {
        return new FindItemResult(SlotUtils.OFFHAND, mc.player.getOffhandItem().getCount());
    }
    if (testInMainHand(isGood)) {
        return new FindItemResult(mc.player.getInventory().getSelectedSlot(), mc.player.getMainHandItem().getCount());
    }
    return find(isGood, 0, 8);
}

public static FindItemResult find(Predicate<ItemStack> isGood, int start, int end) {
    if (mc.player == null) return new FindItemResult(0, 0);
    int slot = -1, count = 0;
    for (int i = start; i <= end; i++) {
        ItemStack stack = mc.player.getInventory().getItem(i);
        if (isGood.test(stack)) {
            if (slot == -1) slot = i;
            count += stack.getCount();
        }
    }
    return new FindItemResult(slot, count);
}
```

`FindItemResult` 记录（来源 `FindItemResult.java` 第 16-45 行）：

```java
public record FindItemResult(int slot, int count) {
    public boolean found() {
        return slot != -1;
    }

    public InteractionHand getHand() {
        if (slot == SlotUtils.OFFHAND) return InteractionHand.OFF_HAND;
        if (slot == mc.player.getInventory().getSelectedSlot()) return InteractionHand.MAIN_HAND;
        return null;
    }

    public boolean isHotbar() {
        return slot >= SlotUtils.HOTBAR_START && slot <= SlotUtils.HOTBAR_END;
    }

    public boolean isMain() {
        return slot >= SlotUtils.MAIN_START && slot <= SlotUtils.MAIN_END;
    }
}
```

要点：
- `findInHotbar` 先检副手、再主手、最后扫 0~8；返回的 `slot` 直接是玩家物品栏索引。
- `found()` 判空、`getHand()` 判归属手、`isHotbar()/isMain()/isArmor()` 判区域。
- 按谓词查找用 `find(Predicate, start, end)`，按具体物品用 `find(Item...)`。

## 示例 3：交换 / 移动物品

出处：`Meteor原始源码/meteordevelopment/meteorclient/utils/player/InvUtils.java`（第 148-170 行、第 209-245 行、第 322-356 行）

```java
// 把快捷栏 slot 设为当前选中格（swapBack=true 记录原槽位）
public static boolean swap(int slot, boolean swapBack) {
    if (slot == SlotUtils.OFFHAND) return true;
    if (slot < 0 || slot > 8) return false;
    if (swapBack && previousSlot == -1) previousSlot = mc.player.getInventory().getSelectedSlot();
    else if (!swapBack) previousSlot = -1;

    mc.player.getInventory().setSelectedSlot(slot);
    ((IMultiPlayerGameMode) mc.gameMode).meteor$syncSelected();
    return true;
}

// 把物品从一个槽位移动到另一个槽位（索引自动转 id）
public static Action move() {
    ACTION.type = ContainerInput.PICKUP;
    ACTION.two = true;
    return ACTION;
}

public Action from(int index) {
    return fromId(SlotUtils.indexToId(index));
}

public void toHotbar(@Range(from = 0, to = 8) int i) {
    to(SlotUtils.HOTBAR_START + i);
}
```

要点：
- `swap(int, boolean)` 只切快捷栏选中格（slot 0~8 或 `OFFHAND`），切完要 `meteor$syncSelected()` 同步本地游戏控制器。
- 跨格移动用流式 API：`InvUtils.move().from(槽位索引).toHotbar(0~8)`，内部 `from(fromId)` 先 `indexToId` 再 `click`。
- `Action` 是共享单例 `ACTION` 复用对象，链式调用后 `run()` 自动重置字段，不能保存引用后再用。

## 示例 4：实战整合——找骨粉并切到主手（本项目）

出处：`src/main/java/com/example/addon/modules/AutoBoneMeal.java`（第 581-598 行）

```java
private InteractionHand findBoneMealHand() {
    // 副手优先
    if (offhandFirst.get() && mc.player.getOffhandItem().is(Items.BONE_MEAL)) return InteractionHand.OFF_HAND;
    // 快捷栏（含主手）
    FindItemResult hotbar = InvUtils.findInHotbar(Items.BONE_MEAL);
    if (hotbar.found()) {
        InvUtils.swap(hotbar.slot(), false);
        return InteractionHand.MAIN_HAND;
    }
    // 背包（排除快捷栏已搜过的 0~8）
    FindItemResult inv = InvUtils.find(Items.BONE_MEAL);
    if (inv.found() && inv.slot() > 8) {
        InvUtils.move().from(inv.slot()).toHotbar(mc.player.getInventory().getSelectedSlot());
        return InteractionHand.MAIN_HAND;
    }
    return null;
}
```

要点：
- 判断持有：`mc.player.getOffhandItem().is(Items.X)` / `getMainHandItem().is(...)`；通用谓词用 `InvUtils.testInHands(Item...)`。
- 快捷栏命中 → `swap(slot, false)`；背包命中（`slot()>8`）→ `move().from(slot).toHotbar(当前选中格)`。
- 都找不到返回 null，由上层的自动暂停逻辑处理（完整性检查）。

## 模式要点

1. **两套槽位体系**：索引（index，0~40，逻辑）vs ID（id，服务端容器 slot id）。`SlotUtils.indexToId()` 只在「和打开容器交互」时才需要。
2. **查找优先副手/主手**：`InvUtils.findInHotbar` 内部自动包含副手和主手，大多数用例直接用它覆盖快捷栏。
3. **选中格切换必须 `syncSelected()`**：`setSelectedSlot` 改的是客户端逻辑，`IMultiPlayerGameMode.meteor$syncSelected()` 才同步到本地交互控制器。
4. **`InvUtils.Action` 是共享单例**：`move()/click()/quickSwap()/shiftClick()/drop()/dropOne()` 返回同一个 `ACTION`，链式 `.from(...).to(...)` 立即执行。
5. **手持判定要区分上下文**：`testInHands`（主/副）、`testInHotbar`（含手持 + 快捷栏）、`testInMainHand`/`testInOffHand` 单侧。

## 常见坑

- **槽位 36~39 是护甲不是背包**：搜背包想避开快捷栏时写 `inv.slot() > 8` 即可覆盖 9~35，但护甲/副手（36~40）要另行处理，别把护甲格当背包格搬。
- **`swap(slot, true)` 忘记 `swapBack()`**：`swapBack=true` 只记录原槽位，之后要 `InvUtils.swapBack()` 才还原，否则选中格停留在换过去的位置。
- **直接往容器塞没转 id**：`InvUtils.move().fromHotbar(i).toMain(j)` 内部已转 id；但你自己调 `mc.gameMode.handleContainerInput(...)` 时必须传 `SlotUtils.indexToId(...)` 后的 id。
- **`getSelectedSlot()` 当成了手握物品槽位**：它返回当前选中的快捷栏索引，实际主手物品是 `mc.player.getMainHandItem()`。
- **`find(Item...)` 扫全背包**（0~35+），副手（40）不包含在内，需要副手时用 `findInHotbar` 或单独 `testInOffHand`。

## 26.1.2 注意

- **`ContainerInput` 是 26.1.2 的新枚举**（`net.minecraft.world.inventory.ContainerInput`），不是旧版 `ClickType`/`SlotActionType`：`PICKUP`、`QUICK_MOVE`、`SWAP`、`THROW`、`CLONE` 等，`InvUtils.Action` 内部就靠它。
- **`handleContainerInput` 签名变了**：`mc.gameMode.handleContainerInput(int containerId, int slotId, int data, ContainerInput input, Player player)`（26.1.2 第 5 参是 `Player`，旧版是 `ClickType`），别再按旧教程传 `ClickType.CLONE`。
- **`IMultiPlayerGameMode` 是 Meteor 的 mixin 接口**（`mixininterface.IMultiPlayerGameMode`），`syncSelected()` 是它提供的方法，不是原版 API。
- **`slot id` 的翻译表随容器变化**：附魔台 `enchantmentTable(i)` 快捷栏是 `29+i`、主区 `2+(i-9)`；漏斗 `hopper(i)` 快捷栏 `32+i`。别用一个写死的偏移套所有容器。
