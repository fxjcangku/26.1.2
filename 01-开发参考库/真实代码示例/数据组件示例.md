# 数据组件示例

## 概述

26.1.2 彻底转向 **Data Component API**（`net.minecraft.core.component.*`）后，物品附魔、耐久、食物属性、容器内容等**全部不再用旧 NBT 标签**，而是用强类型组件：

| 组件 | 读取 | 说明 |
| --- | --- | --- |
| 附魔（装备） | `stack.get(DataComponents.ENCHANTMENTS)` | 返回 `ItemEnchantments` |
| 附魔（附魔书） | `stack.get(DataComponents.STORED_ENCHANTMENTS)` | 附魔书专用 |
| 食物 / 可食用 | `item.components().has(DataComponents.FOOD)` / `DataComponents.CONSUMABLE` | 判断是否为食物 |
| 不可损坏 | `stack.has(DataComponents.UNBREAKABLE)` | 无法损坏的标志 |
| 铁砧修理费 | `stack.getOrDefault(DataComponents.REPAIR_COST, 0)` | 铁砧累积修理惩罚 |

关键类型：`net.minecraft.world.item.enchantment.ItemEnchantments`（不可变集合）、`ItemEnchantments.Mutable`（可编辑）、`EnchantmentHelper`（读写附魔的官方工具）。附魔 ID 用 `Holder<Enchantment>`，取字符串 ID 要 `holder.unwrapKey().map(ResourceKey::identifier).orElse(...)`，**不能直接 `toString()` 或 `getRegisteredName()`**。

## 示例 1：读取装备完整附魔（Data Component API）

出处：`src/main/java/com/example/addon/enchant/gear/EnchantEvaluationService.java`（第 35-49 行）

```java
import net.minecraft.core.Holder;
import net.minecraft.core.component.DataComponents;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.enchantment.Enchantment;
import net.minecraft.world.item.enchantment.ItemEnchantments;

import java.util.LinkedHashMap;
import java.util.Map;

/** 读取装备完整附魔，返回 enchantmentId → 等级的映射。 */
public static Map<String, Integer> readEnchantments(ItemStack stack) {
    Map<String, Integer> result = new LinkedHashMap<>();
    if (stack == null || stack.isEmpty()) return result;

    ItemEnchantments enchantments = stack.get(DataComponents.ENCHANTMENTS);
    if (enchantments == null || enchantments.isEmpty()) return result;

    for (var entry : enchantments.entrySet()) {
        Holder<Enchantment> holder = entry.getKey();
        String id = holder.unwrapKey().map(key -> key.identifier().toString()).orElse(null);
        if (id == null) continue;
        result.put(id, entry.getIntValue());
    }
    return result;
}
```

要点：
- `stack.get(DataComponents.ENCHANTMENTS)` 返回**完整**附魔数据（含隐藏附魔），比 GUI 只读第一行文本可靠。
- `entry.getKey()` 是 `Holder<Enchantment>`，`entry.getIntValue()` 是等级。
- 附魔 ID 字符串用 `unwrapKey().map(k -> k.identifier().toString())` 得到 `"minecraft:sharpness"` 形式。

## 示例 2：装备附魔 + 附魔书存储附魔（区分两种组件）

出处：`src/main/java/com/example/addon/itemid/ItemIdentifier.java`（第 115-138 行）

```java
import net.minecraft.core.component.DataComponents;
import net.minecraft.world.item.enchantment.EnchantmentHelper;
import net.minecraft.world.item.enchantment.ItemEnchantments;

private static List<ItemIdentity.EnchantmentEntry> extractEnchantments(ItemStack stack) {
    List<ItemIdentity.EnchantmentEntry> result = new ArrayList<>();
    // 装备类附魔（ENCHANTMENTS）
    ItemEnchantments enchantments = stack.get(DataComponents.ENCHANTMENTS);
    if (enchantments != null) collectEnchantments(enchantments, result);
    // 附魔书存储附魔（STORED_ENCHANTMENTS）
    ItemEnchantments stored = stack.get(DataComponents.STORED_ENCHANTMENTS);
    if (stored != null) collectEnchantments(stored, result);
    return result;
}

private static void collectEnchantments(ItemEnchantments enchantments,
                                        List<ItemIdentity.EnchantmentEntry> out) {
    for (var entry : enchantments.entrySet()) {
        Holder<Enchantment> holder = entry.getKey();
        int level = entry.getIntValue();
        // 附魔 ID 走 unwrapKey().identifier()
        String id = holder.unwrapKey().map(key -> key.identifier().toString()).orElse("");
        // 中文名：description() 是本地化 Component；完整名（含等级罗马数字）用 getFullname
        String chineseName = clean(holder.value().description().getString());
        String fullName = clean(Enchantment.getFullname(holder, level).getString());
        out.add(new ItemIdentity.EnchantmentEntry(id, chineseName, level, fullName));
    }
}
```

要点：
- 附魔书（`Items.ENCHANTED_BOOK`）的附魔存在 `STORED_ENCHANTMENTS`，普通装备在 `ENCHANTMENTS`，两者类型相同但语义不同，读取要分开。
- 中文名/完整名：`holder.value().description()` 给本地化名，`Enchantment.getFullname(holder, level)` 给带罗马数字的完整名。

## 示例 3：写附魔 / 清附魔（EnchantmentHelper + Mutable）

出处：`Meteor原始源码/meteordevelopment/meteorclient/utils/Utils.java`（第 590-603 行）

```java
import net.minecraft.core.Holder;
import net.minecraft.world.item.ItemStack;
import net.minecraft.world.item.enchantment.Enchantment;
import net.minecraft.world.item.enchantment.EnchantmentHelper;
import net.minecraft.world.item.enchantment.ItemEnchantments;

public static void addEnchantment(ItemStack itemStack, Holder<Enchantment> enchantment, int level) {
    ItemEnchantments.Mutable b = new ItemEnchantments.Mutable(EnchantmentHelper.getEnchantmentsForCrafting(itemStack));
    b.set(enchantment, level);

    EnchantmentHelper.setEnchantments(itemStack, b.toImmutable());
}

public static void clearEnchantments(ItemStack itemStack) {
    EnchantmentHelper.updateEnchantments(itemStack, components -> components.removeIf(a -> true));
}

public static void removeEnchantment(ItemStack itemStack, Enchantment enchantment) {
    EnchantmentHelper.updateEnchantments(itemStack, components -> components.removeIf(enchantment1 -> enchantment1.value().equals(enchantment)));
}
```

要点：
- 写附魔：`new ItemEnchantments.Mutable(现有附魔).set(holder, level).toImmutable()` → `EnchantmentHelper.setEnchantments(stack, ...)`。
- `EnchantmentHelper.updateEnchantments(stack, mutator)` 就地修改附魔集，是清空/移除的标准姿势。
- `getEnchantmentsForCrafting(stack)` 会跳过与创造物品冲突的附魔，造展示物品时用它作种子。

## 示例 4：食物 / 不可损坏 / 修理费 / 耐久判断

出处：`Meteor原始源码/meteordevelopment/meteorclient/utils/Utils.java`（第 201-208 行）+ `src/main/java/com/example/addon/farm/FarmPacketOps.java`（第 152-157 行）+ `src/main/java/com/example/addon/enchant/gear/AnvilPlanner.java`（第 158 行）

```java
// 判断是否为食物（26.1.2：需同时有 FOOD 和 CONSUMABLE 两个组件）
public static boolean isFood(Item item) {
    return item.components().has(DataComponents.FOOD) && item.components().has(DataComponents.CONSUMABLE);
}

// 计算物品剩余耐久（不可损坏返回 Integer.MAX_VALUE）
public static int getRemainingDurability(ItemStack stack) {
    if (stack.isEmpty()) return 0;
    if (!stack.isDamageableItem()) return Integer.MAX_VALUE;
    if (stack.has(DataComponents.UNBREAKABLE)) return Integer.MAX_VALUE;
    return stack.getMaxDamage() - stack.getDamageValue();
}

// 读取铁砧修理费（无则 0）
int repairCost = stack.getOrDefault(DataComponents.REPAIR_COST, 0);
```

要点：
- 26.1.2 食物判定要同时查 `FOOD`（能吃）与 `CONSUMABLE`（可食用动作），只查一个会误判（如鱼桶）。
- 不可损坏用 `stack.has(DataComponents.UNBREAKABLE)`；`isDamageableItem()` 判是否可损坏。
- `getOrDefault(DataComponents.REPAIR_COST, 0)` 读铁砧修理惩罚，用于 AnvilPlanner 评估「太昂贵」。

## 模式要点

1. **读组件**：`stack.get(DataComponents.X)`（缺省返回 null）、`stack.getOrDefault(DataComponents.X, 默认值)`；物品级默认组件用 `item.components().has(DataComponents.X)`。
2. **附魔 ID → 字符串**：`Holder.unwrapKey().map(ResourceKey::identifier).orElse(null)`，得到 `minecraft:xxx`；不要用 `toString()`（含包装格式）或已废弃的 `getRegisteredName()`。
3. **写附魔走 EnchantmentHelper**：改组分 `Mutable.set` + `setEnchantments`；清空/移除用 `updateEnchantments(stack, mutator)`。
4. **附魔书 vs 装备**：`STORED_ENCHANTMENTS`（书）和 `ENCHANTMENTS`（装备/剑镐），类型同为 `ItemEnchantments`。
5. **序列化**：`DataComponentPatch.CODEC` + `registryAccess().createSerializationContext(JsonOps.INSTANCE)` 可把整块组件补丁序列化成 JSON（`ItemIdentifier.serializeComponents` 第 142-155 行用法）。

## 常见坑

- **用旧 NBT 读附魔**：`stack.getOrCreateTag().getList("Enchantments")` 是 26.1.2 之前 / Forge 老写法，本版本已移除，编译不过。
- **附魔 ID `toString()`**：`ResourceKey.toString()` 带 `ResourceKey[...]` 包装、`Holder.toString()` 也可能带 `Reference{...}`，必须 `unwrapKey().identifier()`。
- **把 `STORED_ENCHANTMENTS` 当装备附魔读**：附魔书的附魔在 STORED，读 `ENCHANTMENTS` 拿到的是空。
- **`components.has` 与 `stack.has` 不分**：`item.components().has(...)` 查物品**基础定义**是否有默认组件；`stack.has(...)` 查**具体物品实例**。食物判定前一个、不可损坏后一个。
- **忽略 `CONSUMABLE`**：有的 Item 有 `FOOD` 但没 `CONSUMABLE`（如鱼桶），只判 `FOOD` 会让它们被误当普通食物吃掉。

## 26.1.2 注意

- **`ResolvableProfile` / `ItemEnchantments` 都是不可变对象**：改附魔必须 `ItemEnchantments.Mutable` 复制一份再 `set`，`toImmutable()` 写回；直接改原对象会抛 `UnsupportedOperationException`。
- **`EnchantmentHelper.getEnchantmentsForCrafting`** 是 26.1.2 名称，旧版叫 `getEnchantments`/`getEnchantmentLevel`，抄旧教程会报方法不存在。
- **`EnchantmentHolder` → `Holder<Enchantment>`**：26.1.2 附魔持久化把大量 `EnchantmentHolder` 弱化成 `Holder<Enchantment>`（泛型 TypeUse），调用签名里遇到 `Holder<Enchantment>` 传 `Holder` 即可。
- **`DataComponentPatch.CODEC.encodeStart`** 需要 `RegistryAccess.createSerializationContext(...)`，不能直接用 `DataComponentPatch.CODEC.encodeStart(JsonOps.INSTANCE, patch)`（缺注册表上下文会报「registry not loaded」）。
- **`DataComponents.X` 常量**在 `net.minecraft.core.component.DataComponents`，`net.minecraft.core.component.DataComponentType` 是通用类型；读特定组件用前者的具名常量。
