# 注册表（Registry）

> 源码依据：Minecraft原始源码/net/minecraft/core/（Registry、Holder、MappedRegistry）与 net/minecraft/resources/（Identifier、ResourceKey）与 net/minecraft/core/registries/ 26.1.2 Mojang官方映射

---

## Registry（net.minecraft.core.Registry）

- 包名：`net.minecraft.core`
- 源码路径：`net/minecraft/core/Registry.java`
- 继承与接口：`public interface Registry<T> extends IdMap<T>, Keyable, HolderLookup.RegistryLookup<T>`。
- 给一类对象分配「字符串 id → 数值 id」的双向映射，也是 lookup/tag 的来源。

### 关键方法（签名照抄源码）

```java
ResourceKey<? extends Registry<T>> key();          // 本注册表自己的 key

// 名字 -> 值
@Nullable Identifier getKey(T thing);              // 值 -> 字符串 id
Optional<ResourceKey<T>> getResourceKey(T thing);
@Nullable T getValue(ResourceKey<T> key);
@Nullable T getValue(Identifier key);
default Optional<T> getOptional(Identifier key);
default T getValueOrThrow(ResourceKey<T> key);     // 缺 key 抛 IllegalStateException

// 数值 id
int getId(@Nullable T thing);                      // 继承自 IdMap，稳定网络 id

// 集合遍历
Set<Identifier> keySet();
Set<Entry<ResourceKey<T>, T>> entrySet();
Set<ResourceKey<T>> registryKeySet();
default Stream<T> stream();
Optional<Holder.Reference<T>> getRandom(RandomSource random);
boolean containsKey(Identifier key); boolean containsKey(ResourceKey<T> key);

// Holder
Holder.Reference<T> createIntrusiveHolder(T value);
Optional<Holder.Reference<T>> get(int id);
Optional<Holder.Reference<T>> get(Identifier id);
Holder<T> wrapAsHolder(T value);
Optional<Holder.Reference<T>> getAny();            // 任意一个（常见第一个）

// codec
default Codec<T> byNameCodec();                    // 字符串 id 编解码
default Codec<Holder<T>> holderByNameCodec();

// tag
default Iterable<Holder<T>> getTagOrEmpty(TagKey<T> id);
Stream<HolderSet.Named<T>> getTags();

// 注册（静态工具，注册期/测试用，运行期注册表已冻结）
static <T> T register(Registry<? super T> registry, String name, T value);
static <V, T extends V> T register(Registry<V> registry, Identifier location, T value);
static <V, T extends V> T register(Registry<V> registry, ResourceKey<V> key, T value);
```

## Identifier（net.minecraft.resources.Identifier / 中文常称「资源定位」）

- 源码路径：`net/minecraft/resources/Identifier.java`
- 继承与接口：`public final class Identifier implements Comparable<Identifier>`。
- **Yarn 旧名 `ResourceLocation` 在 26.1.2 已不存在**，统一叫 `Identifier`。等值语义已重写 `equals/hashCode`，可直接当 Map 键。

### 关键字段、常量与方法（签名照抄源码）

```java
public static final char NAMESPACE_SEPARATOR = ':';
public static final String DEFAULT_NAMESPACE = "minecraft";
public static final Codec<Identifier> CODEC;
public static final StreamCodec<ByteBuf, Identifier> STREAM_CODEC;

public static Identifier fromNamespaceAndPath(String namespace, String path);
public static Identifier parse(String identifier);               // 支持缺省命名空间补 minecraft
public static Identifier withDefaultNamespace(String path);
@Nullable public static Identifier tryParse(String identifier);  // 非法返回 null，不抛
@Nullable public static Identifier tryBuild(String namespace, String path);

public String getNamespace(); public String getPath();
public Identifier withPath(String newPath);
public Identifier withPrefix(String prefix);
public Identifier withSuffix(String suffix);
public String toString();          // "namespace:path"
public String toLanguageKey();     // "namespace.path"
public String toShortString();
public static boolean isValidPath(String path);
public static boolean isValidNamespace(String namespace);
```

> 创建用工厂方法，构造函数私有；自动带默认命名空间 `minecraft`（如 `Identifier.parse("stone")` → `minecraft:stone`）。

## ResourceKey（net.minecraft.resources.ResourceKey）

- 源码路径：`net/minecraft/resources/ResourceKey.java`
- 继承与接口：`public class ResourceKey<T>`（不可变，含 registry + 对象两个 Identifier）。
- 用途：标识「某个注册表里的某个值」，是可序列化/可参照的稳定键，不是值本体（比 Yarn 的 `RegistryKey` 同名，注意现在叫 `ResourceKey`）。

### 关键方法（签名照抄源码）

```java
public static <T> ResourceKey<T> create(ResourceKey<? extends Registry<T>> registryName, Identifier location);
public static <T> ResourceKey<Registry<T>> createRegistryKey(Identifier identifier); // 造注册表自身的 key
public static <T> Codec<ResourceKey<T>> codec(ResourceKey<? extends Registry<T>> registryName);

public Identifier identifier();                 // 对象 id 部分
public Identifier registry();                   // 所属注册表 id
public ResourceKey<Registry<T>> registryKey();
public boolean isFor(ResourceKey<? extends Registry<?>> registry);
public <E> Optional<ResourceKey<E>> cast(ResourceKey<? extends Registry<E>> registry);
```

## Holder / Holder.Reference / Holder.Direct（net.minecraft.core.Holder）

- 源码路径：`net/minecraft/core/Holder.java`
- 继承与接口：`public interface Holder<T>`；内嵌 `public record Direct<T>(T value, DataComponentMap components) implements Holder<T>` 与 `public static class Reference<T> implements Holder<T>`。

```java
T value();                       // 值本体
boolean isBound();               // 是否已绑定
boolean is(Identifier key);
boolean is(ResourceKey<T> key);  // 判断身份（常用：holder.is(Enchantments.SHARPNESS)）
boolean is(Holder<T> holder);
boolean is(Predicate<ResourceKey<T>> predicate);
boolean is(TagKey<T> tag);       // 是否属于某 tag
```

- `Holder.Reference`：注册表注册产生的「按 key 引用」holder（网络/存档用）；`Holder.Direct`：直接包住值（动态注册/未进注册表）。
- 现代 API 大量返回 `Holder<T>` 而非裸 `T`；判断「是不是某个注册对象」一律 `holder.is(SomeKey)`，不要 `holder.value() == 某常量`（注册表值可能不是单例）。

## BuiltInRegistries（net.minecraft.core.registries.BuiltInRegistries）

- 源码路径：`net/minecraft/core/registries/BuiltInRegistries.java`
- 运行时实际可用的注册表单例全在这（`public static final Registry<X> / DefaultedRegistry<X>`），是 `Registries` key 对应的实例。客户端 addon 读注册都从这里拿：

```java
public static final DefaultedRegistry<Block> BLOCK;
public static final DefaultedRegistry<Item> ITEM;          // 缺省 air
public static final DefaultedRegistry<EntityType<?>> ENTITY_TYPE;
public static final Registry<Enchantment> ENCHANTMENT? // 运行时经 gameRegistries lookup，见下
public static final Registry<DataComponentType<?>> DATA_COMPONENT_TYPE;
public static final Registry<Attribute> ATTRIBUTE;
public static final Registry<MobEffect> MOB_EFFECT;
public static final Registry<SoundEvent> SOUND_EVENT;
public static final Registry<MenuType<?>> MENU;
public static final Registry<Item> ...;
public static final Registry<? extends Registry<?>> REGISTRY; // 注册表之注册表
// ...（完整字段见源码 BuiltInRegistries.java，共上百个）
```

> 注意：登录后**数据驱动的注册表**（Block/Item/Enchantment 等）以「登录时同步下来的 dynamic registry 快照」为准，见 `Minecraft.getInstance().getConnection().registryAccess()` 返回的 `RegistryAccess.Frozen`；`BuiltInRegistries` 是静态启动期注册表。拿附魔/生物群系/伤害类型等数据驱动值，应经 `registryAccess().lookupOrThrow(Registries.ENCHANTMENT)`。

### RegistryAccess 取值（客户端 addon 常用）

```java
HolderLookup.Provider ra = Minecraft.getInstance().getConnection().registryAccess();
Holder.Reference<Enchantment> sharp = ra.lookupOrThrow(Registries.ENCHANTMENT)
    .getOrThrow(Enchantments.SHARPNESS);   // ResourceKey -> Holder.Reference
```

```java
public interface RegistryAccess { ... }
// RegistryLookup 接口核心（HolderLookup.RegistryLookup）
Holder.Reference<T> getOrThrow(ResourceKey<T> key);
Optional<Holder.Reference<T>> get(ResourceKey<T> key);
Optional<Holder.Reference<T>> get(Identifier id);
```

## MappedRegistry / DefaultedRegistry（net.minecraft.core）

- 路径：`net/minecraft/core/MappedRegistry.java`、`DefaultedRegistry.java`、`DefaultedMappedRegistry.java`
- 实现类。`DefaultedRegistry<T>` 是带「缺省值」的注册表（如 `BuiltInRegistries.BLOCK` 缺省 `Blocks.AIR`、`ITEM` 缺省 `Items.AIR`）。
- 客户端 addon 一般用接口 `Registry<T>` 即可，无需关心实现类。

## 常见坑

1. **别把 `ResourceKey` 当值用**：`Enchantments.SHARPNESS`、`Registries.ITEM` 都是 `ResourceKey`，判断身份 `holder.is(key)`，取本体要 `lookup.getOrThrow(key)` 或 `registry.getValue(key)`。
2. **`Identifier` 不可直接 `new`**：构造私有；一律 `Identifier.parse/fromNamespaceAndPath/withDefaultNamespace`；`parse` 缺命名空间自动补 `minecraft`，`tryParse` 非法返回 `null` 不抛异常。
3. **类名 `Identifier` vs `ResourceLocation`**：Yarn 的 `ResourceLocation` 26.1.2 已不存在，全部换成 `net.minecraft.resources.Identifier`；旧代码 `new ResourceLocation(...)` 全部改 `Identifier.parse(...)`。
4. **`Registry.getRandom` / `getAny` 可能空**：返回 `Optional`，注册表空表时会 empty；`getValueOrThrow` 找不到直接抛 `IllegalStateException`，读外部 key 前用 `getOptional`/`containsKey` 兜底。
5. **数据驱动注册表 vs 静态注册表**：Enchantment/MobEffect/生物群系等以登录同步为准，别用 `BuiltInRegistries` 里的静态视图做「运行时查附魔」，要用 `registryAccess().lookupOrThrow(...)`；两者的 `Holder` 实例可能不同。
