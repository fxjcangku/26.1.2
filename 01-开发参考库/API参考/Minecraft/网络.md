# 网络（Network）

> 源码依据：Minecraft原始源码/net/minecraft/client/multiplayer/... 与 net/minecraft/network/... 26.1.2 Mojang官方映射

客户端 addon 视角下的网络层：收包处理器 `ClientPacketListener`、底层通道 `Connection`、以及 `Minecraft#getConnection()` 的获取与判空。

### 收包机制
`ClientPacketListener` 是客户端在 PLAY 阶段处理所有 `Clientbound*` 包的入口：Netty 收到包 → `Connection.channelRead0` → `packet.handle(listener)` → 命中 `ClientPacketListener` 中 160+ 个 `handleXxx` 方法之一。

## Minecraft#getConnection()（net.minecraft.client.Minecraft）

```java
@Nullable
public ClientPacketListener getConnection() {
    return this.player == null ? null : this.player.connection;
}
```
- 返回类型是 `ClientPacketListener`（**不是** `net.minecraft.network.Connection`）。
- 当 `this.player`（`LocalPlayer`）为 null（未进入世界/退出世界）时返回 `null`——**必须判空**。
- 典型使用：
  ```java
  ClientPacketListener conn = Minecraft.getInstance().getConnection();
  if (conn != null) {
      conn.sendCommand("say hello");
  }
  ```

## Connection（net.minecraft.network.Connection）

### 类信息
- 全限定名：`net.minecraft.network.Connection`
- 包名：`net.minecraft.network`
- 源码路径：`net/network/Connection.java`（即 `net/minecraft/network/Connection.java`）
- 继承：`extends SimpleChannelInboundHandler<Packet<?>>`（Netty 入站处理器）

### 关键方法（真实签名）
```java
public void send(Packet<?> packet);                 // 发送（默认 flush）
public void send(Packet<?> packet, @Nullable ChannelFutureListener listener);
public void send(Packet<?> packet, @Nullable ChannelFutureListener listener, boolean flush);
public boolean isConnected();                        // channel 是否开放
public boolean isConnecting();                       // channel 是否尚未建立
public boolean isMemoryConnection();                 // 本机内存连接（局域网/单机）
public PacketFlow getReceiving();                    // 入站方向（客户端为 CLIENTBOUND）
public PacketFlow getSending();                      // 出站方向 = getOpposite()
public void disconnect(Component reason);           // 断连
public void disconnect(DisconnectionDetails details);
public void setupInboundProtocol(ProtocolInfo<T> protocol, T packetListener);  // 设置入站协议与监听器
public void setReadOnly();                           // 关自动读（断连时）
public SocketAddress getRemoteAddress();             // 对端地址
```

### 字段（关键）
| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `receiving` | `PacketFlow` | 本连接入站方向（`PacketFlow.CLIENTBOUND`） |
| `packetListener` | `volatile PacketListener` | 当前包监听器 |
| `channel` | `Channel` | Netty 通道 |
| `pendingActions` | `Queue<Consumer<Connection>>` | 未连接时缓存的动作队列 |
| `address` | `SocketAddress` | 远端地址 |

### 发送通路
`Connection.send(...)` → `isConnected()` 为真则 `flushQueue()` + `sendPacket(...)`；否则入 `pendingActions` 队列，待连接后统一发出。`sendPacket` 内部在 `channel.eventLoop().inEventLoop()` 为假时 `execute(...)` 转投 Netty 事件线程。

## PacketListener 体系概括

- `net.minecraft.network.PacketListener`：根接口（`flow()`/`protocol()`/`onDisconnect(...)`）。
- `net.minecraft.network.ClientboundPacketListener`：标记客户端收包方向。
- `net.minecraft.network.ServerboundPacketListener`：标记服务端收包方向。
- `net.minecraft.network.protocol.game.ClientGamePacketListener`：PLAY 阶段客户端收包接口（160+ `handleXxx`）。
- `net.minecraft.network.protocol.common.ClientCommonPacketListener`：公共阶段客户端收包接口（keepalive/cookie/transfer 等）。
- `net.minecraft.network.protocol.login.ClientLoginPacketListener`、`status.ClientStatusPacketListener`、`configuration.ClientConfigurationPacketListener`：各状态阶段监听器。
- `net.minecraft.client.multiplayer.ClientCommonPacketListenerImpl`：客户端监听器公共实现基类（`send(Packet)`、`onDisconnect`、`handleDisconnect`、`handleCustomPayload` 等在此实现）。
- 派生子类：`ClientHandshakePacketListenerImpl`、`ClientConfigurationPacketListenerImpl`、`ClientPacketListener`。

## 常见坑

1. **`getConnection()` 判空**：`Minecraft#getConnection()` 在未进世界时返回 null，务必 `if (conn != null)`。更稳妥是再判 `conn.getConnection().isConnected()`。
2. **两个 `getConnection()` 不要混**：
   - `Minecraft#getConnection()` → `ClientPacketListener`（收包处理器）。
   - `ClientPacketListener#getConnection()` → `net.minecraft.network.Connection`（底层通道）。
3. **发送线程**：`sendChat`/`sendCommand` 触碰非线程安全的签名/消息状态，必须在客户端主线程（游戏线程）调用；`Connection.send` 的线程安全仅保证底层投递，不保证业务状态安全。
4. **收包处理器在 Netty 线程之外**：`channelRead0` 通过 `PacketUtils` 抛回客户端主线程执行 `handle`，不要假设 `handle` 在 Netty 线程内运行。
5. **断连监听**：断连时 `Connection.handleDisconnection()` 会调用 `packetListener.onDisconnect(details)`；自定义监听器需实现 `onDisconnect`。
6. **`sendCommand` 有签名语义**：普通 `sendCommand` 走签名通道，服务器可能拒绝裸 `ServerboundChatCommandPacket`，可用 `sendUnattendedCommand`（内部先 `verifyCommand`）。
7. **Yarn 旧名对照（26.1.2 已不存在）**：Yarn 的 `ClientConnection` → 官方 `Connection`；`ClientPlayNetworkHandler` → `ClientPacketListener`；`ClientPlayerEntity` → `LocalPlayer`。引包时一律用官方名。
