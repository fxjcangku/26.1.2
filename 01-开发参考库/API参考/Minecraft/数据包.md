# 数据包（Packet）体系

> 源码依据：Minecraft原始源码/net/minecraft/network/protocol/... 26.1.2 Mojang官方映射

本文覆盖 26.1.2 官方映射中的数据包体系。类名、方法名、字段名、包名逐字沿用官方源码英文原名；客户端 addon（Meteor 体系）开发视角优先。

## 一、包结构（已用 Glob 核实的真实子包）

`net.minecraft.network.protocol` 下真实存在的子包（26.1.2）：

| 子包 | 内容 | 说明 |
| --- | --- | --- |
| `net.minecraft.network.protocol` | `Packet`、`PacketFlow`、`PacketType`、`PacketUtils`、`ProtocolInfoBuilder`、`BundlerInfo` 等 | 根包，定义接口与注册骨架 |
| `net.minecraft.network.protocol.game` | PLAY 阶段包（游戏内、`Serverbound*`/`Clientbound*` 全量） | 客户端 addon 主要打交道的地方 |
| `net.minecraft.network.protocol.common` | 公共阶段包（keepalive/ping/cookie/transfer 等），含子包 `common/custom` | 登录后所有阶段共用 |
| `net.minecraft.network.protocol.configuration` | CONFIGURATION 阶段包（registry 数据、known packs 等） | 1.20.2 起拆分出的配置阶段 |
| `net.minecraft.network.protocol.login` | LOGIN 阶段包，含子包 `login/custom` | 登录握手 |
| `net.minecraft.network.protocol.handshake` | 握手包（`ClientIntentionPacket` 等） | 建立连接第一步 |
| `net.minecraft.network.protocol.status` | 状态查询包（server list ping） | 服务器列表 |
| `net.minecraft.network.protocol.cookie` | cookie 传输包 | 26.1.2 新增 |
| `net.minecraft.network.protocol.ping` | ping/pong 响应包 | 与 `common` 的 keepalive 配套 |

> 注意：26.1.2 **不存在** 名为 `cgame`/`sgame` 的子包。PLAY 阶段的客户端包与服务端包同处于 `protocol/game` 一个包里，仅靠类名前缀 `Clientbound*` / `Serverbound*` 区分方向。

## 二、核心接口与枚举（源码真实签名）

### Packet（net.minecraft.network.protocol.Packet）
```java
public interface Packet<T extends PacketListener> {
    PacketType<? extends Packet<T>> type();
    void handle(T listener);
    default boolean isSkippable() { return false; }
    default boolean isTerminal() { return false; }
    static <B extends ByteBuf, T extends Packet<?>> StreamCodec<B, T> codec(
        final StreamMemberEncoder<B, T> writer, final StreamDecoder<B, T> reader) {
        return StreamCodec.ofMember(writer, reader);
    }
}
```
- `type()` 返回 `PacketType`（方向 + 资源 ID），用于协议注册与分派。
- `handle(T listener)` 是双向分派入口：包内自己调用 `listener.handleXxx(this)`。
- `isSkippable()` / `isTerminal()` 用于 Bundle 与故障处理。
- `codec(...)` 是 StreamCodec 的便捷工厂，几乎所有包都通过它定义编解码。

### PacketFlow（net.minecraft.network.protocol.PacketFlow）
```java
public enum PacketFlow {
    SERVERBOUND("serverbound"),
    CLIENTBOUND("clientbound");
    public PacketFlow getOpposite();
    public String id();
}
```
- `SERVERBOUND` = 客户端→服务端；`CLIENTBOUND` = 服务端→客户端。
- `Connection` 内部用 `receiving` + `getOpposite()` 推导收/发方向。

### PacketType（net.minecraft.network.protocol.PacketType）
```java
public record PacketType<T extends Packet<?>>(PacketFlow flow, Identifier id) {
    public String toString() { return this.flow.id() + "/" + this.id; }
}
```

### PacketListener 体系（net.minecraft.network.PacketListener）
```java
public interface PacketListener {
    PacketFlow flow();
    ConnectionProtocol protocol();
    void onDisconnect(DisconnectionDetails details);
    default boolean shouldHandleMessage(Packet<?> packet);
    ...
}
```
- `net.minecraft.network.ServerboundPacketListener` / `net.minecraft.network.ClientboundPacketListener` 是两个标记式父接口。
- 客户端收包主接口：`net.minecraft.network.protocol.game.ClientGamePacketListener`（PLAY），扩展 `ClientCommonPacketListener`（common 阶段）与 `ClientPongPacketListener`。
- 客户端还有 `ClientLoginPacketListener`、`ClientStatusPacketListener`、`ClientConfigurationPacketListener` 分别对应登录/状态/配置阶段。

## 三、双向包命名规律（26.1.2 已核实：Serverbound/Clientbound 存续）

1.20+ 时代的官方命名 `Serverbound*`（C→S）/ `Clientbound*`（S→C）**在 26.1.2 完整存续**。真实目录 `protocol/game` 内全部移动端包均以这两类前缀命名，无 Yarn 风格的 `C2S`/`S2C`/`PlayerMoveC2SPacket` 等旧名。

判断方向的铁律：
- `ServerboundXxxPacket` → 客户端发送（`PacketFlow.SERVERBOUND`），由 `ServerGamePacketListener` 接收。
- `ClientboundXxxPacket` → 服务端发送（`PacketFlow.CLIENTBOUND`），由 `ClientGamePacketListener` 接收。

## 四、发包的两个真实通道（以源码为准）

统一底层：`net.minecraft.network.Connection`（继承 Netty `SimpleChannelInboundHandler<Packet<?>>`）。

### 通道 1：`Connection.send(...)`
```java
// net.minecraft.network.Connection
public void send(final Packet<?> packet);
public void send(final Packet<?> packet, @Nullable final ChannelFutureListener listener);
public void send(final Packet<?> packet, @Nullable final ChannelFutureListener listener, final boolean flush);
```
- 客户端持有的 `Connection` 通过 `ClientPacketListener#getConnection()` 拿到（返回 `this.connection`）。
- 未连接时消息进入 `pendingActions` 队列；连接建立后 `flushQueue()` 统一发出。
- `sendPacket(...)` 内部检查 `channel.eventLoop().inEventLoop()`，不在事件循环则 `execute(...)` 转移——**这意味着发送线程安全，但最好仍在主线程/游戏线程发起**（见「常见坑」）。

### 通道 2：`ClientCommonPacketListenerImpl.send(...)`
```java
// net.minecraft.client.multiplayer.ClientCommonPacketListenerImpl
public void send(final Packet<?> packet) {
    this.connection.send(packet);
}
```
- `ClientPacketListener` 继承 `ClientCommonPacketListenerImpl`，因此 `ClientPacketListener` 实例具备 `send(Packet)` 能力。
- 客户端几乎所有的 `ServerboundXxx` 包都由 `ClientPacketListener` 内部调 `this.send(...)` 发出。addon 直接拿 `mc.getConnection()`（返回 `ClientPacketListener`）后也能调 `.send(...)`、`.sendCommand(...)`、`.sendChat(...)`。

### 便捷高层方法（也在 ClientPacketListener 内）
- `sendChat(String content)`：组装并发送 `ServerboundChatPacket`。
- `sendCommand(String command)`：解析 + 签名后发 `ServerboundChatCommandPacket` 或 `ServerboundChatCommandSignedPacket`。
- `sendUnattendedCommand(String command, @Nullable Screen screenAfterCommand)`：弹确认窗语义命令发送。

### ServerboundMovePlayerPacket 详解（重要，接入移动需要用）
```java
public abstract class ServerboundMovePlayerPacket implements Packet<ServerGamePacketListener> {
    protected final double x, y, z;       // 位置（仅 hasPos 时有效）
    protected final float yRot, xRot;     // 朝向（仅 hasRot 时有效）
    protected final boolean onGround;     // 是否着地
    protected final boolean horizontalCollision; // 水平碰撞
    protected final boolean hasPos;       // 是否携带位置
    protected final boolean hasRot;       // 是否携带朝向
    // 内部类：
    public static class Pos extends ServerboundMovePlayerPacket {...}        // 只有位置
    public static class PosRot extends ServerboundMovePlayerPacket {...}     // 位置+朝向
    public static class Rot extends ServerboundMovePlayerPacket {...}        // 只有朝向
    public static class StatusOnly extends ServerboundMovePlayerPacket {...} // 只有 onGround/collision
}
```
- `type()` 分别指向 `GamePacketTypes.SERVERBOUND_MOVE_PLAYER_POS` / `..._POS_ROT` / `..._ROT` / `..._STATUS_ONLY`。
- `getX(double fallback)`/`getY`/`getZ`/`getYRot`/`getXRot` 带默认值读取；`hasPosition()`/`hasRotation()` 判断是否携带。

## 七、协议注册骨架（背景）

- `net.minecraft.network.protocol.PacketUtils`：包处理线程调度工具。
- `net.minecraft.network.protocol.game.GameProtocols` / `GamePacketTypes`：PLAY 阶段的协议构建与包类型常量（客户端所有 `PacketType` 常量都定义在此）。
- `net.minecraft.network.protocol.game.CommonPlayerSpawnInfo`：`ClientboundLoginPacket` 携带的出生信息。
- `net.minecraft.network.protocol.PacketType` 的 `id` 是 `Identifier`（如 `game/move_player_pos`）。

## 八、常见坑

1. **`getConnection()` 判空**：`Minecraft#getConnection()`（返回 `ClientPacketListener`）在 `player == null` 时返回 `null`；登录中/未进世界时调用会 NPE。发包前必须判空，且再判 `connection.getConnection().isConnected()`。
2. **`Connection` 不是 `ClientPacketListener`**：`ClientPacketListener#getConnection()` 返回的是 `net.minecraft.network.Connection`（底层通道），而 `Minecraft#getConnection()` 返回的是收包处理器 `ClientPacketListener`。两处同名方法含义完全不同，勿混淆。
3. **发包必须在游戏线程**：`Connection.sendPacket` 虽会异步切到 eventLoop，但 `ClientPacketListener.sendChat/sendCommand` 会访问 `lastSeenMessages`、`signedMessageEncoder` 等非线程安全状态——务必在主线程（渲染/游戏线程）里发。
4. **移动包有 4 个子类**：不要直接 new 抽象类 `ServerboundMovePlayerPacket`，按需 new `Pos`/`PosRot`/`Rot`/`StatusOnly`。
5. **`ServerboundInteractPacket` 是 record**：构造参数顺序 `(entityId, hand, location, usingSecondaryAction)`，`location` 是 `Vec3`。
6. **命令走签名**：`sendCommand` 在有参数时会发 `ServerboundChatCommandSignedPacket`，裸发 `ServerboundChatCommandPacket` 可能因服务端要求签名而被拒绝（`sendUnattendedCommand` 内部会先 `verifyCommand`）。
7. **不要迷信 Yarn 旧名**：26.1.2 官方映射没有 `ClientConnection`（Yarn 旧名对 `Connection`）、`ClientPlayNetworkHandler`（对应 `ClientPacketListener`）等，写 Import 时用官方名。
