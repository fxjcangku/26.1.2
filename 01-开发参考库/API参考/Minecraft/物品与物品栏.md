# 物品与物品栏（Item & Inventory）

> 源码依据：Minecraft原始源码/net/minecraft/world/item/ 与 net/minecraft/world/inventory/ 26.1.2 Mojang官方映射

---

## ItemStack（net.minecraft.world.item.ItemStack）

- 包名：`net.minecraft.world.item`
- 源码路径：`net/minecraft/world/item/ItemStack.java`
- 继承与接口：`public final class ItemStack implements DataComponentHolder, ItemInstance`。
- 客户端 addon 操作物品的唯一核心数据结构，**不可变值语义**：修改后返回新实例。背包/容器/掉落物里存的都是它。

### 关键字段与常量

```java
public static final ItemStack EMPTY;    // 空物品（item == null），is == 判断
```

### 关键方法——组件读写（走 DataComponentHolder，签名照抄源码）

```java
@Nullable
public <T> T get(DataComponentType<? extends T> type);                 // 读组件，不存在返回 null
public <T> T getOrDefault(DataComponentType<? extends T> type, T defaultValue); // 读不到给默认值
public <T> T set(DataComponentType<T> type, @Nullable T value);        // 写组件，返回旧值；value=null 等价删除
public <T> T remove(DataComponentType<? extends T> type);              // 删除组件，返回旧值
public <T> T update(DataComponentType<T> type, T defaultValue, UnaryOperator<T> function); // 读-改-写
public <T, U> T update(DataComponentType<T> type, T defaultValue, U value, BiFunction<T, U, T> combiner);
public DataComponentMap getComponents();   // 取全部组件快照
public DataComponentMap getPrototype();    // 物品原型（默认组件）
```

```java
// 物品类型
public Item getItem();                 // 物品类型；空物品返回 Items.AIR
public Holder<Item> typeHolder();      // 注册 Holder，判断/序列化用

// 数量
public int getCount();
public void setCount(int count);
public void grow(int amount);          // 数量 += amount（最大 maxStackSize）
public void shrink(int amount);        // 数量 -= amount，<=0 变 EMPTY
public ItemStack split(int amount);    // 从本组拆出 amount 个（返回新组，本组相应减少）

// 复制
public ItemStack copy();               // 深拷贝（含组件）
public ItemStack copyWithCount(int count);
public ItemStack copyAndClear();       // 拷贝后本组清空
public ItemStack transmuteCopy(ItemLike newItem);            // 换类型保留组件
public ItemStack transmuteCopy(ItemLike newItem, int newCount);

// 耐久（Damage 组件驱动的耐久条）
public boolean isDamageableItem();     // 是否有耐久
public boolean isDamaged();            // 耐久 > 0 已受损
public int getDamageValue();           // 已损耐久
public void setDamageValue(int value);
public int getMaxDamage();             // 最大耐久（MAX_DAMAGE 组件）

// 附魔（详见 附魔.md）
public ItemEnchantments getEnchantments();   // 物品上的附魔（ENCHANTMENTS 组件）

// 显示
public Component getHoverName();       // 显示名（含 CUSTOM_NAME）
public Component getItemName();        // 物品本名
public boolean hasFoil();              // 是否附魔光效（含 ENCHANTMENT_GLINT_OVERRIDE）
public boolean isEmpty();              // 是否 EMPTY
public boolean is(Predicate<Holder<Item>> predicate); // 类型判断
```

> `ItemStack` **没有** Yarn 里的 `getNbt()/setNbt()/getOrCreateNbt()`（26.1.2 已不存在）。数据全部走组件系统：组件外的数据无法再像旧版 NBT 那样随意塞入。客户端要读任意已注册组件用 `get(DataComponents.XXX)`。

## Items（net.minecraft.world.item.Items）

- 源码路径：`net/minecraft/world/item/Items.java`
- 所有物品的注册常量都在这：`public static final Item DIAMOND_PICKAXE`、`public static final Item ENCHANTED_BOOK` 等，命名规则 `大写_蛇形`。
- 判断某个 `ItemStack` 是不是某物品直接比引用：`stack.getItem() == Items.DIAMOND_PICKAXE`，或 `stack.is(Items.DIAMOND_PICKAXE::equals)`。
- 空物品：`Items.AIR`（`ItemStack.EMPTY.getItem()` 返回它）。

## ItemInstance（net.minecraft.world.item.ItemInstance）

- 源码路径：`net/minecraft/world/item/ItemInstance.java`
- 继承与接口：`public interface ItemInstance extends TypedInstance<Item>, DataComponentGetter`。
- `ItemStack` 实现了它；很多只读 API（如 `EnchantmentHelper.getItemEnchantmentLevel(Holder<Enchantment>, ItemInstance)`）收的是 `ItemInstance` 而不是 `ItemStack`，两者可混用。

```java
int count();
default int getMaxStackSize();   // 返回 MAX_STACK_SIZE 组件值，默认 1
```

## Inventory（net.minecraft.world.entity.player.Inventory）

> 详见 `玩家.md`。这里只复述跨容器操作必须分清的关键槽号：

| 区间 | 槽号 | 含义 |
|------|------|------|
| 快捷栏 | `0~8` | 选中槽下标（`SELECTION_SIZE=9`） |

| 装备槽 | `36=鞋 37=腿 38=胸 39=头` | `getItem(36..39)` 自动查 `EQUIPMENT_SLOT_MAPPING` |
| 副手 / body / 鞍 | `40 / 41 / 42` | `SLOT_OFFHAND / SLOT_BODY_ARMOR / SLOT_SADDLE` |

public int findSlotMatchingItem(ItemStack stack);
public ItemStack removeItem(int slot, int count);
public int getSelectedSlot(); public void setSelectedSlot(int selected);

```

## AbstractContainerMenu（net.minecraft.world.inventory.AbstractContainerMenu）

- 源码路径：`net/minecraft/world/inventory/AbstractContainerMenu.java`
- 继承与接口：`public abstract class AbstractContainerMenu`（`Inventory` 的 `InventoryMenu` 是它子类）。
- 客户端通过它收发容器操作；**26.1.2 点击方法参数从 `SlotActionType` 改为枚举 `ContainerInput`**。

public static final int SLOT_CLICKED_OUTSIDE = -999;  // 点击容器外

```

### 关键方法（签名照抄源码）

```java

public void setItem(int slot, int stateId, ItemStack itemStack);   // 服务端下发槽内容（stateId 为同步序号）
public void initializeContents(int stateId, List<ItemStack> items, ItemStack carried);

// 光标携带物（拿起/放下）
public ItemStack getCarried();
public void setCarried(ItemStack carried);

// 点击分发（客户端模拟点击/物品转移入口）

public boolean clickMenuButton(Player player, int buttonId);
public void slotsChanged(Container container);        // 容器内容变化回调

```

### 26.1.2 注意
- `ContainerInput`（`net.minecraft.world.inventory`）是枚举：`PICKUP / QUICK_MOVE / SWAP / CLONE / THROW / QUICK_CRAFT / PICKUP_ALL`，Yarn 旧名 `SlotActionType` 已不存在。
- `slots` 的 index 是**菜单内**槽下标（不是玩家 `Inventory` 那套 0~42）；`Slot.getContainerSlot()` 才给出容器视图内的逻辑槽号，跨容器操作务必分清两套下标。

## 常见坑

1. **`ItemStack.EMPTY` 判断**：空物品用 `stack.isEmpty()`（内部 `stack == EMPTY || count<=0`）；不要用 `stack == null`（槽里永远是 `ItemStack.EMPTY` 不是 null）。
2. **`ItemStack` 值语义 + `set` 返回旧值**：`get/set/update/remove` 都是基于组件的新实例语义，`set(type, value)` 返回的是**旧值**不是新物品；要拿到修改后的副本自己持有 `stack.set(...)` 后的 `stack`，别依赖返回值判断成功。
3. **没有 `getOrCreateTag()`**：Yarn 旧 API `getNbt()/getOrCreateNbt()/setNbt()` 26.1.2 全部移除，改成 `get(DataComponents.CUSTOM_DATA)`；想存自定义数据用 `CustomData` 组件，否则无处安放。
4. **`getItem() == Item` 才是可靠的同类型判断**：`ItemStack.is(...)` 收的是 `Predicate<Holder<Item>>`，写 `stack.is(Items.DIAMOND_PICKAXE)` 会编译失败，要用 `stack.is(item -> item.value() == Items.DIAMOND_PICKAXE)`，最简就是 `stack.getItem() == Items.DIAMOND_PICKAXE`。
5. **菜单槽号 ≠ 玩家背包槽号**：`menu.slots` 下标是菜单内部序；合成台/容器的合成格下标、玩家快捷栏在菜单里的下标（如 `9+`），与 `player.getInventory().getItem(0..8)` 完全不同。跨容器真实转移用 `Slot.safeInsert/safeTake` 或 `menu.clicked(...)`，不要手改 `slot.set(...)` 而不做同步。
