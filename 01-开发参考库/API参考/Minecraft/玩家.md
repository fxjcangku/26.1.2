# 玩家（Player）

> 源码依据：Minecraft原始源码/net/minecraft/world/entity/player/ 与 net/minecraft/client/player/ 26.1.2 Mojang官方映射

玩家相关类分两条线：

- 逻辑侧（双端通用）：`net.minecraft.world.entity.player.Player`。
- 客户端侧（仅客户端，`@Environment(EnvType.CLIENT)`）：`net.minecraft.client.player.AbstractClientPlayer` → `LocalPlayer` / `RemotePlayer`。

类名冲突提醒：`net.minecraft.world.entity.player.Player` 是**玩家实体**（服务端 `ServerPlayer` 与客户端 `AbstractClientPlayer` 的共同基类），不是 Yarn 里的 `PlayerEntity`。`PlayerEntity` 是 Yarn 旧名，26.1.2 已不存在。

---

## Player（net.minecraft.world.entity.player.Player）

- 包名：`net.minecraft.world.entity.player`
- 源码路径：`net/minecraft/world/entity/player/Player.java`
- 继承与接口：`public class Player extends LivingEntity`（同时实现 `Nameable`、`ItemInstance` 等通过 `Inventory` 暴露；`LivingEntity` 继承链 `Entity`）。
- 客户端常用场景：ADdon 里拿到的是一个 `Player`（可能是 `LocalPlayer`、`RemotePlayer` 或服务端投影），获取背包/食物/能力/物品都走这一层。

### 关键字段（源码真实名，部分为 protected/private）

| 字段 | 类型 | 说明 |
|------|------|------|
| `inventory` | `private final Inventory` | 36 格背包 + 装备栏，见下方 `Inventory` |
| `foodData` | `protected FoodData` | 饥饿/饱和/消耗度 |
| `abilities` | `private final Abilities` | 飞行/创造/无敌等能力 |
| `experienceLevel` / `totalExperience` / `experienceProgress` | `public int` / `public int` / `public float` | 经验等级/总经验/升级进度 |
| `cooldowns` | `private final ItemCooldowns` | 物品冷却（通过 `getCooldowns()` 获取） |
| `enchantmentSeed` | `protected int` | 附魔种子 |

### 关键方法（签名照抄源码声明行）

```java
// 背包 / 能力 / 食物（最常被客户端脚本调用）
public Inventory getInventory();      // 返回 36 格背包 + 装备槽，配合 getItem(int slot)
public Abilities getAbilities();      // 直接读写 flying/mayfly/instabuild/mayBuild 等
public FoodData getFoodData();        // 饥饿度，见 FoodData
public ItemCooldowns getCooldowns();  // 物品冷却（吃金苹果等）

// 游戏模式
public abstract GameType gameMode();  // 抽象方法；客户端由 AbstractClientPlayer 实现，可能为 null
public boolean isCreative();          // return this.gameMode() == GameType.CREATIVE;
public boolean isSpectator();         // return this.gameMode() == GameType.SPECTATOR;
public boolean hasInfiniteMaterials();// 创造模式：物品/耐久无限，客户端常用作“创造判断”

// 物品
public boolean addItem(ItemStack itemStack);          // 尝试向背包放一个 ItemStack
public ItemStack getItemInHand(InteractionHand hand); // 继承自 LivingEntity，取主/副手
public ItemStack getMainHandItem();                   // 继承自 LivingEntity，取主手
public ItemStack getOffhandItem();                    // 继承自 LivingEntity，取副手

// 交互范围（26.1.2 交互距离已组件化）
public double blockInteractionRange();   // 方块交互距离（默认 4.5）
public double entityInteractionRange();  // 实体交互距离（默认 3.0，创造 +2.0）
public boolean isWithinEntityInteractionRange(Entity entity, double buffer);
public boolean isWithinBlockInteractionRange(BlockPos pos, double buffer);

// 建造 / 合法放置
public boolean mayBuild();
public boolean mayUseItemAt(BlockPos pos, Direction direction, ItemStack itemStack);

// 经验
public void giveExperiencePoints(int i);
```

### 26.1.2 注意事项
- `Player` 常量：`MAX_HEALTH = 20`；`DEFAULT_BLOCK_INTERACTION_RANGE = 4.5F`、`DEFAULT_ENTITY_INTERACTION_RANGE = 3.0F`（源码第 133-134 行）。
- `hurt` 改名：伤害入口是 `hurtServer(ServerLevel, DamageSource, float)`（源码），客户端另有 `Entity.hurtClient(DamageSource)`。Yarn 旧名 `damage()` 已不存在。
- `gameMode()` 在客户端可能返回 `null`（玩家信息未加载时）；判断创造/旁观优先用 `isCreative()`/`isSpectator()` 或 `Minecraft.getInstance().gameMode.getPlayerMode()`。

### 发指令的正确姿势
`sendCommand` 不在 `Player`/`LocalPlayer` 上，而在 `net.minecraft.client.multiplayer.ClientPacketListener`：

```java
public void sendCommand(final String command);  // ClientPacketListener.java
// 调用：Minecraft.getInstance().player.connection.sendCommand("/gamemode creative")
```

### 26.1.2 注意事项
- 输入不再是旧的 `MovementInput`（Yarn 旧名），26.1.2 用 `ClientInput`（`keyPresses : net.minecraft.world.entity.player.Input` + `moveVector : Vec2`）。
- `xxa / zza / jumping` 是 `LivingEntity` 的 protected 字段，由 `applyInput()` 每 tick 从 `input` 写入；直接改 `input` 才会被服务器同步。
- `LocalPlayer` 客户端权威判断：`isLocalPlayer()` 返回 `true`（重写自 Player）。判空务必先 `Minecraft.getInstance().player != null`。

- 源码路径：`net/minecraft/world/entity/player/Inventory.java`
- 继承与接口：`public class Inventory implements Container, Nameable`。

### 插槽号规则（26.1.2 真实常量，务必背熟）

| 常量 | 值 | 含义 |
|------|----|------|
| `INVENTORY_SIZE` | `36` | `items` 列表长度（0~35） |
| `SELECTION_SIZE` | `9` | 快捷栏 0~8 |
| 装备槽映射 `EQUIPMENT_SLOT_MAPPING` | — | `36=FEET, 37=LEGS, 38=CHEST, 39=HEAD, 40=OFFHAND, 41=BODY, 42=SADDLE` |

| `SLOT_BODY_ARMOR` | `41` | 马铠/狼甲 body 槽 |
| `SLOT_SADDLE` | `42` | 鞍（坐骑用） |

## 常见坑

1. **`Minecraft.getInstance().player` / `level` 判空**：标题界面、世界加载切换中两者都可能为 `null`，任何 addon 入口先判空，否则 NPE。
2. **`player.gameMode()` 可能为 `null`**：客户端用 `PlayerInfo.getGameMode()` 回填，尚未同步时为 null；判断模式用 `isCreative()`（内部已处理）或 `mc.gameMode.getPlayerMode()`。
3. **改能力后必须同步**：直接改 `abilities.flying = true` 不会自动发服务器，客户端要调 `player.onUpdateAbilities()`（LocalPlayer 已重写为发包），否则服务端不认。
4. **背包插槽号混淆**：`Inventory.getItem(0..8)` 是快捷栏而非 9 号；护甲是 `36~39`、副手 `40`。合成/容器界面里 `Slot.getContainerSlot()` 与玩家 `Inventory` 槽号不是一套，跨容器操作要分清 `container`。
5. **`LocalPlayer.heal` 是空实现**：客户端本地玩家不会因 `heal()` 回血，血量由服务器同步；本地想改血用 `hurtTo()` 或直接 `setHealth()`（仅显示层，服务器会覆盖）。
