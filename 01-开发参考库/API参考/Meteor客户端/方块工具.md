# 方块工具

> 源码依据：Meteor原始源码/meteordevelopment/meteorclient/utils/world/... Meteor Client 26.1.2-SNAPSHOT

本文以 **addon 模块作者** 视角，整理 Meteor 26.1.2 中与「方块放置 / 破坏 / 遍历 / 方向」相关的工具类。所有方法签名均照抄源码，未在源码中出现的旧版 API（如 `placeBlock`、`BlockData`/`BlockDataSetting`）已明确标注。

---

## BlockUtils

### 类名
`meteordevelopment.meteorclient.utils.world.BlockUtils`

### 包名
`meteordevelopment.meteorclient.utils.world`

### 源码路径
`utils/world/BlockUtils.java`

### 继承与接口
无继承（`public class BlockUtils`），构造器私有（`private BlockUtils()`），纯静态工具类。类内通过 `@PreInit` 把自身订阅到 `MeteorClient.EVENT_BUS`。

### 关键字段
| 字段名 | 类型 | 中文用途 |
| --- | --- | --- |
| `breaking` | `public static boolean` | 表示当前是否处于「持续挖方块」状态，由 `breakBlock(...)` 置 `true`，tick 末自动复位 |
| `MobSpawn`（内部枚举） | `enum` | 刷怪判定结果：`Never` / `Potential` / `Always` |

### 关键方法（真实签名照抄）

**放置类**。注意：26.1.2 中方法名是 `place`，不存在 `placeBlock`。

```java
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, int rotationPriority)
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, boolean rotate, int rotationPriority)
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, boolean rotate, int rotationPriority, boolean checkEntities)
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, int rotationPriority, boolean checkEntities)
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, boolean rotate, int rotationPriority, boolean swingHand, boolean checkEntities)
public static boolean place(BlockPos blockPos, FindItemResult findItemResult, boolean rotate, int rotationPriority, boolean swingHand, boolean checkEntities, boolean swapBack)
public static boolean place(BlockPos blockPos, InteractionHand hand, int slot, boolean rotate, int rotationPriority, boolean swingHand, boolean checkEntities, boolean swapBack)
```
- 用途：把指定槽位的方块放置到 `blockPos`。`FindItemResult` 来自 `InvUtils` 的找物品结果，`slot` 必须是 0-8 热键栏。放置位置不一定能直接点击，Meteor 会自动找一个相邻方块侧面（`getPlaceSide`）作为点击面，再调用 `interact` 发包。
- 使用场景：addon 做「自动搭桥 / 自动放置黑曜石」时，先 `InvUtils.findInHotbar(...)` 拿到 `FindItemResult`，再 `BlockUtils.place(pos, item, 0)`。

**交互 / 放置判定**

```java
public static void interact(BlockHitResult blockHitResult, InteractionHand hand, boolean swing)
public static boolean canPlaceBlock(BlockPos blockPos, boolean checkEntities, Block block)
public static boolean canPlace(BlockPos blockPos, boolean checkEntities)
public static boolean canPlace(BlockPos blockPos)
public static Direction getPlaceSide(BlockPos blockPos)
public static Direction getClosestPlaceSide(BlockPos blockPos)
public static Direction getClosestPlaceSide(BlockPos blockPos, Vec3 pos)
```
- `interact`：临时取消潜行，用 `mc.gameMode.useItemOn(...)` 右键方块面，必要时挥动手（发送 `ServerboundSwingPacket`）。
- `canPlaceBlock`：检查 y 坐标是否可生成、目标方块是否可被替换、方块是否与其他实体碰撞。
- `getPlaceSide` / `getClosestPlaceSide`：按视线方向或与玩家距离挑选合适的放置贴面。

**破坏类**

```java
public static boolean breakBlock(BlockPos blockPos, boolean swing)
public static boolean canBreak(BlockPos blockPos, BlockState state)
public static boolean canBreak(BlockPos blockPos)
public static boolean canInstaBreak(BlockPos blockPos, float breakSpeed)
public static boolean canInstaBreak(BlockPos blockPos)
public static float calcBlockBreakingDelta2(BlockPos blockPos, float breakSpeed)
helper public static double getBreakDelta(int slot, BlockState state)
```
- `breakBlock`：**必须在 `TickEvent.Pre` 中调用**（源码注释明确要求）。会联动 `InstantRebreak` 模块（如存在且激活则直接发包秒破）。`swing=true` 挥动手，否则只发包。
- `canBreak`：非创造模式下检查 `getDestroySpeed < 0`（基岩等不可破坏）以及碰撞形状是否为空。
- `canInstaBreak`：判断是否能「瞬间破坏」。
- 使用场景：addon 做「自动挖矿」时，在 `@EventHandler TickEvent.Pre` 里循环调用 `BlockUtils.breakBlock(...)`。

**其他**

```java
public static boolean isClickable(Block block)
public static MobSpawn isValidMobSpawn(BlockPos blockPos, BlockState blockState, int spawnLightLimit)
public static boolean isValidSpawnBlock(BlockState blockState)
public static Direction getDirection(BlockPos pos)
public static boolean isExposed(BlockPos blockPos)
public static BlockPos.MutableBlockPos mutateAround(BlockPos.MutableBlockPos mutable, BlockPos origin, int xOffset, int yOffset, int zOffset)
```
- `isClickable`：判断方块是否有 GUI / 交互（工作台、铁砧、门、按钮、床、音符盒等）；`getPlaceSide` 会跳过可点击、空气、流体方块。
- `isValidMobSpawn`：结合雪层、亮度、下方方块判断刷怪可行性，返回 `BlockUtils.MobSpawn`。
- `isExposed`：任意一个方向相邻方块非 `isSolidRender()` 即露空。
- `mutateAround`：快速把 `MutableBlockPos` 设为相对 `origin` 的偏移坐标（递归遍历用）。

### 相关类
- `meteordevelopment.meteorclient.utils.player.FindItemResult`（`place` 的入参来源）
- `meteordevelopment.meteorclient.utils.player.InvUtils`、`SlotUtils`、`Rotations`（放置时切槽、朝向）

### 26.1.2 注意事项
- 不再有 `placeBlock(...)`，统一为 `place(...)`。
- `breakBlock` 必须在 `TickEvent.Pre` 阶段调用。
- 放置时会**自动切槽再切回**（`swapBack` 参数控制），前端若有自定义背包同步状态需额外注意。

## BlockIterator

### 类名
`meteordevelopment.meteorclient.utils.world.BlockIterator`

### 包名
`meteordevelopment.meteorclient.utils.world`

### 源码路径
`utils/world/BlockIterator.java`

### 继承与接口
无继承，静态工具类；内部用 `Pool<Callback>` 复用回调对象。

### 关键字段
| 字段名 | 类型 | 中文用途 |
| --- | --- | --- |
| `hRadius` / `vRadius` | `private static int` | 所有已注册回调合并后的最大水平/垂直半径 |

### 关键方法
```java
public static void register(int horizontalRadius, int verticalRadius, BiConsumer<BlockPos, BlockState> function)
public static void disableCurrent()
public static void after(Runnable callback)
```
- `register`：注册一个「每 tick 对半径内所有方块执行一次」的回调。回调里满足条件后调用 `disableCurrent()` 可停止本次继续遍历该回调。
- 内部通过 `@EventHandler` 订阅 `TickEvent.Pre`，在玩家周边遍历 `(x,z) ∈ [px-hRadius, px+hRadius]`，`y ∈ [py-vRadius, py+vRadius]`。
- 使用场景：addon 做「区块扫描 / 找特定方块」，例如 `BlockIterator.register(4, 2, (pos, state) -> { if (state.is(Tags.Blocks.ORES)) {...; BlockIterator.disableCurrent();} })`。

### 相关类
- `meteordevelopment.meteorclient.utils.misc.Pool`
- `meteordevelopment.meteorclient.utils.world.BlockEntityIterator`、`ChunkIterator`（同目录，用于遍历方块实体 / 区块）

## CardinalDirection

### 类名
`meteordevelopment.meteorclient.utils.world.CardinalDirection`

### 包名
`meteordevelopment.meteorclient.utils.world`

### 源码路径
`utils/world/CardinalDirection.java`

### 继承与接口
`public enum CardinalDirection`：`North, East, South, West`

### 关键方法
```java
public Direction toDirection()
public static CardinalDirection fromDirection(Direction direction)
```
- `toDirection`：转成原版 `net.minecraft.core.Direction`。
- `fromDirection`：反查。**注意**：源码中 `WEST -> East`、`EAST -> West`（东西方向在 `fromDirection` 中是反的，见源码 switch；使用前务必对照，属原文行为）。

## Dir

### 类名
`meteordevelopment.meteorclient.utils.world.Dir`

### 包名
`meteordevelopment.meteorclient.utils.world`

### 源码路径
`utils/world/Dir.java`

### 继承与接口
无继承，纯静态位标志工具类，构造器私有。

### 关键字段（位标志）
```java
public static final byte UP = 1 << 1;
public static final byte DOWN = 1 << 2;
public static final byte NORTH = 1 << 3;
public static final byte SOUTH = 1 << 4;
public static final byte WEST = 1 << 5;
public static final byte EAST = 1 << 6;
```

### 关键方法
```java
public static byte get(Direction dir)
public static boolean is(int dir, byte idk)
public static boolean isNot(int dir, byte idk)
```
- 用途：位组合表示「要排除的方向」。`Renderer3D.boxLines(...)` / `boxSides(...)` 的 `excludeDir` 参数就是用 `Dir.*` 按位或组合。
- 使用场景：绘制方框时 `excludeDir = Dir.UP | Dir.DOWN`（不画顶底），或传 `0` 画全部。

## 常见坑
1. `breakBlock` 放到 `TickEvent.Post` 或任意 tick 外调用不会正确生效（依赖 `breaking`/`breakingThisTick` 的 tick 复位逻辑）。
2. 放置方块走的是「选相邻面 + 右键」逻辑，不是直接设置方块状态；无法放置时先 `BlockUtils.canPlaceBlock(...)` 判断。
3. `place` 会切到对应热键栏槽位（最多 8），`slot` 越界返回 `false`。
4. `CardinalDirection.fromDirection` 的东/西映射与直觉相反，慎用。
5. `BlockIterator` 的回调只在主线程 tick 内执行，且一个 tick 内必须同步完成，避免在里面做耗时操作。
