### 关键方法（真实签名照抄）

```java
public static boolean isAttackable(EntityType<?> type)
public static boolean isRideable(EntityType<?> type)
public static float getTotalHealth(LivingEntity target)
public static int getPing(Player player)
public static GameType getGameMode(Player player)
public static boolean isAboveWater(Entity entity)
public static boolean isInCobweb(Entity entity)
public static boolean isInRenderDistance(Entity entity)
public static boolean isInRenderDistance(BlockEntity entity)
public static boolean isInRenderDistance(BlockPos pos)
public static boolean isInRenderDistance(double posX, double posZ)
public static BlockPos getCityBlock(Player player)
public static String getName(Entity entity)
public static Color getColorFromDistance(Entity entity)
public static Color getColorFromHealth(Entity entity, Color nonLivingEntityColor)
public static boolean intersectsWithEntity(AABB box, Predicate<Entity> predicate)
public static EntityType<?> getGroup(Entity entity)
public static boolean isOnAir(Entity entity)
```

方法用途（addon 使用场景）：
- `isAttackable(type)`：黑名单式排除不可攻击实体（区域效果云、箭、掉落物、经验球、雷击、钓鱼钩等），返回 `true` 表示「可以攻击」。做攻击类 aura 时先过滤。
- `isRideable(type)`：判断实体是否可骑乘（猪、马、船、矿车等）。
- `getTotalHealth(target)`：`健康值 + 伤害吸收值`，用于血量条显示/斩杀线判断。
- `getPing(player)`：从 `PlayerInfo` 读延迟（ms）；未连接返回 0。
- `getGameMode(player)`：返回原版 `GameType`（生存/创造等）。
- `isAboveWater(entity)`：从实体位置向下逐格找水。
- `isInCobweb(entity)`：实体包围盒里是否有蜘蛛网。
- `isInRenderDistance(...)`：与主摄像机距离是否在渲染距离内。
- `getCityBlock(player)`：寻找目标玩家周围可「city」的方块（黑曜石/下界合金块等）坐标。
- `getName(entity)`：玩家取名字，非玩家取实体显示名。
- `getColorFromDistance` / `getColorFromHealth`：按距离 / 血量生成渐变 `Color`（用于 ESP 着色）。
- `intersectsWithEntity(box, predicate)`：高效判断包围盒是否与满足条件的实体相交（走 `LevelEntityGetter`，快速路径用 section 缓存）。
- `getGroup(entity)`：返回 `entity.getType()`（等价）。
- `isOnAir(entity)`：判断实体是否悬空（复刻 `ServerPlayNetworkHandler#isEntityOnAir`）。

### 相关类
- `meteordevelopment.meteorclient.utils.render.color.Color`（返回值类型）
- `meteordevelopment.meteorclient.utils.player.PlayerUtils`

### 26.1.2 注意事项
- 源码中 `EntityUtils` **没有**「实体禁列表 / 防裸奔注解」处理逻辑（不存在 `@Entity` 注解或类似黑名单）——见文末「不存在的项」。相关黑名单逻辑体现在 `isAttackable` 的硬编码类型排除上。
- `isRideable` 已在 26.1.2 更新到较新的实体列表（含 `CAMEL`、`NAUTILUS`、`HAPPY_GHAST` 等），照抄即可。

## TargetUtils

### 类名
`meteordevelopment.meteorclient.utils.entity.TargetUtils`

### 包名
`meteordevelopment.meteorclient.utils.entity`

### 源码路径
`utils/entity/TargetUtils.java`

### 继承与接口
无继承，纯静态工具类。

### 关键方法
```java
@Nullable public static Entity get(Predicate<Entity> isGood, SortPriority sortPriority)
public static void getList(List<Entity> targetList, Predicate<Entity> isGood, SortPriority sortPriority, int maxCount)
@Nullable public static Player getPlayerTarget(double range, SortPriority priority)
public static boolean isBadTarget(Player target, double range)
```
- `get`：把「渲染中的实体 + 假玩家」中满足 `isGood` 的实体按 `sortPriority` 排序，取第一个。
- `getList`：写出到传入列表，最多 `maxCount` 个。
- `getPlayerTarget(range, priority)`：自带「排除自己、排除死亡、距离范围内、好友保护（`Friends.get().shouldAttack`）、排除 `noHit` 假玩家、仅生存模式」的完整过滤，是攻击类 addon 最常用的入口。
- `isBadTarget`：目标为 null / 超出距离 / 死亡 / 血量 ≤0 时为「坏目标」。

## 常见坑
1. `TargetUtils.getPlayerTarget` 会**过滤非生存模式**玩家，也**过滤好友**（受 `Friends` 控制），做「打所有玩家」的 addon 时不要直接用默认过滤，需自己写 `Predicate` 配合 `TargetUtils.get`。
2. `FakePlayerEntity` 的 `noHit` 同时影响交互与目标选择，做「假人攻击测试」时记得 `noHit = false`。
3. `getPing` / `getGameMode` 依赖网络 `PlayerInfo`，尚未加载玩家信息时返回 0 / null，需判空。
4. `SortPriority` 是枚举 `Comparator`，直接传给 `TargetUtils.getList` 即可（不必自己写比较器）。
5. 假玩家由 `FakePlayerManager` 集中管理，切换世界/退出时需自行 `clear()`，否则残留实体。
