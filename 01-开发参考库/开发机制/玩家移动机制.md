# 玩家移动机制

> 源码依据：Minecraft原始源码/net/minecraft/client/player/ 与 net/minecraft/world/entity/ 26.1.2 Mojang官方映射

本文讲清「本地玩家（`LocalPlayer`）的移动数据从键盘到世界坐标、再到发包」的完整运行链路。核心结论一句话：**输入走 `ClientInput` → `applyInput()` 写入 `xxa/zza/jumping` → `travel()` 把相对轴转速成世界速度 → `move()` 落地并碰撞 → `tick()→sendPosition()` 按变化发送 `ServerboundMovePlayerPacket`**。addon 做「加速 / 飞行 / 反拉回」应在 `applyInput`、`travel`、`sendPosition` 三层找介入点，而不是只改 `abilities.flying`。

---

## 一、输入采集层（事件 → 内存状态）

### 键盘事件入口
- `KeyboardHandler`（`net/minecraft/client/KeyboardHandler`）把 GLFW 键盘事件聚合成一个 `ClientInput` 实例 `KeyboardInput`。
- `KeyboardInput extends ClientInput`（`net/minecraft/client/player/KeyboardInput`，`ClientInput` 在 `net/minecraft/client/player/ClientInput`）。
- 每 tick 结束时 `KeyboardHandler` 把聚合结果写进 `LocalPlayer.input`（见 `handleLogin`：`this.minecraft.player.input = new KeyboardInput(this.minecraft.options);`）。

### 数据结构
```java
// net.minecraft.client.player.ClientInput
public Input keyPresses = Input.EMPTY;   // 按键位集
protected Vec2 moveVector = Vec2.ZERO;   // 归一化后的 XZ 移动向量

// net.minecraft.world.entity.player.Input（record）
public record Input(boolean forward, boolean backward, boolean left, boolean right,
                    boolean jump, boolean shift, boolean sprint) {
    public static final Input EMPTY;
    public static final StreamCodec<FriendlyByteBuf, Input> STREAM_CODEC;
}
```
- `ClientInput.getMoveVector()`：把 `forward/backward/left/right` 合成一个 `Vec2`（`x`=左右，`y`=前后），归一化到长度 1。
- 关键点：**玩家移动语义只依赖 `keyPresses` 和 `moveVector` 这两份数据**，改这两处才会真正改变移动意图。

## 二、输入应用层（`LocalPlayer.applyInput` → `LivingEntity` 字段）

调用链：每 tick `LivingEntity.aiStep()`（见下）之前会先 `applyInput()`。

```java
// LocalPlayer.applyInput()  源码 688 行
public void applyInput() {
    if (this.isControlledCamera()) {
        Vec2 modifiedInput = this.modifyInput(this.input.getMoveVector());
        this.xxa = modifiedInput.x;    // 横向轴（左右）
        this.zza = modifiedInput.y;    // 纵向轴（前后）
        this.jumping = this.input.keyPresses.jump();
        // ... 手臂摆动 yBob/xBob 计算
    } else {
        super.applyInput();            // LivingEntity.applyInput() → 骑乘等其它场景
    }
}
```

`isControlledCamera()` 返回 `this.minecraft.getCameraEntity() == this`，即「第三人称旁观/控制他人」时走 else 分支不写 `xxa/zza`。

字段归属：`xxa/zza/jumping` 是 `LivingEntity` 的 `protected` 字段（`public float xxa; public float zza; protected boolean jumping;`），`applyInput` 每 tick 从 `input` 覆盖它们。所以 **addon 直接改 `xxa` 没有持久意义，下一 tick 被 `applyInput` 覆盖**（除非覆写 `applyInput` 或改 `input`）。

### `modifyInput`（摩擦 + 使用物品减速 + 潜行减速 + 斜向修正）
```java
private Vec2 modifyInput(final Vec2 input) {   // 源码 702 行
    if (input.lengthSquared() == 0.0F) return input;
    Vec2 newInput = input.scale(0.98F);                 // 基础 0.98 摩擦
    if (this.isUsingItem() && !this.isPassenger()) {
        newInput = newInput.scale(this.itemUseSpeedMultiplier());  // 使用物品减速
    }
    if (this.isMovingSlowly()) {
        float f = (float)this.getAttributeValue(Attributes.SNEAKING_SPEED); // 潜行减速
        newInput = newInput.scale(f);
    }
    return modifyInputSpeedForSquareMovement(newInput);  // 斜向 45° 归一化修正
}
```

## 三、每 tick 逻辑入口（`LocalPlayer.aiStep`）

`aiStep()`（源码 762 行）是「本地玩家逻辑推进」的核心入口，被 `LivingEntity.tick()` 调用。做的事：

1. 处理冲刺触发窗口 `sprintTriggerTime`。
2. 传入门过渡效果/传送冷却（`handlePortalTransitionEffect` / `processPortalCooldown`）。
3. 计算潜行 `crouching`（不能飞、非游泳、非骑乘、能蹲入碰撞箱等条件）。
4. `this.input.tick()`（推进 `ClientInput` 内部状态）。
5. 自动跳跃 `autoJump` 处理（`makeJump()`）。
6. 冲刺开关判定：`canStartSprinting()` → `setSprinting(true)`。
7. 后续（源码 813 行后）处理飞行开关开关（空格升降）、骑乘跳跃等，最终把 `xxa/zza/jumping` 组合成 `Vec3 input` 交给 `travel(input)`。

## 四、移动执行层（`LivingEntity.travel` → `moveRelative` → `move`）

```java
// LivingEntity.travel()  源码 2377 行
public void travel(final Vec3 input) {
    // 分三路：飞行 travelFlying（源码 2395/2399）、水中 travelInWater（2395 行附近）、空气/地面 travelInAir（2399 行附近）
}

// Entity.moveRelative() —— 把「相对轴速度」按 yaw 旋转成世界位移
public void moveRelative(float speed, Vec3 input);

// Entity.move() —— 真实移动入口，带 AABB 碰撞、方块夹出（MoverType 决定特殊碰撞）
public void move(MoverType moverType, Vec3 delta);
```

`travel` 关键逻辑（`LivingEntity`）：
- **飞行**：走 `travelFlying(Vec3 input, float speed)`，Y 方向由 `jumping`/潜行控制，水平摩擦系数 0.91（空气阻率）。
- **水中/空气**：走 `travelInAir`，地面摩擦 0.98 / 空中 0.91，受 `getEffectiveGravity()` 重力累积。
- 地面加速用 `getSpeed()`（受 `Attributes.MOVEMENT_SPEED`、`speed` 字段影响，默认 0.1）。
- 冲刺判定 `isSprinting()` 会乘冲刺速度加成。

`LocalPlayer.move()` 重写（源码 978 行）在调用 `super.move()` 后再叠加 `updateAutoJump()` 的自定义水平移动，用于自动跳跃。

### 踩到的关键字段
| 字段 | 类型 | 语义 |
|------|------|------|
| `deltaMovement` | `private Vec3`（Entity） | 每 tick 位移，含重力累积；`move` 后重置 |
| `onGround` | `private boolean` | 是否着地（碰撞结算后写） |
| `horizontalCollision` / `verticalCollision` | `public boolean` | 水平/垂直碰撞标记 |
| `position` | `private Vec3` | 精确坐标 |

## 五、发包层（`LocalPlayer.tick` → `sendPosition`）

移动逻辑结算完后，`LocalPlayer.tick()`（源码 229 行）负责把结果发给服务器：

```java
public void tick() {
    if (this.connection.hasClientLoaded()) {
        super.tick();
        if (!this.lastSentInput.equals(this.input.keyPresses)) {
            this.connection.send(new ServerboundPlayerInputPacket(this.input.keyPresses)); // 载具输入
            this.lastSentInput = this.input.keyPresses;
        }
        if (this.isPassenger()) {
            this.connection.send(new ServerboundMovePlayerPacket.Rot(...));  // 骑乘只发朝向
            // 载具本地权威时另发 ServerboundMoveVehiclePacket
        } else {
            this.sendPosition();   // 关键
        }
        // ... 环境音 handler tick
    }
}
```

### `sendPosition()`（源码 265 行）——按变化类型发 4 种移动包
```java
private void sendPosition() {
    this.sendIsSprintingIfNeeded();           // 冲刺变化 → ServerboundPlayerCommandPacket(START/STOP_SPRINTING)
    if (this.isControlledCamera()) {
        // 计算 deltaX/Y/Z、deltaYRot/deltaXRot，positionReminder++ 
        boolean move = 位移平方 > (2.0E-4)^2 || positionReminder >= 20;  // 20 tick 强制补发一次
        boolean rot = deltaYRot != 0.0 || deltaXRot != 0.0;
        if (move && rot) send(new ServerboundMovePlayerPacket.PosRot(position(), yRot, xRot, onGround, horizontalCollision));
        else if (move)   send(new ServerboundMovePlayerPacket.Pos(position(), onGround, horizontalCollision));
        else if (rot)    send(new ServerboundMovePlayerPacket.Rot(yRot, xRot, onGround, horizontalCollision));
        else if (onGround 或 collision 变化) send(new ServerboundMovePlayerPacket.StatusOnly(onGround, horizontalCollision));
        // 更新 xLast/yLast/zLast/yRotLast/xRotLast/lastOnGround/lastHorizontalCollision
    }
}
```

`ServerboundMovePlayerPacket` 四个内部类（源码 `net/minecraft/network/protocol/game/ServerboundMovePlayerPacket.java`）：
- `Pos`：只位置（`hasPos=true, hasRot=false`）。
- `PosRot`：位置 + 朝向。
- `Rot`：只朝向（`hasPos=false, hasRot=true`）。
- `StatusOnly`：只 `onGround + horizontalCollision`（无位置无朝向）。
- 各自 `type()` 指向 `GamePacketTypes.SERVERBOUND_MOVE_PLAYER_POS / _POS_ROT / _ROT / _STATUS_ONLY`。

**结论**：玩家移动不会每 tick 无条件全量发包，而是「变化检测 + 20 tick 兜底」，这是 addon 判断「服务端何时拉回我」的关键时间窗口。

## addon 介入点（按侵入性从低到高）

1. **读状态**：`mc.player.getDeltaMovement()`、`mc.player.position()`、`mc.player.onGround()`、`mc.player.getAbilities().flying`。
2. **读输入意图**：`mc.player.input.getMoveVector()`、`mc.player.input.keyPresses.forward()` 等。
3. **改能力**：`mc.player.getAbilities().flying = true; mc.player.onUpdateAbilities();`（发包 `ServerboundPlayerAbilitiesPacket`）。
4. **改速度（本地预测）**：`mc.player.setDeltaMovement(...)` / `addDeltaMovement(...)`（仅当帧生效，下一 tick 受重力/摩擦重算）。
5. **Mixin 拦截**（Meteor 常用）：
   - `LocalPlayer.applyInput()`：覆写 `xxa/zza/jumping` 的写入（等效改输入）。
   - `LivingEntity.travel(Vec3)`：拦截移动总入口，直接改 `moveRelative` 的 `speed`。
   - `LocalPlayer.sendPosition()`：拦截/伪造移动包内容、或节流发包频率。
6. **主动发包**：`mc.getConnection().send(new ServerboundMovePlayerPacket.PosRot(...))`（注意与本地预测一致性）。

## 常见坑

1. **改 `abilities.flying` 不等于会飞**：飞行 = 「能力 `flying/mayfly`」+「`travel` 走 `travelFlying` 分支」共同决定；只置位不走进飞行分支，客户端不会真正飞行，还会与服务端脱节被踢。
2. **`xxa/zza` 是相对轴不是世界轴**：`xxa` 左右、`zza` 前后（相对 yaw）；直接塞世界坐标会走歪。
3. **改 `xxa` 无效**：下一 tick `applyInput()` 会从 `input` 覆盖；要驱动移动改 `input.keyPresses`/`getMoveVector()` 或覆写 `applyInput()`。
4. **`setPos` ≠ 传送**：只改本地不发包，服务端下个位置包会拉回；要让旁人可见走 `move()`/`teleportTo()`/`sendPosition`。
5. **`getDeltaMovement()` 每 tick 变**：`move` 后、`setDeltaMovement` 前含重力，别长期持有同一 Vec3。
6. **骑乘分支不同**：骑乘时 `sendPosition()` 不发 `Pos`，只发 `Rot` + `ServerboundMoveVehiclePacket`，对骑乘做移动 hack 要另走载具包路径。
7. **渲染插值是另一套**：渲染平滑用 `getKnownMovement()`（上一帧→当前帧插值），物理结算用 `getDeltaMovement()`，二者混淆会画面瞬移但碰撞仍在原地。
