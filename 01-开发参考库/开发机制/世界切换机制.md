# 世界切换机制

> 源码依据：Minecraft原始源码/net/minecraft/client/multiplayer/ClientPacketListener.java 与 net/minecraft/client/Minecraft.java 及 net/minecraft/client/multiplayer/ClientLevel.java 26.1.2 Mojang官方映射

本文讲「客户端 `ClientLevel` 何时创建、何时销毁，进世界/跨维度/退出世界三条路径分别发生什么」。核心结论：**进世界在 `handleLogin` 首次 `new ClientLevel`；同世界重生只刷新出生状态不换 level；跨维度在 `handleRespawn` 里重建 `ClientLevel`（`dimensionChanged` 为真）；退出世界在 `Minecraft.disconnect` 里关连接、清 `level/player`**。addon 缓存 `mc.level` 必须随切换失效，任何模块跨维度/重登都要重新判空与重新取引用。

---

## 一、进世界（`handleLogin`，首次创建 `ClientLevel`）

`ClientPacketListener.handleLogin(ClientboundLoginPacket)`（源码 499 行）：

```java
this.minecraft.gameMode = new MultiPlayerGameMode(this.minecraft, this);
CommonPlayerSpawnInfo spawnInfo = packet.commonPlayerSpawnInfo();
// 洗牌存 levels（可探索维度清单）
ResourceKey<Level> dimension = spawnInfo.dimension();
Holder<DimensionType> dimensionType = spawnInfo.dimensionType();
this.serverChunkRadius = packet.chunkRadius();
this.serverSimulationDistance = packet.simulationDistance();
this.levelData = new ClientLevel.ClientLevelData(Difficulty.NORMAL, packet.hardcore(), isFlat);
this.level = new ClientLevel(this, levelData, dimension, dimensionType,
    this.serverChunkRadius, this.serverSimulationDistance, this.minecraft.levelRenderer,
    isDebug, spawnInfo.seed(), seaLevel);
this.minecraft.setLevel(this.level);                       // mc.level 就指向它
if (this.minecraft.player == null) {
    this.minecraft.player = this.minecraft.gameMode.createPlayer(...); // 首次建 LocalPlayer
}
this.minecraft.player.resetPos();
this.level.addEntity(this.minecraft.player);
this.minecraft.player.input = new KeyboardInput(this.minecraft.options);
this.minecraft.setCameraEntity(this.minecraft.player);
this.startWaitingForNewLevel(this.minecraft.player, this.level, LevelLoadingScreen.Reason.OTHER);
```

要点：
- `setLevel`（`Minecraft` 源码 2155 行）赋值 `this.level = level` 并 `updateLevelInEngines(level)`（渲染引擎/声音引擎绑定新 level）。
- `startWaitingForNewLevel` 进入加载屏（`LevelLoadingScreen`），期间 `setClientLoaded(false)`；区块加载完成后回调 `setClientLoaded(true)`。
- `ClientboundLoginPacket` 还携带 `levels`（可切换维度集合）与 `CommonPlayerSpawnInfo`（维度/类型/种子/海平面/出生/游戏模式/死亡位置等）。

## 二、同维重生 / 重登（`handleRespawn`，`dimensionChanged == false`）

`ClientPacketListener.handleRespawn(ClientboundRespawnPacket)`（源码 1254 行）：

```java
ResourceKey<Level> dimensionKey = spawnInfo.dimension();
ResourceKey<Level> oldDimensionKey = oldPlayer.level().dimension();
boolean dimensionChanged = dimensionKey != oldDimensionKey;
LevelLoadingScreen.Reason reason = this.determineLevelLoadingReason(oldPlayer.isDeadOrDying(), dimensionKey, oldDimensionKey);
if (dimensionChanged) {
    // 重建 ClientLevel（见下）
} 
// 无论是否换维度，都会更新 spawnInfo 关联状态、重新 addEntity、startWaitingForNewLevel
```

- 死亡重生（同维度）走这里：刷新出生点、清背包预测、重新进入加载流程，但 `ClientLevel` 实例不变。
- addon 注意：重生不清 `mc.level` 引用，但死亡瞬间 `LocalPlayer` 状态（血量/位置）会被服务端推送重置。

## 三、跨维度（`handleRespawn`，`dimensionChanged == true`）

```java
if (dimensionChanged) {
    Map<MapId, MapItemSavedData> mapData = this.level.getAllMapData();  // 转移地图数据
    ClientLevel.ClientLevelData levelData = new ClientLevel.ClientLevelData(
        this.levelData.getDifficulty(), this.levelData.isHardcore(), spawnInfo.isFlat());
    this.levelData = levelData;
    this.level = new ClientLevel(this, levelData, dimensionKey, dimensionType,
        this.serverChunkRadius, this.serverSimulationDistance, this.minecraft.levelRenderer,
        isDebug, spawnInfo.seed(), seaLevel);
    this.minecraft.setLevel(this.level);
    // ... 复用 oldPlayer（mc.player 不变），重置姿态/位置，重新 addEntity、setCameraEntity、startWaitingForNewLevel
}
```

**关键结论（addon 铁律）**：
- 跨维度 **`ClientLevel` 换新**、`LocalPlayer` 复用——`mc.player` 引用仍有效，`mc.level` 引用失效。
- 长时间持有的 `ClientLevel` 引用要每 tick 校验 `mc.level == cached`，否则操作错世界（旧 world 对象已废弃）。
- 切换期间 `setClientLoaded(false)` + 加载屏，玩家 tick 被短路（`LocalPlayer.tick()` 首行 `hasClientLoaded()` 门槛）。

## 四、退出世界（`Minecraft.disconnect`）

入口：用户断开 / 被踢（`onDisconnect`）/ 崩溃恢复 → `Minecraft.disconnect(Screen, boolean, boolean)`（源码 2199 行）：

```java
ClientPacketListener connection = this.getConnection();
if (connection != null) {
    this.dropAllTasks();
    connection.close();                               // 关底层 Connection
    if (!keepResourcePacks) this.clearDownloadedResourcePacks();
}
this.playerSocialManager.stopOnlineMode();
// ... 停指标、关单机 IntegratedServer、this.level = null、this.player = null
```

- 之后 `ClientLevel.disconnect(Component)`（源码 442 行）→ 底层 `connection.getConnection().disconnect(message)`，世界资源随 `ClientLevel` 释放。
- `mc.getConnection()` 因 `player == null` 返回 null（此时判断「是否在世界」就用它）。
- 单机（`isLocalServer()`）走 `disconnectWithSavingScreen()`（保存进度），多人走 `disconnectWithProgressScreen()`。
- 资源包：`keepResourcePacks` 控制是否 `clearDownloadedResourcePacks()`（服务器资源包切换会触发 reload）。

## 五、世界切换对 addon 的影响汇总

| 场景 | `ClientLevel` | `LocalPlayer` | `mc.getConnection()` |
|------|---------------|---------------|----------------------|
| 首次进世界 | 新建 | 新建 | 非 null |
| 同维重生 | 不变 | 复用 | 非 null |
| 跨维度 | **重建** | 复用 | 非 null |
| 重登回标题→再进 | 销毁再新建 | 新建 | 先 null 后非 null |
| 退出到标题 | 销毁 | null | null |

---

## addon 介入点

1. **判空铁律**：所有入口先 `mc.level != null && mc.player != null`，再 `mc.getConnection() != null`。
2. **监听进世界/切维度**：Mixin `handleLogin`/`handleRespawn` 的 TAIL，或订阅 `ClientboundLoginPacket`/`ClientboundRespawnPacket` 接收事件（Meteor `WorldEvent`/`GameJoinedEvent`）。
3. **监听退出世界**：Mixin `Minecraft.disconnect` HEAD（Meteor `GameLeftEvent`，见 `MinecraftMixin.onDisconnect` ＝ 165 行）。
4. **模块状态重置**：跨维度/重登时刷新对 `mc.level` 缓存、清空「世界内对象缓存」（开始/结束位置、容器引用、路径规划缓存）。
5. **单机 vs 多人分支**：`mc.isLocalServer()` / `mc.hasSingleplayerServer()` 区分保存语义与断开屏。

---

## 常见坑

1. **缓存 `mc.level` 跨维度失效**：维度切换重建 `ClientLevel`，旧引用对象被废弃但不会被 GC 立即回收；操作旧引用会「打在已销毁世界」上，务必校验 `mc.level == cached`。
2. **切维度 `mc.player` 引用不变但 `player.level()` 变了**：别把「玩家对象」和「玩家所在世界」绑死，跨维度后重新取 `player.level()`。
3. **进世界早期 `hasClientLoaded()` 门槛**：加载屏期间玩家 tick 短路，移动/交互不生效；等加载完成再加状态机。
4. **退出世界后 `getConnection()` 为 null**：先判 `player != null` 再拿连接，再判 `.getConnection().isConnected()`。
5. **资源包 reload 触发二次加载**：跨服务器/资源包切换会走 `reloadResourcePacks`，绑定在 `ClientPacketListener` 的资源引用会短暂失效，勿在 reload 中发包。
6. **单机保存屏**：单机退出走 `SavingLevel` 屏，期间世界仍在 `disconnect` 中，addon 的 `GameLeftEvent` 之后不要再操作世界。
