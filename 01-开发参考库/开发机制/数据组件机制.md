# 数据组件机制

> 源码依据：Minecraft原始源码/net/minecraft/core/component/ 与 net/minecraft/world/item/ 与 net/minecraft/core/registries/ 26.1.2 Mojang官方映射

本文讲「数据组件（Data Component）如何注册、如何存默认值、如何回退、如何序列化、如何修改」。核心结论：**26.1.2 物品不再有 NBT，全部属性拆成「注册的 `DataComponentType<T>` + 每个 ItemStack 携带的 `DataComponentMap` 覆盖」；默认值来自 `Item` 的 prototype 组件（`getPrototype()`），读用 `getOrDefault(type, default)` 回退；每个组件同时声明 `persistent(Codec)`（落盘）与 `networkSynchronized(StreamCodec)`（发包）两套编解码**。addon 读写物品属性就是「拿 `DataComponents.XXX` + `stack.get/set/update/remove`」。

---

## 一、注册系统（`DataComponents` → `BuiltInRegistries.DATA_COMPONENT_TYPE`）

```java
// DataComponents.java  源码 430 行
private static <T> DataComponentType<T> register(String id, UnaryOperator<DataComponentType.Builder<T>> builder) {
    return Registry.register(BuiltInRegistries.DATA_COMPONENT_TYPE, id, builder.apply(DataComponentType.builder()).build());
}

// 用法（源码 108-117 行）
public static final DataComponentType<CustomData> CUSTOM_DATA = register("custom_data", b -> b.persistent(CustomData.CODEC));
public static final DataComponentType<Integer> MAX_STACK_SIZE = register(
    "max_stack_size", b -> b.persistent(ExtraCodecs.intRange(1, 99)).networkSynchronized(ByteBufCodecs.VAR_INT));
public static final DataComponentType<Integer> DAMAGE = register(
    "damage", b -> b.persistent(ExtraCodecs.NON_NEGATIVE_INT).ignoreSwapAnimation().networkSynchronized(ByteBufCodecs.VAR_INT));
```

- 所有组件 type 常量都在 `net/minecraft/core/component/DataComponents`，注册进 `BuiltInRegistries.DATA_COMPONENT_TYPE`（`Registry<DataComponentType<?>>`）。
- `DataComponents` 只是「常量集合」，注册表本体在 `BuiltInRegistries.DATA_COMPONENT_TYPE`；也可经 `Registries.DATA_COMPONENT_TYPE` key + registryAccess lookup。

## 二、`DataComponentType<T>` 与 Builder

```java
// DataComponentType.java —— 接口，T 为组件值类型
static <T> DataComponentType.Builder<T> builder();
@Nullable Codec<T> codec();                      // 持久化编解码（null = transient）
default Codec<T> codecOrThrow();                  // 无 codec 抛 IllegalStateException
default boolean isTransient();                    // codec()==null，不落盘
boolean ignoreSwapAnimation();                    // 交换是否播动画
StreamCodec<? super RegistryFriendlyByteBuf, T> streamCodec(); // 网络同步编解码
```

Builder 链式（源码 58/63/68/81 行）：
```java
.persistent(Codec<T>)                // 可落盘（存档/命令给物品）
.networkSynchronized(StreamCodec<T>) // 可发包（跨服/同步）
.cacheEncoding()                     // 编码缓存（高频编码性能）
.ignoreSwapAnimation()               // 交换不播动画（如 DAMAGE）
```

关键区分：
- **persistent（Codec）** 管「存盘、命令、配方、data 包」路径。
- **networkSynchronized（StreamCodec）** 管「网络传输」。
- 只写一个会导致另一边丢数据：`isTransient()`（无 `codec()`）的组件只在网络/内存存在，不落盘。

## 三、`DataComponentMap`（组件快照，不可变）

```java
// net/minecraft/core/component/DataComponentMap（接口）
DataComponentMap EMPTY;
static DataComponentMap composite(DataComponentMap prototype, DataComponentMap overrides); // prototype + 覆盖合并
static DataComponentMap.Builder builder();
Set<DataComponentType<?>> keySet();
default boolean has(DataComponentType<?> type);
default int size(); default boolean isEmpty();
// Builder
public <T> Builder set(DataComponentType<T> type, @Nullable T value);
public Builder addAll(DataComponentMap map);
public Builder addValidator(Consumer<DataComponentMap> validator);
public DataComponentMap build();
```

- `ItemStack.getComponents()` 返回**快照**（不可变），改它不影响物品。
- `composite(prototype, overrides)` 是「默认值 + 覆盖」的合并核心：先查 overrides（物品实例覆盖），缺则查 prototype（物品类型默认）。

## 四、`ItemStack` 上的读写与回退

### 三层取值模型
1. **覆盖层**：`ItemStack.getComponents()`（`this.components`，源码 220 行）。
2. **默认层**：`ItemStack.getPrototype()`（源码 224 行）= `this.typeHolder().components()`，即 `Item` 的默认组件。
3. **回退读取**：`getOrDefault(type, defaultValue)`——先查覆盖层，缺则回退到 prototype 默认，再缺才用传入 default。

```java
// ItemStack 源码（组件读写，DataComponentHolder 接口）
@Nullable public <T> T get(DataComponentType<? extends T> type);                 // 缺省 null
public <T> T getOrDefault(DataComponentType<? extends T> type, T defaultValue);  // 缺省回退
public <T> T set(DataComponentType<T> type, @Nullable T value);                 // 写；value=null 删除；返回旧值
public <T> T remove(DataComponentType<? extends T> type);                        // 删；返回旧值
public <T> T update(DataComponentType<T> type, T defaultValue, UnaryOperator<T> fn); // 读-改-写
public DataComponentMap getComponents();
public DataComponentMap getPrototype();
public boolean hasNonDefault(DataComponentType<?> type);                         // 236 行，是否「非默认」显式覆盖
```

### 典型写法
```java
ItemEnchantments enc = stack.get(DataComponents.ENCHANTMENTS);                  // null 或 ItemEnchantments
int dmg = stack.getOrDefault(DataComponents.DAMAGE, 0);                         // 回退读
stack = stack.set(DataComponents.CUSTOM_NAME, Component.literal("神剑"));        // 写（重新赋值）
stack = stack.update(DataComponents.REPAIR_COST, 0, c -> c + 2);                // 原子累加
CustomData cd = stack.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY);// 自定义数据
```

## 五、序列化（两套 codec 分离）

- **落盘/命令/配方**：用 `Codec`（`DataComponents.VALUE_MAP_CODEC`，源码 `DataComponentType` 24 行，`Codec.dispatchedMap(PERSISTENT_CODEC, codecOrThrow)` 按组件 type 分发）。`PERSISTENT_CODEC`（源码 19-21 行）会**拒绝 transient 组件**（无 codec 就报错）。
- **网络**：用 `RegistryFriendlyByteBuf` + `StreamCodec`，仅含 `networkSynchronized` 的组件。
- `ItemStack` 的持久化整体走 `componentsPatch`（`DataComponentPatch`）：`getComponentsPatch()`（源码 228 行）返回相对 prototype 的差异patch，节省体积。

## addon 介入点

1. **读任意属性**：`stack.get(DataComponents.XXX)` 或 `getOrDefault(DataComponents.XXX, 默认)`。
2. **写/改属性**：`stack = stack.set/update/remove(...)`（值语义，重接返回值）。
3. **自定义数据**：用 `DataComponents.CUSTOM_DATA`（`CustomData`），等价旧 `getOrCreateNbt()`。
4. **注册自定义组件**（需与服务端/资源包配套）：`Registry.register(BuiltInRegistries.DATA_COMPONENT_TYPE, id, DataComponentType.builder().persistent(...).networkSynchronized(...).build())`；客户端单选几乎无法全局生效，需 Mixin/Service 在初始化期注册。
5. **监听物品变化**：读 `ItemStack.getComponents()` 快照比对，或拦截容器/背包同步包拿物品组件（见《容器同步机制》）。

## 常见坑

1. **`getComponents()` 是快照**：改它不影响物品；改物品必须 `stack = stack.set/update(...)` 重新赋值。
2. **`set(type, null)` 是删除**：value==null 等价 `remove`；区分「写 0/空串」与「删组件」。
3. **transient 组件不落盘**：`isTransient()`（无 `codec()`）只存网络/内存；自定义组件要带 `persistent` 才可持久化，`PERSISTENT_CODEC` 会拒绝 transient。
4. **persistent 与 networkSynchronized 是两套**：只写一个会导致另一路径丢数据，跨服/盘点要两个都配。
5. **`CUSTOM_DATA` 不是万能口袋**：它要求可 codec 的数据结构，旧 `NbtCompound`（已删除）不能当存储类型。
6. **`DataComponentMap` 不可变 + keySet 只读**：`keySet().remove(...)` 会失败；遍历用 `for (TypedDataComponent<?> e : components)` 或 `stream()`。
7. **回退链三层**：`get(type)` 只查覆盖层返回 null；要「默认值」用 `getOrDefault(type, default)`，它自动并 prototype 默认，别手动拼回退。
