# 版本规则 —— 全项目开发唯一版本基准

> 源码依据：本资料库 README.md「版本基准」+ `26.1.2\03-映射表\文档\来源与版本记录-26.1.2.md` + `26.1.2\src\main\java\com\example\addon\convention\YiyiaddonConvention.java` 第七章。

## 一、唯一版本（固定，禁止漂移）

| 项目 | 版本 | 说明 |
|------|------|------|
| Minecraft | **26.1.2** | 对外 CalVer 版本号（年.批次.修订） |

## 二、新版才允许使用的东西

- `build.gradle.kts` 中**没有** `mappings(loom.officialMojangMappings())` 是**正确**的——26.1 不混淆、不需要重映射步骤，禁止「好心」补上。
- 客户端与玩家类名直接用官方名（LocalPlayer/ClientLevel/Minecraft 等）。
- 26.1.2 里已大规模改名：`ResourceLocation`→`Identifier`、`PlayerInventory`→`Inventory`、`ScreenHandler`→`AbstractContainerMenu` 等（全表见 `生成的索引文件\易错对照表-26.1.2.txt`）。

## 三、绝对禁止

1. Yarn API / Yarn 名（MinecraftClient、ClientPlayerEntity、Text、NbtCompound…）
2. 旧 Minecraft 教程里的 API（1.20/1.21 时代的 Yarn 教程）
3. 旧版 Meteor API（凭记忆写 0.5.x/旧版 Meteor 的类）
4. 凭模型记忆猜 API——一切以本资料库原始源码为准
5. 无法确认版本的第三方代码样例

## 四、不确定时的标准流程（铁律）

第一步：查 `快速索引\` —— 类索引/方法索引看这个 API 是否存在、在哪。
第二步：查 `API参考\` —— 看该领域的真实签名、用途、注意点。
第三步：查 `开发机制\` —— 理解机制运行方式。
第四步：直接打开 `Minecraft原始源码\` / `Meteor原始源码\` 确认（Grep 简名/全名/方法）。

**原始源码优先级最高**。任何文档与源码冲突，以源码为准。

## 五、命令速查工具

```powershell
# 在 d:\mcaddon\26.1.2 下
node "01-开发参考库\工具\查JARAPI.js" <类名>              # 类全路径 + 全部字段方法签名
node "01-开发参考库\工具\查JARAPI.js" <类名> <方法关键字>  # 类内搜方法
node "01-开发参考库\工具\查JARAPI.js" --找 <方法名>        # 全量 9848 类全局搜方法（慢）
```

工具依赖：`生成的索引文件\类名索引-26.1.2.txt` + `.gradle\loom-cache` 下的 merged JAR（首次需先 `.\gradlew.bat classes`）。

- [ ] import 路径与源码真实包路径一致（简名对照表核对）
