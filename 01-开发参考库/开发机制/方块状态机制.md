# 方块状态机制

> 源码依据：Minecraft原始源码/net/minecraft/world/level/block/state/ 与 net/minecraft/client/multiplayer/ 26.1.2 Mojang官方映射

本文讲「`BlockState` 怎么组织、怎么存储、怎么同步到客户端」。核心结论：**`BlockState` 是对象池化的单例——`StateDefinition` 启动时把「方块类型 × 每个属性的全部取值」笛卡尔积预计算成一张 `neighbors` 状态表，`setValue` 只是查表返回已有单例；属性值存 `StateHolder.propertyValues` 数组；客户端同步靠 `ClientboundBlockUpdatePacket → ClientLevel.setServerVerifiedBlockState`**。addon 读状态用 `level.getBlockState(pos)`，改状态返回新 `BlockState`（不可变），放方块要走预测/发包。

---

## 一、类层次

```
BlockBehaviour.BlockStateBase (net/minecraft/world/level/block/state/BlockBehaviour.java，源码 423 行)
   └─ extends StateHolder<Block, BlockState>
        └─ BlockState (net/minecraft/world/level/block/state/BlockState.java，源码 8 行)
```

- `StateHolder<O, S>`（`StateHolder.java` 源码 15 行）是「属性值载体」基类，`O`=owner（Block），`S`=具体状态类型（BlockState）。
- `BlockState` 直接 `extends BlockStateBase`，不加字段——**状态本身只含：owner（方块类型）+ 属性值数组**。

## 二、属性值存储（`StateHolder` 内部结构）

```java
// StateHolder  源码 20-22 行
protected final O owner;
private final Property<?>[] propertyKeys;      // 属性键数组（与 StateDefinition 顺序一致）
private final Comparable<?>[] propertyValues;  // 属性值数组（下标一一对应）
private S[][] neighbors;                       // setValue 查表用的状态表（池化）
```

读写方法（源码真实签名）：
```java
public <T extends Comparable<T>> T getValue(Property<T> property);            // 86 行，缺属性抛 IllegalArgumentException
public <T extends Comparable<T>, V extends T> S setValue(Property<T> property, V value); // 103 行，查表返回新状态
public <T extends Comparable<T>> S trySetValue(Property<T> property, V value);          // 111 行，缺属性返回自身
public boolean hasProperty(Property<?> property);                              // 76 行
public Collection<Property<?>> getProperties();                               // 61 行
```

- `getValue` 按 `valueIndex(property)` 找到下标，再 `propertyValues[index]` 取 `Comparable`，`getValueClass().cast(...)` 转型返回。
- **`setValue` 不改自身**：`setValueInternal` 看 `property.getInternalIndex(value)` 得列号，返回 `neighbors[propertyIndex][valueIndex]`——从状态表直接取既有单例，本身不变。

## 三、状态表的池化构建（`StateDefinition`）

`StateDefinition`（`StateDefinition.java`）在方块注册期构建：

```java
// 单属性（源码 81 行 createSinglePropertyStates）：遍历 property.getPossibleValues()，建状态
// 多属性（源码 105 行 createMultiPropertyStates）：
List<List<Comparable<?>>> stateValues = Lists.cartesianProduct(allPropertyValues); // 属性取值笛卡尔积
Map<List<Comparable<?>>, S> statesByValues = new HashMap();
for (List<Comparable<?>> values : stateValues) {
    S blockState = factory.create(owner, propertyKeys, valuesCopy.toArray(EMPTY_VALUES)); // 建单例
    statesByValues.put(valuesCopy, blockState);
    states.add(blockState);
}
statesByValues.forEach((valuesx, state) -> state.initializeNeighbors(stateCollection.fillNeighborsForState(propertyKeys, valuesx)));
```

结论：
- **每种 (方块, 属性取值组合) 全局只有一个 `BlockState` 实例**（对象池）。
- `neighbors[属性下标][取值下标]` 预填邻居状态，`setValue` 是 O(1) 查表。
- 因此 `equals`（`StateHolder` 源码 53 行 `return super.equals(obj)`，即**身份比较**）在池化前提下**等价于值比较**。两个「相同值」的 BlockState 本质是同一实例，`==` 与 `equals` 结果一致。

## 四、客户端读写与方位

### 读
```java
BlockState state = mc.level.getBlockState(pos);
Block block = state.getBlock();               // 方块类型（注册单例）
boolean air = state.isAir();
// 属性：state.getValue(BlockStateProperties.FACING) 等 Property<?>
```
- 判断方块类型：`state.getBlock() == Blocks.STONE`（block 常量是注册单例，`==` 可靠）。
- 26.1.2 的 `BlockState` **没有** 简单的 `is(Block)` 重载（只有 `is(TagKey<Block>, Predicate)`），旧代码 `state.is(Blocks.STONE)` 会编译失败。

### 改（产生新状态，不可变）
```java
BlockState next = state.setValue(BlockStateProperties.FACING, Direction.EAST); // 返回新单例，state 不变
```
- `setValue` 返回新 `BlockState`，原状态不可变；`BlockPos` 同样不可变（`Vec3i` 语义）。

### 写回世界（区分本地与服务端）
```java
level.setBlock(pos, state, Block.UPDATE_ALL);       // 本地写（预测 / 不保证服务端认可）
level.setBlockAndUpdate(pos, state);                 // 本地写 + 邻居更新 + 渲染更新
// 客户端「合法放置」走 gameMode：mc.gameMode.startDestroyBlock / useItemOn（见世界与方块 API）
```

## 五、客户端同步链路（服务端 → 客户端）

### 单方块更新
`ClientPacketListener.handleBlockUpdate(ClientboundBlockUpdatePacket)`（源码 942 行）：
```java
PacketUtils.ensureRunningOnSameThread(packet, this, this.minecraft.packetProcessor());
this.level.setServerVerifiedBlockState(packet.getPos(), packet.getBlockState(), 19);
```

### 区块段批量更新
`handleChunkBlocksUpdate(ClientboundSectionBlocksUpdatePacket)`（源码 852 行）：
```java
packet.runUpdates((pos, state) -> this.level.setServerVerifiedBlockState(pos, state, 19));
```

### `ClientLevel.setServerVerifiedBlockState`（源码 187 行）
```java
public void setServerVerifiedBlockState(BlockPos pos, BlockState blockState, int updateFlag) {
    if (!this.blockStatePredictionHandler.updateKnownServerState(pos, blockState)) { // 与本地预测对账
        super.setBlock(pos, blockState, updateFlag, 512);                            // 未预测命中→真正落块
    }
}
```
- 方块状态预测（`BlockStatePredictionHandler`）：客户端挖/放是「先本地预测、再等服务器确认」，收到服务端权威状态后对账，避免闪回。
- `getBlockStatePredictionHandler().onTeleport()` 在位置纠正时清空预测（见《位置同步与纠正》）。

### 方块变化确认
`handleBlockChangedAck(ClientboundBlockChangedAckPacket)`（源码 2433 行）→ `level.handleBlockChangedAck(packet.sequence())`，配合客户端序列号确认。

## addon 介入点

1. **读状态**：`mc.level.getBlockState(pos)`、`state.getBlock()`、`state.getValue(Property)`。
2. **筛选建筑**：配合 `BlockPos.withinManhattan/betweenClosed` 遍历，`state.getCollisionShape(...)` 做碰撞判定。
3. **本地预测改块**：`level.setBlock(pos, nextState, flags)`（仅视觉/预测）；陷进服务端纠正时注意预测被 onTeleport 清空。
4. **拦截同步**：Mixin `ClientPacketListener.handleBlockUpdate` / `handleChunkBlocksUpdate`（改渲染状态）。
5. **监听破坏进度**：`MultiPlayerGameMode.startDestroyBlock/continueDestroyBlock`（`mc.gameMode`），读 `getDestroyProgress` 做矿透/破坏预测分析。

## 常见坑

1. **`BlockState` 不可变**：`setValue` 返回新实例，原状态不变；忘接返回值直接丢改动。
2. **`BlockState.is(Block)` 已不存在**：用 `state.getBlock() == Blocks.XXX`；`is(TagKey)` 是两参版本。
3. **`equals` 是身份比较、但可当值比较用**：因为对象池化，相同值==同一实例；跨「静态注册 vs 动态注册」的 BlockState 不要混比（26.1.2 方块还基本是静态单例）。
4. **改方块要同步**：`level.setBlock` 只改本地，服务端不认可时会被 `setServerVerifiedBlockState` 纠正；合法放/挖走 `gameMode`。
5. **`getValue` 缺属性会抛异常**：先 `hasProperty` 或 `getOptionalValue/getValueOrElse`，避免不同 Block 状态上的属性误取。
6. **属性下标与邻居表绑定**：`propertyKeys` 顺序由 `StateDefinition` 固定，`propertiesByName.values()` 顺序一致，addon 自建 `Property` 排序要小心（`Property.compareTo` 顺序是关键）。
