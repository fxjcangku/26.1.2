# 26.1.2 官方映射速查

给 AI 和开发者用的 API 事实来源。**写代码前查这里，不要凭记忆猜类名。**

## 为什么需要这个目录

Minecraft 26.1.2（内部版本号 `1.21.11`）之后，Mojang 做了两件大事：

1. **取消代码混淆**，官方名称直接编译进 JAR，Yarn 映射退役
2. **大规模改名**，最典型的是 `ResourceLocation` → `Identifier`

结果是：网上大量教程、AI 记忆里的类名在 26.1.2 已经不存在，照抄直接编译失败。这个目录把官方映射拆成可查的索引，任何 API 疑问都能当场验证。

## 目录结构

```
Mappings/
├─ 说明.md                    本文件
├─ 官方映射原文件/            client/server 映射（11MB + 8MB，不进 Git）
├─ 工具/
│  ├─ 下载官方映射.ps1        重建原文件（clone 后先跑这个）
│  ├─ 提取映射索引.js         生成类名索引与简名对照
│  ├─ 生成分类速查表.js       按功能域拆成 15 个文件
│  ├─ 验证易错API.js          核对 Yarn/旧名是否还存在
│  └─ 查API.js                ★ 日常最常用：查类、查方法、全局搜
├─ 分类速查/                  15 个按功能域分类的类名清单，带中文用途注释
├─ 类名索引-26.1.2.txt        全部 9848 个类
├─ 简名对照-26.1.2.txt        简名 → 完整包路径（写 import 时查）
└─ 易错对照表-26.1.2.txt      ★ 39 个高频 API 的新旧对照
```

## 日常怎么用

### 查一个类怎么 import

```powershell
node Mappings\工具\查API.js Identifier
```

输出完整包路径、全部字段和方法签名。

### 不确定方法在哪个类

```powershell
node Mappings\工具\查API.js --找 sendCommand
```

### 在某个类里搜方法

```powershell
node Mappings\工具\查API.js LocalPlayer sendSystem
```

### 类名报错查不到

说明它在 26.1.2 不存在。先看 `易错对照表-26.1.2.txt`，八成是改名了。

## clone 之后的初始化

原文件受 Mojang EULA 限制不能进 Git，需要本地重建：

```powershell
powershell -ExecutionPolicy Bypass -File Mappings\工具\下载官方映射.ps1
node Mappings\工具\提取映射索引.js
node Mappings\工具\生成分类速查表.js
node Mappings\工具\验证易错API.js
```

## 26.1.2 关键事实

| 项目 | 值 |
|------|-----|
| 对外版本号 | 26.1.2（CalVer：`年.批次.修订`） |
| 内部版本号 | 1.21.11 |
| 映射类型 | Mojang 官方映射（**不是 Yarn**） |
| 是否混淆 | 否，26.1 起官方发布不混淆版本 |
| Fabric Loader | 0.19.3 |
| Meteor Client | 26.1.2-SNAPSHOT |
| JDK | 25 |
| 类总数 | 9848（net.minecraft 下） |

`build.gradle.kts` 里**没有** `mappings(loom.officialMojangMappings())` 这一行是正确的，不是遗漏——26.1 不混淆，不需要重映射步骤。

## 最容易踩的坑

以下写法在 26.1.2 **全部编译失败**，已用映射文件逐个核实：

| 错误写法 | 26.1.2 正确写法 |
|----------|----------------|
| `ResourceLocation` | `net.minecraft.resources.Identifier` |
| `MinecraftClient` | `net.minecraft.client.Minecraft` |
| `ClientPlayerEntity` | `net.minecraft.client.player.LocalPlayer` |
| `ClientWorld` | `net.minecraft.client.multiplayer.ClientLevel` |
| `Text` / `MutableText` | `Component` / `MutableComponent` |
| `NbtCompound` | `net.minecraft.nbt.CompoundTag` |
| `World` / `ServerWorld` | `Level` / `ServerLevel` |
| `Formatting` | `net.minecraft.ChatFormatting` |
| `Box` | `net.minecraft.world.phys.AABB` |
| `Vec3d` | `net.minecraft.world.phys.Vec3` |
| `Hand` | `net.minecraft.world.InteractionHand` |
| `ActionResult` | `net.minecraft.world.InteractionResult` |
| `DrawContext` | `net.minecraft.client.gui.GuiGraphics` |
| `PlayerInventory` | `net.minecraft.world.entity.player.Inventory` |
| `ScreenHandler` | `net.minecraft.world.inventory.AbstractContainerMenu` |
| `HungerManager` | `net.minecraft.world.food.FoodData` |
| `RegistryKey` | `net.minecraft.resources.ResourceKey` |
| `DynamicRegistryManager` | `net.minecraft.core.RegistryAccess` |
| `StatusEffects` | `net.minecraft.world.effect.MobEffects` |
| `GameMode` | `net.minecraft.world.level.GameType` |

方法层面的改动（同样已核实）：

| 旧写法 | 26.1.2 正确写法 |
|--------|----------------|
| `ResourceKey#location()` | `ResourceKey#identifier()` |
| `Level#random`（字段） | `Level#getRandom()`（方法） |
| `new ResourceLocation(ns, path)` | `Identifier.fromNamespaceAndPath(ns, path)` |

完整清单见 `易错对照表-26.1.2.txt`。
