## 症状

多人服务器中点击开启服务器检测，模块显示「已开启」后约 1 秒自动关闭。

## 可证伪假设

| ID | 假设 | 结论 |
|----|------|------|
| A | 单人世界检测误判，`mc.hasSingleplayerServer()` 返回 true | ❌ 排除，日志显示 `hasSingleplayerServer: false` |
| B | `onActivate()` 中有其他自动关闭逻辑 | ❌ 排除，代码审查未发现 |
| C | `toggleOnBindRelease = true` 导致自动切换 | ✅ 当时判定确认（方向对，但修复不完整） |
| D | 事件监听冲突导致模块被外部关闭 | ❌ 排除，调用栈来自 `Module.toggle()` |

## 证据

从用户截图提取的游戏内日志：

```
[21:12:56] [yiyiaddon][服务器检测]已开启
[21:12:56] [yiyiaddon][服务器检测]服务器检测模块：onActivate() 被调用
[21:12:56] [yiyiaddon][服务器检测]hasSingleplayerServer: false
[21:12:56] [yiyiaddon][服务器检测]当前世界: 存在
[21:12:56] [yiyiaddon][服务器检测]连接状态: 已连接
[21:12:56] [yiyiaddon][服务器检测]服务器检测模块：初始化完成，开始监听
[21:12:57] [yiyiaddon][服务器检测]onDeactivate() 被调用
[21:12:57] [yiyiaddon][服务器检测]调用栈: Module.toggle(Module.java:104)
[21:12:57] [yiyiaddon][服务器检测]已关闭
```

时间线：

1. `21:12:56` 用户点击开启，`onActivate()` 正常执行
2. `21:12:56` 所有检查通过（非单人世界、世界存在、已连接）
3. `21:12:57` 约 1 秒后自动调用 `onDeactivate()`
4. 调用栈只截到 `Module.toggle()`，未继续往上取帧

## 当时判定的根因

`ServerDetector` 构造函数中设置了：

```java
this.toggleOnBindRelease = true;
```

该属性会让 Meteor 在特定时机自动切换模块开关状态。

## 当时的修复

删除构造函数里的赋值：

```java
public ServerDetector() {
    super(CATEGORY_TACTICAL, "服务器检测", "多层指纹识别核心与反作弊，自动白嫖资源包。");
    // 已移除: this.toggleOnBindRelease = true;
}
```

## 本轮的两个失误

1. **调用栈取得太浅**：只记到 `Module.toggle()` 就停了，没往上追到真正的触发方
   （实际是 `Modules.onOpenScreen`），因此把「1 秒后」误当成定时行为，而非「关闭 GUI 时」。
2. **忽略了配置持久化**：`toggleOnBindRelease` 会被序列化进 `modules.nbt`，
   `Module.fromTag` 每次启动都把旧的 `true` 读回内存。删源码赋值对已存盘配置无效，
   所以标了结案但用户仍然复现。

教训：调用栈要取足够深度；涉及可序列化字段时，必须同时处理内存与存档两条路径。
