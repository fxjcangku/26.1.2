# 调试会话：服务器检测模块两个 bug

**状态**：已修复  
**日期**：2026-08-26  
**模块**：ServerDetector

---

## 问题描述

用户报告 ServerDetector 有两个 bug：

1. **Bug A**：打开了模块进入服务器，不提示核心/反作弊类型（没检测）
2. **Bug B**：资源包下载没用，没提示下载成功（暴力模式和白嫖模式都没提示）

---

## 影响范围

- Bug A 影响核心检测与反作弊检测的播报
- Bug B 影响资源包自动下载功能

---

## 复现前提

- 多人服务器环境（单人世界会自动关闭模块）
- **关键**：用户操作顺序是**先进服，后开模块**

---

## 复现步骤

1. 进入多人服务器
2. 打开 ServerDetector 模块
3. 观察聊天栏 → 没有检测结果输出

---

## 根因分析

**核心问题**：`GameJoinedEvent` 只在进入世界时触发一次。如果用户是**进服后才打开模块**，事件已经错过，`onGameJoined()` 不会再执行。

**证据链**：
1. `onGameJoined()` 是唯一启动检测的入口（行 189）
2. 检测逻辑在延迟线程里调用 `performDetection()`（行 207）
3. Meteor 的事件系统：模块开启时才注册监听器，开启前的事件收不到
4. 用户报告"打开了模块进入服务器不提示" → 操作顺序是**先进服，后开模块**
5. 此时 `GameJoinedEvent` 早已触发，模块开启时不会再收到该事件

**Bug A 根因**：检测逻辑只在 `GameJoinedEvent` 触发，进服后才开启模块会错过事件。

**Bug B 根因**：资源包包本身工作正常（会持续接收），但用户反馈"都没提示"可能是因为服务器未发送资源包请求，或资源包模式设置问题。主要问题是 Bug A 导致用户误以为整个模块都不工作。

---

## 修复方案

在 `onActivate()` 里检查是否已在世界中：
1. 判断 `mc.player != null && mc.level != null && !mc.hasSingleplayerServer()`
2. 如果已在服务器中，手动启动延迟检测线程（复用 `onGameJoined` 的逻辑）
3. 播报提示"已在服务器中，将在 X 秒后开始侦测"

**关键代码**（ServerDetector.java 第 173-195 行）：
```java
// 如果是进服后才开启模块，手动触发检测（GameJoinedEvent 已经错过了）
if (mc.player != null && mc.level != null && !mc.hasSingleplayerServer()) {
    detectionDone = false;
    seenChannels.clear();
    rubberBandIndex = 0;
    rubberBandTotal = 0;
    
    long delayMs = detectDelay.get() * 1000L;
    Thread waiter = new Thread(() -> {
        try {
            Thread.sleep(delayMs);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            return;
        }
        mc.execute(this::performDetection);
    }, "yiyiaddon-ServerDetector-LateStart");
    waiter.setDaemon(true);
    waiter.start();
    
    notify("已在服务器中，将在 " + detectDelay.get() + " 秒后开始侦测");
}
```

---

## 修复层级

基类层面：无需修改基类，问题在于事件监听时机。

模块层面：在 `ServerDetector.onActivate()` 里补充"进服后开启"的处理分支。

---

## 复测结果

**预期行为**：
1. 进服前开模块 → `GameJoinedEvent` 触发检测
2. 进服后开模块 → `onActivate()` 手动触发检测
3. 两种情况都能看到侦测结果

待用户验证。

## 教训总结

**问题根源**：过度依赖单一事件入口，未考虑模块在不同时机开启的场景。

**设计缺陷**：
- `GameJoinedEvent` 只在进入世界时触发一次，不是持续状态
- 模块未检查当前是否已在世界中，直接假设开启时会收到事件

**改进方向**：
- 需要前置条件的模块（如进服才能工作），`onActivate()` 里必须检查当前状态
- 如果已满足条件（如已在服务器中），手动触发业务逻辑
- 不能只依赖事件驱动，要结合状态检查

**适用范围**：
- 所有依赖 `GameJoinedEvent` 的模块都要检查是否有这个问题
- 其他一次性事件（如 `GameLeftEvent`）也要注意类似场景
