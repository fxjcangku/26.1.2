## 0. 结论

- 自动附魔保持三模式：**原版装备极品附魔 / 原版附魔书 / 自定义附魔**，切换模式只显示对应配置页，业务流程隔离。
- 本次新增「原版装备极品附魔」：用**附魔台 + 砂轮 + 铁砧**把钻石装备逐步处理成 JSON 预定义极品附魔。
- 铁砧合并的是**装备 + 装备**（叠加附魔凑齐目标），**不是**「空白书 → 附魔书 → 装备」，装备模式零依赖附魔书生产流程。
- 复用现有状态机 / 发包 / 寻路 / 挂机 / .fumo / 点位 / 自检，未新建第二套系统。
- `gradlew clean build` 通过；代码层面完成，真机测试尚未进行。

## 2. 三种模式架构

```
自动附魔（AutoEnchantBook）
│
├── 原版装备极品附魔（GEAR）
│     ├── 装备箱（类型过滤 + 批量取用）
│     ├── 附魔台（装备本体附魔）

├── 原版附魔书（BOOK）—— 原有独立流程
```

## 3. 原版装备极品附魔完整流程

```
装备箱（按 gearTargetItem 类型过滤，每批取用数量默认 4）
  → 读取 JSON 目标（GearEnchantSetting.currentProfile → TargetProfile）
  → 原版附魔台（装备本体 QUICK_MOVE 到 slot 0 + 青金石 slot 1 + 点击附魔）
  → 读实际附魔（DataComponents.ENCHANTMENTS 完整解析）
  → 评估评分（EnchantEvaluationService.evaluate）
       ├─ complete(100%)  → 成品箱
       ├─ 可合并          → AnvilPlanner 规划铁砧合并
       └─ 凑不齐          → 砂轮磨掉全部 → 重新附魔重试
  → 铁砧「装备+装备」合并（互补/不互斥/不冗余判定）
  → XP 判断（附魔台固定 30 级 / 铁砧 AnvilMenu.getCost 实际费用）
  → XP 不足 → .fumo 挂机刷经验 → 达标 gearReturnState 返回
  → 铁砧继续 → JSON 最终验证（STRICT 100%）
  → 成品箱（卸货前重新验收 + 卸货成功确认）
```

## 4. JSON 数据体系

### 4.1 完整 Schema

```json
{
  "gears": [
    {
      "id": "minecraft:diamond_sword",
      "name": "钻石剑",
      "category": "weapon",
      "profiles": [
        {
          "id": "sharpness",
          "name": "锋利",
          "default": true,
          "exclusiveWith": ["smite", "bane_of_arthropods"],
          "targets": [
            { "id": "minecraft:sharpness", "name": "锋利", "level": 4, "excludable": false },
            { "id": "minecraft:unbreaking", "name": "耐久", "level": 3, "excludable": true }
          ]
        }
      ]
    }
  ]
}
```

### 4.2 装备范围（10 种，仅钻石）

| 类别 | 装备 |
|------|------|
| 工具 | 钻石镐、钻石斧、钻石锹、钻石锄 |
| 武器 | 钻石剑、弓 |
| 护甲 | 钻石头盔、钻石胸甲、钻石护腿、钻石靴子 |

### 4.3 校验规则（GearEnchantData.validate）

- 装备 ID 存在（`Registries.ITEM` 查证）
- 附魔 ID 存在（`Registries.ENCHANTMENT` 查证）
- 等级合法（`1 ~ Enchantment.getMaxLevel()`）
- 装备支持该附魔（`Enchantment.isSupportedItem`）
- 附魔属原版（namespace = `minecraft`）
- 附魔台可出（黑名单排除：mending / frost_walker / soul_speed / swift_sneak / binding_curse / vanishing_curse / wind_burst / breach / density）

非法配置日志明确报错，装备级非法直接剔除，不静默接受。

## 5. 核心模块方法级详解

### 5.1 EnchantEvaluationService（附魔识别 + 评分）

| 方法 | 说明 |
|------|------|
| `readEnchantments(ItemStack)` | `DataComponents.ENCHANTMENTS` 完整解析 → enchantmentId → 等级 Map |
| `evaluate(actual, profile, strategy, minAcceptRatio)` | 输出已满足/等级不足/缺失/多余/被排除/完成度/acceptable/complete |

评分策略：

- **STRICT**：所有目标（必需+可选）满级
- **BALANCED**：必需全满 + 可选达最低接受完成度
- **LOOSE**：必需达最低接受完成度

### 5.2 AnvilPlanner（铁砧合并规划）

| 方法 | 说明 |
|------|------|
| `plan(profile, gears)` | 选主装备（贡献最多）+ 逐件合并材料 |
| `isComplementary(base, mat, profile)` | 互补判定：材料带主装备缺失/等级不足附魔 |
| `hasConflict(base, mat)` | 互斥判定：`Enchantment.areCompatible(Holder, Holder)` |
| `mergeInto(target, source)` | 模拟附魔合并（相同附魔取高+1，不同叠加，仅逻辑不算 XP） |
| `readCost(AnvilMenu)` | `getCost()` 实际费用（唯一费用来源） |
| `isTooExpensive(cost)` | `cost > 39` 判定太昂贵 |

**合并判定三原则**：互补（有价值）/ 不互斥（不丢附魔）/ 不冗余（无收益则跳过）。

### 5.3 GearEnchantTask / GearTaskQueue（任务队列）

- `GearEnchantTask`：taskId / 装备身份 / TargetProfile / 当前装备 / 阶段 / 步骤 / XP / 点位 / 状态 / 错误原因；`accept(finalGear)` 用 STRICT 100% 验收。
- `GearTaskQueue`：每件独立推进，单件失败标记异常继续下一件，不拖垮整批。

### 5.4 可靠性

| 类 | 职责 | 接入状态 |
|----|------|---------|
| GearSafetyGuard | 耐久 <20% 停止处理（`DataComponents.UNBREAKABLE` 恒安全） | 已接入（铁砧合并前） |
| RetryGuard | 重试上限（默认 3），防死循环 | 已接入（附魔→砂轮循环） |
| RecoveryValidator | 断点恢复验证（玩家/维度/装备） | 已接入（onTick 周期校验） |
| XpPlanner | 附魔台固定 30 级 / 铁砧实际费用 / 批次最高需求 | 已接入 |

## 6. 状态机完整定义

复用现有 `State` 枚举（未建第二套状态机），GEAR 新增状态与流转：

| 状态 | 中文名 | 流转 |
|------|--------|------|
| GEAR_IDLE | 待机 | 无队列→取装备；有队列→附魔；空→停机 |
| GEAR_WALK_EQUIPMENT | 前往装备箱 | 到→取装备 |
| GEAR_TAKE_GEAR | 取装备 | 取满→建队列→待机 |
| GEAR_WALK_ENCHANT | 前往附魔台 | 30 级不足→挂机；青金石不足→青金石箱；到→附魔 |
| GEAR_ENCHANTING | 附魔装备 | 完成→评估 |
| GEAR_WALK_LAPIS | 前往青金石箱 | 到→取青金石 |
| GEAR_RESTOCK_LAPIS | 取青金石 | 补满→附魔台 |
| GEAR_EVALUATE | 评估 | complete→成品；可合并→铁砧；否则→砂轮 |
| GEAR_WALK_GRIND | 前往砂轮 | 到→磨装备 |
| GEAR_GRINDING | 磨装备 | 磨完→附魔台重试 |
| GEAR_WALK_ANVIL | 前往铁砧 | 损坏→铁砧箱；到→铁砧 |
| GEAR_ANVIL | 铁砧合并 | 合并完→验收→成品/异常 |
| GEAR_WALK_ANVIL_BOX | 前往铁砧箱 | 到→取铁砧 |
| GEAR_TAKE_ANVIL | 取铁砧 | 无备用→暂停；取到→回原位 |
| GEAR_WALK_ANVIL_POS | 返回铁砧位 | 到→放置 |
| GEAR_PLACE_ANVIL | 放置铁砧 | 放好→重新检测 |
| GEAR_WALK_OUTPUT | 前往成品箱 | 卸货前重新验收 |
| GEAR_STORE_OUTPUT | 存成品 | 成功→下一件 |
| GEAR_WALK_ERROR | 前往异常箱 | 到→存异常 |
| GEAR_STORE_ERROR | 存异常 | 成功→下一件 |

挂机复用 `WALK_TO_FARM / FARMING`，`gearReturnState` 记录挂机后返回目标。

## 9. 铁砧检测与自动更换

```
使用前 tickGearWalkAnvil → isAnvilAt(posAnvil)（ANVIL/CHIPPED_ANVIL/DAMAGED_ANVIL）
  → 正常 → GEAR_ANVIL 合并
  → 损坏/消失 → GEAR_WALK_ANVIL_BOX（去铁砧箱）
       → GEAR_TAKE_ANVIL（QUICK_MOVE 取 1 个，铁砧不可堆叠）
           → 无备用 → 暂停 + 「铁砧已损坏，铁砧箱没有备用铁砧」
       → GEAR_WALK_ANVIL_POS（回原坐标）
       → GEAR_PLACE_ANVIL（按保存朝向 AnvilBlock.FACING 放置到 posAnvil）
       → 重新检测 → 恢复原任务（gearAnvilPlan/装备/目标上下文保留）
```

合并过程中也检测（`tickGearAnvil` 开头 `isAnvilAt`），损坏立即切换更换。

## 10. 装备过滤与批量取用

- `tickGearTakeGear` 只 `QUICK_MOVE` `stack.is(gearTargetItem)`，其他装备类型不拿。
- 缺货 → `notifyError("装备箱中没有可用的<装备名>…")` + 停机。
- `每批取用数量`（默认 4）参与 `gearTakeCount` 与 `buildGearQueue`，不写死 4。
- 铁砧合并消耗装备，最终完成数可能小于输入数（批量数量是输入数量）。

---

## 11. 青金石与 GUI 延迟

- 复用 `青金石补给组数`（默认 1 组=64），未新建独立组数。
- 附魔前 `countInInventory(LAPIS_LAZULI) < 3` → `GEAR_WALK_LAPIS` 前往青金石箱 → 补满 → 回附魔台。
- GUI 延迟复用 `GUI操作延迟.get()` + `GUI_OPEN_PENDING/GUI_OPEN_TIMEOUT`，无第二套 Delay 系统。

---

## 12. 成品箱自动卸货

- `tickGearWalkOutput` 卸货前重新 `evaluate(STRICT, 1.0).complete()`，不达标进异常箱。
- 满箱 → `notifyError("成品箱空间不足，原版装备极品附魔已暂停。")` + 停机。
- 放入后确认 `gearEquipSlot` 已空（装备已离开背包），失败重试 3 次，超限 `REPEATED_FAILURE` 进异常箱。

---

## 13. 模式隔离与复用

- 装备极品附魔**不调用**附魔书生产流程，`Items.BOOK` / `Items.ENCHANTED_BOOK` 仅存在于 BOOK 模式的 `tickEnchanting/tickChecking/tickGrinding/tickStoring/tickRestocking`。
- 复用：状态机、发包（FarmPacketOps）、寻路（Baritone）、挂机（KillAura）、.fumo、自检、点位、GUI 延迟、青金石组数。
