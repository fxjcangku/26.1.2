# 2026-09-03 传送模块开发报告

## 一、模块概述

新增 Meteor Client 模块「传送」（yiyiaddon §b§l绕过 分类），提供三个相互独立的功能，各自绑定独立按键：

| 功能 | 语义 | 触发方式 |
| --- | --- | --- |
| TP地面 | 回到头顶真正露天地表（洞穴脱身 / 高空落地） | 独立按键（松开触发） |
| TP穿墙 | 穿过准心瞄准的墙体，落在墙后安全点 | 独立按键（松开触发，锁定触发瞬间视线） |
| TP坐标 | 传送到配置坐标或指令指定坐标 | 独立按键 + 指令 `.tp X Y Z` |

统一特性：真实碰撞形状安全判据、服务器回弹验证、载具整体位移、调试渲染、断点中止防护。

## 二、代码分类结构（铁律：不写死单文件，按职责分包）

```
src/main/java/com/example/addon/
├── modules/TeleportModule.java            模块类：设置面板 + 事件接线 + 请求打包（唯一入口）
└── teleport/                              传送功能包（独立英文功能包，同类 mining/farm/tactical）
    ├── model/        数据模型：TeleportMode / TeleportState / TeleportTarget /
    │                               TeleportRequest / TeleportContext
    ├── safety/       安全判据：CollisionSafety（碰撞/支撑/岩浆/虚空）
    │                               SafePositionFinder（邻近安全落点搜索，射线约束）
    ├── geo/          几何扫描：SurfaceScanner（真正地表双向扫描）
    │                              WallRayScanner（体素 DDA 穿墙扫描 + 墙后落点解析）
    ├── move/         执行层：PositionExecutor（本地位移 + 26.1.2 官方发包 / 载具位移）
    ├── verify/       验证层：RubberbandVerifier（服务端权威包分类）
    ├── core/         决策层：TeleportCoordinator（O→D→E→V 状态机，唯一决策点）
    ├── command/      指令：TpCommand（.tp X Y Z）
    └── render/       渲染：TeleportRender（目标点/射线/候选格/回弹点）
```

- 模块类放 `modules/`，辅助类全部放 `teleport/` 功能包并按职责细分子包，符合工程规范化标准 ④。
- 决策层只消费 `TeleportRequest` 参数包，不依赖任何模块/设置对象；播报经 `Sink` 回调回模块基类 `highlight*` 方法，遵守强调色转换体系与前缀对齐要求。

## 三、架构：Observe → Decide → Execute → Verify

1. **OBSERVE（同步）**：锁定原点、维度、视线快照（穿墙模式射线在按键瞬间快照，之后移动鼠标不影响本次目标）。
2. **DECIDE（同步）**：按模式计算目标落点，全部经过统一安全判据；失败即播报终止。
3. **EXECUTE（同步）**：本地位移 + 发包。
4. **VERIFY（异步窗口，默认 8 tick）**：观察服务端位置权威包与超时共同裁决——
   - 收到权威位置且偏差 ≤ 阈值（1.5 格）→ 接受；
   - 偏差 > 阈值 → 回弹（播报偏差，位置跟随服务器）；
   - 窗口内无权威包 → 服务端接受（原版服务器接受合法移动时不回位置包）。

断点防护（每 tick 校验）：维度变化 / 玩家死亡 / 载具关系变化 → 立即中止并播报。
防刷屏：执行中重复触发 20 tick 节流提示；单次传送状态转换各播报一次。

## 四、三模式算法

### TP地面（SurfaceScanner）
- 以脚底为起点双向扫描竖直列：优先向下（空中落地），再向上（洞穴回到地表，上限可配默认 200 格）。
- 「真正地表」判据 = `LevelReader.canSeeSky`（开天，保证是露天表面而非洞穴天花板）+ 统一安全判据通过。
- 站在真正地表时触发 → 播报「已在真正地表，无需传送」，不移动。

### TP穿墙（WallRayScanner）
- Amanatides-Woo 体素 DDA 步进，以 `getBlockCollisions` 真实碰撞形状判定实体墙层，统计穿透层数并给出墙体远侧射线出口点。
- 出口点解析落点：先出口列、再视线前推列，允许最大落差下落（默认 6 格）找支撑。
- 解析失败回退 `SafePositionFinder`（准心射线约束：落点垂直偏离 ≤ 上限默认 3 格）。
- 远侧校验：落点沿视线进展不得退回墙的近侧。
- 无墙 / 墙过厚（射线耗尽仍在墙内）→ 明确中文失败播报。

### TP坐标（CoordStrategy，内联于协调器）
- 目标脚底中心（x+0.5, y, z+0.5）直接过安全判据；不可站立时回退邻近安全搜索（半径可配默认 4 格，可关）。

## 五、关键技术依据（26.1.2 官方源码逐项核对）

| 机制 | 依据 |
| --- | --- |
| 本体发包 | `LocalPlayer.sendPosition` 同款 `ServerboundMovePlayerPacket.Pos(x,y,z,onGround,horizontalCollision)`，`mc.connection.send` |
| 载具发包 | `LocalPlayer.tick` 同款 `ServerboundMoveVehiclePacket.fromEntity(vehicle)`，仅本机权威载具（`isLocalInstanceAuthoritative`） |
| 回弹观测 | `PacketEvent.Receive`（Meteor ConnectionMixin，包处理前）+ `PositionMoveRotation.calculateAbsolute`（官方相对→绝对换算，玩家）+ `ClientboundMoveVehiclePacket`（载具） |
| 只观察不拦截 | 权威包照常交原版处理（`handleMovePlayer`/`handleMoveVehicle`），客户端与服务端最终一致 |
| 碰撞判据 | `EntityDimensions.makeBoundingBox` + `Level.getBlockCollisions`（真实 VoxelShape，台阶/半砖可站） |
| 区块可用 | `ClientLevel.hasChunk` |
| 开天 | `LevelReader.canSeeSky` |
| 本地位移 | `Entity.absSnapTo(x,y,z,yRot,xRot)`（官方吸收瞬间位置的同一方法） |
| 独立按键 | Meteor 26.1.2 `KeybindSetting` 的 `action` 回调（模块开启 + 松开触发），三按键互不干扰 |

## 七、模块配置面板

- 触发按键：TP地面键 / TP穿墙键 / TP坐标键（默认未绑定，GUI 内自行绑定，支持组合键与鼠标侧键）。
- TP地面：地表扫描上限（16~320，默认 200）。
- TP穿墙：视线射线距离（4~48，默认 16）、落点偏离上限（0.5~8，默认 3）、最大下落落差（0~20，默认 6）。
- TP坐标：坐标 X/Y/Z（默认 0/100/0）、回退搜索半径（0~8，默认 4）。
- 验证：回弹判定阈值（0.25~4 格，默认 1.5）、验证窗口（2~20 tick，默认 8）。
- 调试：调试渲染（目标点/射线/候选格/回弹点）。

所有数值配置均使用 `.noSlider()`（加减按钮 + 输入框），遵守数值配置控件规范 5.10。

## 八、使用方式

1. 开启「传送」模块；
2. 在 GUI 触发按键组绑定三个独立按键；
3. TP坐标除按键外可用指令 `.tp X Y Z`（当前维度、整数坐标；模块开启后可用）；
4. 乘坐船/矿车等本机权威载具时传送以载具整体位移执行。
