## 五、核心流程

```
onActivate
  ├─ 加载服务器档案 (repo.loadDefault)
  ├─ 自检 selfCheck() → 缺失项阻止启动并提示
  └─ 绑定农田范围 + 全量扫描

onTick（Observe → Decide → Act → Verify → Replan）
  ├─ 有任务 → 推进任务 → done 则 handleResult（Verify / Replan）
  ├─ decideLogistics()：补货优先 → 卸货（复用 UnloadTask / StardewRestockTask）
  ├─ dayManager.plan() → 逐块评估（每次执行前重新 Observe）
  │    优先级：收割 → 浇水 → 施肥 → 种植
  └─ taskFor(FarmAction) → 创建对应 FarmTask

任务内部：Observe → 确认目标(known) → 执行(FarmPacketOps) → 验证(再次识别) → SUCCESS / FAILED
未知状态 → 返回 TARGET_INVALID，安全停止，不执行危险动作
```

### 安全原则

- 未知成熟状态**绝不收割**（宁可不收，也不误收）。
- 未知浇水/施肥状态**绝不盲目浇水/施肥**。
- 未知种子/作物/农田/洒水器：记录 Debug 信息 → 停止当前危险动作 → 等待配置。

## 六、ID 对接流程

```
手持服务器种子
  → IdSystemIntegration.registerFromStack(ItemStack)
  → ItemIdentifier.identifyItem() 生成完整身份（itemId + DataComponents + customName）
  → idManager.add(identity)   ← 复用现有 ID 三件套唯一数据源
  → 生成 StardewSeedProfile（携带 identityKey 引用 + cropId）
  → repo.save(profile) 持久化 JSON
  → 种子选择器 / 自动种植可直接解析
```

种子识别退化逻辑：`RuntimeSeedRecognizer` 先用 `minecraftItemId` 匹配，再回退到 ID 系统 `ItemIdentity.matches(ItemStack)` 组件级匹配。

## 七、无资源包模式可用能力

- 添加 / 删除 / 选择种子（`.stardew addseed` 或 UI 种子选择器）
- 登记农田底盘（`.stardew soiladd`）
- 四点位绑定（农场点位 1/2、种子箱、收获箱）
- 农田扫描、作物/成熟/生长/浇水/施肥识别（基于手工配置档案 + 世界数据）
- 收割 / 种植 / 浇水 / 施肥任务 + 补货 / 卸货
- JSON 持久化、启动自检、未知状态安全停止

**需手工配置后才生效**（因无资源包无法自动推断）：

- 作物方块 ID、成熟方块 / 属性
- 浇水 / 施肥规则
- 肥料与洒水器规则

以上均写入服务器档案 JSON（`<clientdata>/stardew/server_default.json`）后生效。
