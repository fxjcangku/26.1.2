## 二、真实错误（已修复）

### 1. JoinMultiplayerScreenTranslationMixin —— 目标方法与注入点完全不存在

- 文件：`mixin/JoinMultiplayerScreenTranslationMixin.java`
- 原写法注入 `JoinMultiplayerScreen.extractRenderState(...)` 中的 `GuiGraphicsExtractor.text(Font, String, III)V`。
- 实测：26.1.2 的 `JoinMultiplayerScreen` 类中**没有** `extractRenderState` 方法，也不存在该 INVOKE 调用；原 mixin 因 `require=0` 100% 静默失效（功能从未生效）。
- 26.1.2 真实渲染点：`ServerSelectionList$OnlineServerEntry.extractContent(GuiGraphicsExtractor, int, int, boolean, float)` 内第 358 行
  `graphics.text(font, statusComponent, x, y, -8355712)`（Component 重载，非 String）。
- 修复后的注入：
  ```java
  @Mixin(targets = "net.minecraft.client.gui.screens.multiplayer.ServerSelectionList$OnlineServerEntry", priority = 1100)
  @ModifyArg(
      method = "extractContent(Lnet/minecraft/client/gui/GuiGraphicsExtractor;IIZF)V",
      at = @At(value = "INVOKE",
          target = "Lnet/minecraft/client/gui/GuiGraphicsExtractor;text(Lnet/minecraft/client/gui/Font;Lnet/minecraft/network/chat/Component;III)V"),
      index = 1)
  ```
- 同时：纠正参数类型 String→Component；移除错误的 `remap=false`（本项目 Minecraft mixin 统一走官方映射自动 remap）；`require=0` 已删除（目标方法已实证存在，恢复默认收紧，防止未来再静默失效）。
- 组件翻译策略：仅当 `getContents()` 为 `PlainTextContents` 且命中翻译时以 `Component.literal(translated)` 替换；红色版本不兼容提示等特殊样式组件原样保留。

## 五、构建映射体系确认（mixin 字符串能否正确 remap 的关键）

- `gradle/libs.versions.toml` 声明了 yarn 库，但 `build.gradle.kts` 的 dependencies **未引用 `mappings(libs.yarn)`**（yarn 仅存于版本目录，为死配置候选，本次未动）。
- 实际编译映射 = Loom 默认官方映射（Mojang official），证据：项目全部 Minecraft mixin 使用官方类名（`ClientCommonPacketListenerImpl`、`KeyboardHandler`、`MultiPlayerGameMode` 等）且 `--rerun-tasks` 全量编译通过、`javap` 依赖 jar 内 MC 引用亦是官方名（`net.minecraft.client.gui.Font`）。
- 结论：Minecraft mixin 不写 `remap=false`（自动按官方名解析），Meteor/Baritone mixin 写 `remap=false`（它们未被 MC 映射重映射）——现有体系自洽，与本次修复后的写法一致。

## 六、剩余风险提示（非 API 错误，未修改）

1. `ConfigCustomFontDefaultMixin` / `HudCustomFontDefaultMixin` 的 `@ModifyConstant(intValue=1, ordinal=0)` 依赖字节码常量出现顺序，若未来 Meteor 在 Config/Hud 构造器前部新增 int 常量 1 将错位。建议届时改用 `@ModifyArg` 精确指向 `defaultValue` 调用。
2. `CategoryTranslationMixin` 修改 `name` 字段但 `nameHash`/`equals`/`hashCode` 仍基于英文名（Category.java 构造器内计算），当前仅影响同一 Category 内 equals 语义，GUI 分组按引用工作不受影响，暂不处理。
3. `libs.versions.toml` 中未使用的 `yarn` 库声明为死配置候选，因涉及构建系统本次未删，后续确认无隐式引用后可清理。
4. 服务器检测/发包绕过/飞行绕过三模块的重设计结论（见 2026-09-03 联合审计报告）属于架构层面，本次 API 审查不涉及，其现有 API 用法已编译通过。
