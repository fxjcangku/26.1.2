## 五、典型用法

```java
// 读附魔
ItemEnchantments enc = stack.get(DataComponents.ENCHANTMENTS);   // 可能 null，判 stack.has(...) 更稳
int level = stack.getEnchantments().getLevel(Enchantments.SHARPNESS); // 见 附魔.md

// 写显示名（铁砧重命名）
stack = stack.set(DataComponents.CUSTOM_NAME, Component.literal("神剑"));

// 累加修理惩罚
stack = stack.update(DataComponents.REPAIR_COST, 0, cost -> cost + 2);

// 任意数据（等效旧 getOrCreateTag）
CustomData data = stack.getOrDefault(DataComponents.CUSTOM_DATA, CustomData.EMPTY);
```

## 六、常见坑（精简）

1. `getComponents()` 返回快照，改它不影响物品；改物品必须 `stack = stack.set/update(...)` 重新赋值。
2. `set(type, null)` 是删除，区分「写 0/空字符串」与「删组件」。
3. `isTransient()`（无 codec）组件不落盘；自定义组件要绑 `.persistent(Codec)` 才可持久化，`.networkSynchronized(StreamCodec)` 才可发包。
4. `CUSTOM_DATA` 只是普通组件，塞入的数据结构需带 codec；`NbtCompound` 已删除。
5. `DataComponentMap.keySet()` 只读，遍历用 `for (TypedDataComponent<?> e : components)`。
6. 旧 API `getNbt()/getOrCreateNbt()/setNbt()` 已全部移除，改组件体系。
