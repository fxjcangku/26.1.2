# 附魔（Enchantment）

> 源码依据：Minecraft原始源码/net/minecraft/world/item/enchantment/ 与 net/minecraft/tags/EnchantmentTags.java 26.1.2 Mojang官方映射

**26.1.2 附魔全面数据驱动化**（1.21.4+ 大改版）：附魔不再是 `Enchantment` 子类 + 一堆 `overridable` 方法，而是 JSON 数据驱动的一条 `record Enchantment`；互斥关系、效果（伤害/保护/附魔光效等）全部数据化到 `DataComponentMap` 与 effect 注册表。客户端 addon 判读「某物品有哪些附魔/多少级」以 `ItemEnchantments` + `Holder<Enchantment>` 为核心。

---

## Enchantment（net.minecraft.world.item.enchantment.Enchantment）

- 包名：`net.minecraft.world.item.enchantment`
- 源码路径：`net/minecraft/world/item/enchantment/Enchantment.java`
- 继承与接口：`public record Enchantment(Component description, Enchantment.EnchantmentDefinition definition, HolderSet<Enchantment> exclusiveSet, DataComponentMap effects)`。
- 是 record，不是普通 class；由数据包 `enchantment/*.json` 加载，运行时拿到的是 `Holder<Enchantment>`。

### 关键常量与编码

```java
public static final int MAX_LEVEL = 255;
public static final Codec<Enchantment> DIRECT_CODEC;
public static final StreamCodec<RegistryFriendlyByteBuf, Holder<Enchantment>> STREAM_CODEC;
```

### 嵌套 record / Builder

```java
public record EnchantmentDefinition(
    HolderSet<Item> supportedItems,
    Optional<HolderSet<Item>> primaryItems,
    int weight,
    int maxLevel,
    Enchantment.Cost minCost,
    Enchantment.Cost maxCost,
    int anvilCost,
    List<EquipmentSlotGroup> slots
);

public record Cost(int base, int perLevelAboveFirst) {
    public int calculate(int level);   // base + perLevelAboveFirst * (level - 1)
}

public static class Enchantment.Builder {
    public Enchantment.Builder exclusiveWith(HolderSet<Enchantment> set);
    public <E> Enchantment.Builder withEffect(DataComponentType<List<ConditionalEffect<E>>> type, E effect);
    // ... 带条件/目标的 withEffect 重载
}
```

### 26.1.2 注意
- **互斥不再硬编码**：`exclusiveSet` 是 `HolderSet<Enchantment>`，运行时读；判断两附魔能否共存用 `Enchantment.areCompatible(a, b)`，别自己维护锋利/亡灵杀手冲突表。
- **旧 `Enchantment.getSlot()/isTreasureOnly()/getRarity()` 已不存在**，对应信息进 `definition`（slots / weight）或 tag（`TREASURE` / `CURSE`）。

## ItemEnchantments（net.minecraft.world.item.enchantment.ItemEnchantments）

- 源码路径：`net/minecraft/world/item/enchantment/ItemEnchantments.java`
- 继承与接口：`public class ItemEnchantments implements TooltipProvider`。
- 物品上「附魔 -> 等级」的不可变映射（等级 1~255，key 是 `Holder<Enchantment>`）。

### 关键字段与方法（签名照抄源码）

```java
public static final ItemEnchantments EMPTY;
public int getLevel(Holder<Enchantment> enchantment);   // 取等级，无则 0
public Set<Holder<Enchantment>> keySet();
public Set<Object2IntMap.Entry<Holder<Enchantment>>> entrySet();
public int size(); public boolean isEmpty();

// 可变构建器（改等级用它，再写回组件）
public static class Mutable {
    public Mutable(ItemEnchantments enchantments);
    public void set(Holder<Enchantment> enchantment, int level);   // <=0 删除
    public void upgrade(Holder<Enchantment> enchantment, int level);// 取 max 级别
    public void removeIf(Predicate<Holder<Enchantment>> predicate);
    public int getLevel(Holder<Enchantment> enchantment);
    public Set<Holder<Enchantment>> keySet();
    public ItemEnchantments toImmutable();
}
```

```java
// 读物品附魔
ItemEnchantments enc = stack.getEnchantments();                 // == stack.get(DataComponents.ENCHANTMENTS)
int level = enc.getLevel(Enchantments.SHARPNESS);               // 锋利等级

// 修改物品附魔（写回）
ItemEnchantments.Mutable m = new ItemEnchantments.Mutable(stack.getEnchantments());
m.set(Enchantments.UNBREAKING, 3);
stack = stack.set(DataComponents.ENCHANTMENTS, m.toImmutable());
```

## Enchantments（net.minecraft.world.item.enchantment.Enchantments）

- 源码路径：`net/minecraft/world/item/enchantment/Enchantments.java`
- 所有原版附魔的 `ResourceKey<Enchantment>` 常量集合，命名 `大写_蛇形`，如：

```java
public static final ResourceKey<Enchantment> SHARPNESS = key("sharpness");
public static final ResourceKey<Enchantment> UNBREAKING = key("unbreaking");
public static final ResourceKey<Enchantment> EFFICIENCY = key("efficiency");
public static final ResourceKey<Enchantment> FORTUNE = key("fortune");
public static final ResourceKey<Enchantment> SILK_TOUCH = key("silk_touch");
public static final ResourceKey<Enchantment> MENDING = key("mending");
public static final ResourceKey<Enchantment> PROTECTION = key("protection");
// ... 锋利亡灵杀手/火矢/无限/忠诚/激流/多重射击等 45 个常量（见源码，含 DENSITY/BREACH/WIND_BURST/LUNGE 新附魔）
```

- **注意**：`Enchantments` 里是 key 不是 `Holder`，也不是可 `==` 比较的 `Enchantment` 对象。拿到 `Holder<Enchantment>` 后判断身份：`holder.is(Enchantments.SHARPNESS)`；或经注册表 lookup 取 `Holder`。

`EnchantmentTags`（`net/minecraft/tags/EnchantmentTags.java`）常用 tag：`TOOLTIP_ORDER`（tooltip 展示顺序）、`CURSE`（诅咒）、`TREASURE`/`NON_TREASURE`（宝藏/非宝藏）、`TRADEABLE`、`IN_ENCHANTING_TABLE`（附魔台可出），及 `DAMAGE_EXCLUSIVE`/`MINING_EXCLUSIVE` 等互斥集合。

## 常见坑

1. **`Enchantments.XXX` 是 `ResourceKey` 不是 `Holder`**：`getLevel(Enchantments.SHARPNESS)` 传参类型是 `Holder<Enchantment>`，直接传 key 会编译失败。要先从「该物品附魔的 `keySet()`」里拿 `Holder`，或经 `getOrThrow` 的 `HolderLookup.RegistryLookup<Enchantment>` 解析 key 成 `Holder`。
2. **`ItemEnchantments.getLevel` 无则返回 0，`ItemEnchantments.EMPTY` 判空**：未附魔物品 `getEnchantments()` 返回 `EMPTY`，但可能是 `stack.get(DataComponents.ENCHANTMENTS)` 直接返回 `null`（组件不存在）；判空用 `stack.has(DataComponents.ENCHANTMENTS)`，别在 null 上 `getLevel`。
3. **改附魔要经 `Mutable` 再写回组件**：`ItemEnchantments` 本身不可变，直接对它没 `set`；`Mutable.set(h, 0)` 才是删除该附魔（`<=0` 即移除）。
4. **互斥关系用 `areCompatible` 判定，别背表**：`Enchantment.areCompatible(a, b)` 同时查双向 `exclusiveSet`；自己写 `a != b` 判断会漏掉锋利/亡灵杀手这类互斥对。
5. **`EnchantmentHelper` 大量方法是服务端语义（收 `ServerLevel`）**：客户端 addon 只是「预测/展示」，真正扣血、经验、耐久由服务端算；不要在客户端幻想调用 `getDamageProtection` 拿权威数值。
