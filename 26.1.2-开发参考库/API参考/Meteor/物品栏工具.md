# 物品栏工具

物品栏操作三件套：`InvUtils`（查找/交换/移动物品）、`FindItemResult`（查找结果 record）、`SlotUtils`（槽位常量与槽索引→槽 ID 换算）。玩家物品栏以 `mc.player.getInventory()` 访问。

### 内部类 Action（操作链）
`move()`/`click()` 等返回共享单例 `ACTION`（**每次调用会重置状态**）。用法：先选类型，再选 from/to/slot，最后触发：
```java
public Action fromId(int id)
public Action from(int index)          // 玩家 41 槽索引 → id
public Action fromHotbar(int i)        // i: 0..8
public Action fromOffhand()
public Action fromMain(int i)          // i: 0..26
public Action fromArmor(int i)         // i: 装备槽实体序（EquipmentSlot）

public void toId(int id)               // 触发点击（终点）
public void to(int index)
public void toHotbar(int i)
public void toOffhand()
public void toMain(int i)
public void toArmor(int i)

public void slotId(int id)             // 单格点击（from==to）
public void slot(int index)
public void slotHotbar(int i)
public void slotOffhand()
public void slotMain(int i)
public void slotArmor(int i)
```
> 底层最终调用 `mc.gameMode.handleContainerInput(mc.player.containerMenu.containerId, id, data, type, mc.player)`。
> `from`/`to`/`slot` 接受的是**槽索引（index，玩家物品栏 0..40）**，内部经 `SlotUtils.indexToId(index)` 换算成协议 slot id；`fromId/toId/slotId` 直接传协议 id。
> 典型交换主手物品：`InvUtils.move().from(mainIndex).toHotbar(hotbarIndex);`

## 2. FindItemResult

### 类名 / 源码路径
`FindItemResult`／`meteordevelopment/meteorclient/utils/player/FindItemResult.java`

### 定义（record，真实签名）
```java
/**
 * @param slot  槽索引（未找到为 -1）
 * @param count 该物品总数
 */
public record FindItemResult(int slot, int count) {
    public boolean found()                      // slot != -1
    public InteractionHand getHand()            // OFF_HAND / MAIN_HAND / null
    public boolean isMainHand()
    public boolean isOffhand()
    public boolean isHotbar()                   // slot in [HOTBAR_START, HOTBAR_END]
    public boolean isMain()                     // slot in [MAIN_START, MAIN_END]
    public boolean isArmor()                    // slot in [ARMOR_START, ARMOR_END]
}
```
> addon 标准判断：`FindItemResult item = InvUtils.find(Items.TOTEM); if (item.found()) { ... item.slot() ... }`。

## 3. SlotUtils

### 类名 / 源码路径
`SlotUtils`／`meteordevelopment/meteorclient/utils/player/SlotUtils.java`

### 槽位常量（真实值，玩家物品栏 41 槽索引）
```java
public static final int HOTBAR_START = 0;
public static final int HOTBAR_END = 8;
public static final int MAIN_START = 9;   // 主物品栏（27 格）
public static final int MAIN_END = 35;
public static final int ARMOR_START = 36;
public static final int ARMOR_END = 39;
public static final int OFFHAND = 40;
```

### 关键方法
```java
public static int indexToId(int i)   // 玩家槽索引 → 当前容器 ScreenHandler 的协议 slot id
public static boolean isHotbar(int slotIndex)
public static boolean isMain(int slotIndex)
public static boolean isArmor(int slotIndex)
```
> `indexToId` 根据当前打开的容器类型（生存物品栏/箱子/工作台/熔炉/附魔台/酿造台/村民/铁砧/漏斗/马/制图台/磨石/织布机/切石机/锻造台/合成器…）做不同换算；这些槽 ID 用于 `MultiPlayerGameMode.handleContainerInput` 及容器点击包。addon 若绕过 `InvUtils` 直接点击容器槽，必须用 `SlotUtils.indexToId` 转成协议 id。

## 常见坑
1. `InvUtils.move()/click()/quickSwap()...` 返回的是**同一个共享 `Action` 单例**，只适合「立即链式调用完」；**不要缓存引用跨 tick 使用**。
2. `from(index)/to(index)/slot(index)` 传的是玩家物品栏索引（0..40），而 `fromId/toId/slotId` 传协议 id——混用会点到错误槽位。容器内操作务必用 `SlotUtils.indexToId`。
3. `find(...)` 在 `mc.player == null` 时返回 `new FindItemResult(0, 0)`（**slot=0, found()==false 语义易误判**），调用前先判空。
4. `swap(int slot, ...)` 只接受 `0..8` 热键栏，`slot==SlotUtils.OFFHAND(40)` 会直接返回 true 不切换。
5. `FindItemResult.getHand()` 只有「副手/当前选中主手」时非空，其余返回 `null`，使用前判空。
6. 快速换物最佳实践：`InvUtils.find(...)` 定位 → `swap(targetSlot, false)` 切过去 → 用毕 `swapBack()`。
7. 一起 OOM：`find` 的 `count` 是「匹配多个槽的物品总数」，不是单一槽数量，别当成单槽堆叠数。
