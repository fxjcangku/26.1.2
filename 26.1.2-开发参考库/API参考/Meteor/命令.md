# 命令

> 源码依据：Meteor原始源码/meteordevelopment/meteorclient/commands/... Meteor Client 26.1.2-SNAPSHOT

Meteor 命令基于 **Brigadier**（`com.mojang.brigadier`）构建。26.1.2 中 `Command` 抽象类统一管理与注册，`Commands` 是全局命令管理器。本文整理 `Command`、命令真实子类示例（`SayCommand` / `DamageCommand`）、`Commands` 管理器与调用方式。

> ⚠️ 旧版 `CommandArgumentType` 在 26.1.2 中**已移除**。现在直接在 `build(...)` 里用 `argument(name, ArgumentType)` / `literal(name)` 两个受保护静态辅助方法。

## Command

### 类名
`meteordevelopment.meteorclient.commands.Command`

### 包名
`meteordevelopment.meteorclient.commands`

### 源码路径
`commands/Command.java`

### 继承与接口
`public abstract class Command`

### 关键字段（真实，全部可见性照源码）
| 字段名 | 类型 | 中文用途 |
| --- | --- | --- |
| `name` | `private final String` | 命令名（不含前缀） |
| `title` | `private final String` | 由 `Utils.nameToTitle(name)` 生成的标题（用于消息前缀） |
| `description` | `private final String` | 命令描述 |
| `aliases` | `private final List<String>` | 别名列表 |

受保护静态成员：
```java
protected static CommandBuildContext REGISTRY_ACCESS;
protected static final int SINGLE_SUCCESS = com.mojang.brigadier.Command.SINGLE_SUCCESS;
protected static final Minecraft mc = MeteorClient.mc;
```
- `REGISTRY_ACCESS`：服务器加入后由 `Commands.onJoin` 用动态注册表重建（跨服切换后重建）。需要用到注册表（如物品/方块参数）的命令用它。
- `SINGLE_SUCCESS`：`.executes(context -> ...)` 返回 `SINGLE_SUCCESS` 表示执行成功。

### 构造器（真实签名）
```java
public Command(String name, String description, String... aliases)
```

### 关键方法（真实签名照抄）
```java
protected static <T> RequiredArgumentBuilder<ClientSuggestionProvider, T> argument(final String name, final ArgumentType<T> type)
protected static LiteralArgumentBuilder<ClientSuggestionProvider> literal(final String name)

public final void registerTo(CommandDispatcher<ClientSuggestionProvider> dispatcher)
public void register(CommandDispatcher<ClientSuggestionProvider> dispatcher, String name)
public abstract void build(LiteralArgumentBuilder<ClientSuggestionProvider> builder)

public String getName()
public String getDescription()
public List<String> getAliases()
public String toString()

public void info(Component message)

```
- `build(builder)`：唯一必须实现的抽象方法，用于声明参数与执行逻辑。
- `info/warning/error`：带命令标题前缀的聊天反馈（内部走 `ChatUtils`，并 `forceNextPrefixClass(getClass())`）。

### addon 使用场景
继承 `Command`，实现 `build(...)`，然后 `Commands.add(new MyCommand())`，即可用 `.myname <args>` 调用。

## Command 真实子类示例

### SayCommand（消息类命令，源码照抄逻辑）

### 类名 / 包名
`meteordevelopment.meteorclient.commands.commands.SayCommand`
`meteordevelopment.meteorclient.commands.commands`

### 源码路径
`commands/commands/SayCommand.java`

```java
public class SayCommand extends Command {
    public SayCommand() {
        super("say", "Sends messages in chat.");
    }

    @Override
    public void build(LiteralArgumentBuilder<ClientSuggestionProvider> builder) {
        builder.then(argument("message", StringArgumentType.greedyString()).executes(context -> {
            String msg = context.getArgument("message", String.class);
            Script script = MeteorStarscript.compile(msg);
            if (script != null) {
                String message = MeteorStarscript.run(script);
                if (message != null) {
                    Instant instant = Instant.now();
                    long l = Crypt.SaltSupplier.getLong();
                    ClientPacketListener handler = mc.getConnection();
                    LastSeenMessagesTracker.Update lastSeenMessages = ((ClientPacketListenerAccessor) handler).meteor$getLastSeenMessages().generateAndApplyUpdate();
                    MessageSignature messageSignatureData = ((ClientPacketListenerAccessor) handler).meteor$getSignedMessageEncoder().pack(new SignedMessageBody(message, instant, l, lastSeenMessages.lastSeen()));
                    handler.send(new ServerboundChatPacket(message, instant, l, messageSignatureData, lastSeenMessages.update()));
                }
            }
            return SINGLE_SUCCESS;
        }));
    }
}
```
- 要点：消息用 `StringArgumentType.greedyString()` 捕获整段文本；向后端发送带签名的 `ServerboundChatPacket`；文本若含 `{...}` 会先经 `MeteorStarscript` 求值。

### DamageCommand（带别名 + 参数命令）

### 类名 / 包名
`meteordevelopment.meteorclient.commands.commands.DamageCommand`
`meteordevelopment.meteorclient.commands.commands`

### 源码路径
`commands/commands/DamageCommand.java`

```java
public class DamageCommand extends Command {
    public DamageCommand() {
        super("damage", "Damages self", "dmg");   // 别名 dmg
    }

    @Override
    public void build(LiteralArgumentBuilder<ClientSuggestionProvider> builder) {
        builder.then(argument("damage", IntegerArgumentType.integer(1, 7)).executes(context -> {
            int amount = IntegerArgumentType.getInteger(context, "damage");
            if (mc.player.getAbilities().invulnerable) throw new SimpleCommandExceptionType(Component.literal("You are invulnerable.")).create();
            damagePlayer(amount);
            return SINGLE_SUCCESS;
        }));
    }
    // damagePlayer(...) 内部抛 ServerboundMovePlayerPacket.Pos 实现自伤
}
```
- 要点：`IntegerArgumentType.integer(1, 7)` 限定范围；抛 `CommandSyntaxException` 返回错误提示。

## Commands（命令管理器）

### 类名
`meteordevelopment.meteorclient.commands.Commands`

### 包名
`meteordevelopment.meteorclient.commands`

### 源码路径
`commands/Commands.java`

### 关键字段
| 字段名 | 类型 | 中文用途 |
| --- | --- | --- |
| `COMMANDS` | `public static final List<Command>` | 全部已注册命令 |
| `DISPATCHER` | `public static CommandDispatcher<ClientSuggestionProvider>` | Brigadier 分发器 |

### 关键方法（真实签名照抄）
```java
public static void init()
public static void add(Command command)     // 同名覆盖式添加
public static void dispatch(String message) throws CommandSyntaxException
public static Command get(String name)
```
- `add`：`COMMANDS.removeIf(existing -> existing.getName().equals(command.getName()))` 后添加（同名会替换）。
- `dispatch(message)`：`DISPATCHER.execute(message, mc.getConnection().getSuggestionsProvider())`。
- `get(name)`：按名查找命令（不含别名）。
- Snake私有 `onJoin(GameJoinedEvent)`：每次进服重建 `Command.REGISTRY_ACCESS` 和 `DISPATCHER`（因为注册表参数按引用比较，跨服会失效）。

### addon 使用场景
- 添加命令：`Commands.add(new MyCommand())`。
- 程序化执行命令：`Commands.get("say")` 或直接构造消息后 `Commands.dispatch("say hi")`（需 catch `CommandSyntaxException`）。

## 命令使用方式

- 前缀来自 `Config.get().prefix`（`Setting<String>`，默认 `"."`）。
- 输入 `.say hello` 时，客户端发送 `ChatScreen` 预填前缀并解析。Meteor 监听 `KeyBinds.OPEN_COMMANDS`，点击后打开 `new ChatScreen(Config.get().prefix.get(), true)`。
- 命令名 + 参数：`.damage 4`；带别名：`.dmg 4` 等价。

## 常见坑
1. 别用旧版 `CommandArgumentType.*` 静态工厂，26.1.2 已删除，直接用 `argument("x", IntegerArgumentType.integer())`。
2. 命令的 `build` 里 `executes` 回调在主线程执行，别放耗时逻辑（要异步自己开线程）。
3. 所有命令必须由 `Commands.add(...)` 注册才会进入 `.help` 和分发器；仅 `new` 不注册无效。
4. 依赖注册表的参数类型（如 `ItemStackArgumentType`）需要正确的 `REGISTRY_ACCESS`，且跨服后由 `Commands` 自动重建，不要自行缓存。
5. 发聊天消息（像 `SayCommand`）在 1.21+ 需要带签名打包，否则可能被服务端拒绝；应从 `ClientPacketListenerAccessor` 取余 `LastSeenMessagesTracker` / `SignedMessageEncoder`。
