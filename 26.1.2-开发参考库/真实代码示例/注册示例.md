# 注册示例

## 概述

26.1.2 addon 的「注册」发生在四个层面，任何一层漏掉都会导致功能静默失效：

| 注册对象 | 位置 | API |
| --- | --- | --- |
| Addon 入口 | `fabric.mod.json → entrypoints.meteor` | 指向 `com.example.addon.core.AddonTemplate` |
| 模块分类 | `onRegisterCategories()` | `Modules.registerCategory(...)` |
| 模块 / 指令 / HUD / 服务 | `onInitialize()` | `Modules.get().add(...)` / `Commands.add(...)` / `Hud.get().register(...)` / `XxxService.register()` |
| Mixin | `addon-template.mixins.json → client` | 声明所有 `@Mixin` 类 |

Meteor addon 主入口必须继承 `meteordevelopment.meteorclient.addons.MeteorAddon`，覆写 `onInitialize()`、`onRegisterCategories()`、`getPackage()`。项目里这个类就是 `com.example.addon.core.AddonTemplate`。

---

## 示例 1：fabric.mod.json 入口声明

出处：`src/main/resources/fabric.mod.json`（第 15-22 行）

```json
{
  "environment": "client",
  "entrypoints": {
    "meteor": [
      "com.example.addon.core.AddonTemplate"
    ]
  },
  "mixins": [
    "addon-template.mixins.json"
  ],
  "depends": {
    "minecraft": "${minecraft_version}",
    "meteor-client": "*"
  }
}
```

要点：
- entrypoints 类型是 **`meteor`**（Meteor Client 的入口点），不是 `client`（Fabric 原版入口）；`client` 入口留给普通 Fabric mod 初始化。
- `mixins` 数组声明 mixin json 文件名，`depends.meteor-client` 保证加载顺序在 Meteor 之后。

## 示例 2：模块 / 指令 / HUD / 服务 / 自定义设置统一注册

出处：`src/main/java/com/example/addon/core/AddonTemplate.java`（第 62-189 行，节选关键注册行）

```java
import meteordevelopment.meteorclient.addons.MeteorAddon;
import meteordevelopment.meteorclient.commands.Commands;
import meteordevelopment.meteorclient.systems.hud.Hud;
import meteordevelopment.meteorclient.systems.hud.HudGroup;
import meteordevelopment.meteorclient.systems.modules.Category;
import meteordevelopment.meteorclient.systems.modules.Modules;

public class AddonTemplate extends MeteorAddon {
    public static final Logger LOG = LogUtils.getLogger();

    // 自建分类常量（图标用 DisplayItemUtils.toStack）
    public static final Category CATEGORY_AUTOMATION =
        new Category("§c§lyiyiaddon §e§l自动化", () -> DisplayItemUtils.toStack(Items.REDSTONE));
    public static final HudGroup HUD_GROUP = new HudGroup("示例");

    @Override
    public void onInitialize() {
        // ① 模块：Modules.get().add(...)
        Modules.get().add(new AutoBoneMeal());
        Modules.get().add(new FlightBypass());

        // 自定义设置控件：先注册 factory，再 add 使用它的模块
        EnchantmentSelectSetting.register();
        GearEnchantSetting.register();
        CustomEnchantSetting.register();
        Modules.get().add(new AutoEnchantBook());

        // ② 指令：Commands.add(...)
        Commands.add(new CommandExample());
        Commands.add(new WKCommand());

        // ③ 服务：static register()（内部 MeteorClient.EVENT_BUS.subscribe）
        YiyiaddonPasswordInterceptorService.register();
        YiyiaddonWelcomeService.register();
        YiyiaddonTelemetryService.register();

        // ④ HUD：Hud.get().register(HudElementInfo)
        Hud.get().register(HudExample.INFO);
    }

    @Override
    public void onRegisterCategories() {
        Modules.registerCategory(CATEGORY);
        Modules.registerCategory(CATEGORY_AUTOMATION);
    }

    @Override
    public String getPackage() {
        return "com.example.addon";
    }
}
```

要点：
- **模块**：`new XxxModule()` 后 `Modules.get().add(...)`；要开机即开的模块额外 `.enable()`（如翻译模块、用户统计）。
- **指令**：`Commands.get().add(new XxxCommand())`（用 `Commands.add` 静态便捷方法亦可）。
- **HUD**：`Hud.get().register(HudElementInfo.INFO)`，`HUD_GROUP` 是自建分组。
- **服务**：无实例、无全局单例，`public static void register()` 内部 `MeteorClient.EVENT_BUS.subscribe(XxxService.class)`（见示例 4）。
- **自定义设置控件**：先 `XxxSetting.register()`（内部 `SettingsWidgetFactory.registerCustomFactory`），相关模块类才能用。

## 示例 3：HUD 元素注册（HudElementInfo 静态字段）

出处：`src/main/java/com/example/addon/hud/HudExample.java`（第 14-33 行）

```java
import com.example.addon.core.AddonTemplate;
import meteordevelopment.meteorclient.systems.hud.HudElement;
import meteordevelopment.meteorclient.systems.hud.HudElementInfo;
import meteordevelopment.meteorclient.systems.hud.HudRenderer;

public class HudExample extends HudElement {

    public static final HudElementInfo<HudExample> INFO = new HudElementInfo<>(
        AddonTemplate.HUD_GROUP,
        "example",
        "HUD element example.",
        HudExample::new
    );

    public HudExample() {
        super(INFO);
    }

    @Override
    public void render(HudRenderer renderer) {
        setSize(renderer.textWidth("Example element", true), renderer.textHeight(true));
        renderer.quad(x, y, getWidth(), getHeight(), Color.LIGHT_GRAY);
        renderer.text("Example element", x, y, Color.WHITE, true);
    }
}
```

要点：
- `HudElementInfo` 四个参数：分组、名字（kebab-case）、描述、工厂方法引用 `Xxx::new`。
- 注册时传的是**静态 `INFO` 字段**，不是 new 出来的实例；构造函数 `super(INFO)` 绑定。

## 示例 4：服务注册模式（static register + 事件总线订阅）

出处：`src/main/java/com/example/addon/utils/YiyiaddonWelcomeService.java`（第 57-59 行）

```java
import meteordevelopment.meteorclient.MeteorClient;

public static void register() {
    MeteorClient.EVENT_BUS.subscribe(YiyiaddonWelcomeService.class);
}
```

要点：
- 服务类只有 static 方法 + `@EventHandler` static 方法，通过 `MeteorClient.EVENT_BUS.subscribe(XxxService.class)` 订阅整个类的静态事件。
- 与模块不同，服务**不继承 Module**、不注册到 `Modules`，只在 `AddonTemplate.onInitialize()` 里调 `XxxService.register()` 一次。

## 示例 5：Mixin 注册（mixins.json client 数组）

出处：`src/main/resources/addon-template.mixins.json`（第 1-48 行，节选）

```json
{
  "required": true,
  "package": "com.example.addon.mixin",
  "compatibilityLevel": "JAVA_25",
  "client": [
    "ExampleMixin",
    "ClientLevelPredictionAccessor",
    "ServerboundMovePlayerPacketAccessor",
    "LocalPlayerAccessor",
    "MultiPlayerGameModeFastBreakMixin"
  ],
  "injectors": {
    "defaultRequire": 1
  }
}
```

要点：
- `package` 是 mixin 类的包名；`client` 数组里写**类名**（不含包名）。
- 每个 `@Mixin` 类都要在 `client` 数组占一行，漏掉该 Mixin 彻底不加载。
- `fabric.mod.json` 的 `mixins` 数组引用这个 json 文件名（`addon-template.mixins.json`）。

## 模式要点

1. **注册顺序**：`onRegisterCategories()` 先执行（注册分类）→ 再 `onInitialize()`（注册模块/指令/HUD/服务）。
2. **模块 = `Modules.get().add(new X())`**：内部会自动订阅事件（`autoSubscribe=true`），不需要手动 subscribe。
3. **服务 = `XxxService.register()`**：内部 `MeteorClient.EVENT_BUS.subscribe(XxxService.class)`，服务自己管理订阅。
4. **自定义 Setting = `XxxSetting.register()`**：内部 `SettingsWidgetFactory.registerCustomFactory(...)`，必须在任何使用它的模块实例化之前调用。
5. **HUD = `Hud.get().register(HudElement.INFO)`**：传静态 `HudElementInfo` 字段。
6. **Mixin = mixins.json client 数组**：独立于 Java 代码的一条注册，最容易漏。

## 常见坑

- **入口写 `entrypoints.client` 而不是 `meteor`**：Meteor addon 必须挂在 `meteor` 入口，写 `client` 则 Meteor 不加载这个 addon。
- **自定义设置控件没先 `register()`**：`Modules.get().add` 之前没调 `XxxSetting.register()`，运行时会报「no factory registered for XxxSetting」导致打开配置页崩溃。
- **服务忘了 `register()` 调用**：写了 `XxxService.register()` 类方法，但不在 `AddonTemplate.onInitialize()` 里调用，服务永远不会订阅事件。
- **Mixin 没进 `client` 数组**：只创建 `.java` 文件、没加进 `addon-template.mixins.json`，功能静默失效无报错。
- **HUD 传了 `new HudExample()` 而非 `.INFO`**：注册要用 `HudElementInfo`，直接 new 实例会被丢掉。

## 26.1.2 注意

- **`MeteorAddon.getPackage()`**：返回 addon 包名（`com.example.addon`），Meteor 用它在运行时定位资源/翻译文件，改包名时要同步改这个返回值。
- **`GithubRepo`**：`getRepo()` 返回 GitHub 仓库信息用于更新检查；不涉及更新可返回任意仓库，但不能省略覆写。
- **`DisplayItemUtils.toStack(Items.X)`**：分类图标必须用它把 `Item` 转成 `ItemStack` 显示（26.1.2 新增工具），不能直接传 `Item`。
- **`Modules.registerCategory` 是静态方法**（26.1.2 用 `Modules.registerCategory(Category)`），不是旧版 `Categories.add(...)`。
- **服务订阅用 `MeteorClient.EVENT_BUS.subscribe(Class)`**：不接受实例、订阅整个类的 static handler，与模块的 `EVENT_BUS.subscribe(this)`（实例）区分开。
