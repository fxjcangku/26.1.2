# 物品栏机制

> 源码依据：Minecraft原始源码/net/minecraft/world/entity/player/Inventory.java 与 net/minecraft/world/item/ItemStack.java 26.1.2 Mojang官方映射

本文讲「玩家物品栏（`Inventory`）的槽位体系、`ItemStack` 的堆叠/合并规则、以及 addon 怎么读/改背包」。核心结论：**`Inventory` 有 36 格 `NonNullList<ItemStack>`（0~35：快捷栏 0~8 + 主区 9~35），装备/副手经 `EQUIPMENT_SLOT_MAPPING` 折算到 36~42；`ItemStack` 是不可变值语义（组件体系），合并不看引用而看 `isSameItemSameComponents + isStackable + 数量上限`**。跨容器点击/同步另见《容器同步机制》。

---

## 一、槽位体系（`Inventory` 常量，源码真实值）

### 槽位映射表
| 区间 | 槽号 | 含义 |
|------|------|------|
| 快捷栏 | `0~8` | `selected` 选中下标（`getSelectedSlot()`） |
| 背包主区 | `9~35` | 27 格 |
| 装备槽 | `36=FEET 37=LEGS 38=CHEST 39=HEAD` | 经 `EQUIPMENT_SLOT_MAPPING`（源码 37 行）折到 `EntityEquipment` |
| 副手/body/鞍 | `40/41/42` | `OFFHAND/BODY/SADDLE` |

```java
// 关键方法（源码真实签名）

public void setSelectedSlot(int selected);          // 71 行，越界抛 IllegalArgumentException

```

- 存储本体：`private final NonNullList<ItemStack> items = NonNullList.withSize(36, ItemStack.EMPTY);`（源码 56 行）。
- 槽里永远是 `ItemStack.EMPTY` 而非 null（空槽判断 `isEmpty()`，不要 `== null`）。

## 三、`ItemStack` 值语义与合并规则

`ItemStack`（`net/minecraft/world/item/ItemStack`，`final class`，实现 `DataComponentHolder`）：
- 数据全部走组件体系（`DataComponents`），26.1.2 没有 `getNbt/getOrCreateNbt`。
- 修改返回新实例：`stack.set(type, value)` 返回的是旧值，拿新物品要自己持有 `stack`。

### 合并判定（`Inventory.hasRemainingSpaceForItem`，源码 95 行）
```java
return !slotItemStack.isEmpty()
    && ItemStack.isSameItemSameComponents(slotItemStack, newItemStack)  // 同类型+同组件
    && slotItemStack.isStackable()                                      // 可堆叠
    && slotItemStack.getCount() < this.getMaxStackSize(slotItemStack);  // 未满
```

关键子判定（`ItemStack` 源码）：
```java
// isStackable  413 行
public boolean isStackable() {
    return this.getMaxStackSize() > 1 && (!this.isDamageableItem() || !this.isDamaged());
}
// isSameItemSameComponents  636 行
public static boolean isSameItemSameComponents(ItemStack a, ItemStack b) {
    if (!a.is(b.getItem())) return false;
    else return a.isEmpty() && b.isEmpty() ? true : Objects.equals(a.components, b.components);
}
```
- **合并铁律**：类型相同（`is(Item)`）+ 组件完全相同（`DataComponentMap.equals`）+ 可堆叠（无耐久或未损耗）+ 未到上限，四条同时满足才合并。有耐久或组件不同的（附魔、自定义名、CustomData）不能合并。

### 放入逻辑（`Inventory.add`）
```java
public boolean add(ItemStack stack);          // 249 行 → add(-1, stack)
public boolean add(int slot, ItemStack stack); // 253 行
```
- 受损物品（`isDamaged()`）：`slot==-1` 找空槽，无空槽且创造（`hasInfiniteMaterials`）则丢弃，否则失败。
- 未受损：循环调 `addResource`（先并进「同物未满槽」，再放空槽），直到放完或放不动；返回是否「放入了部分/全部」。
- `placeItemBackInInventory`（306 行）：关容器/回退物品用，逐格 `split` + `add`。

## 五、客户端背包操作与同步的边界

- 客户端本地读：`mc.player.getInventory().getItem(i)` / `getSelectedSlot()` 直接读内存，无延迟。
- 客户端改背包**不合法**：本地 `setItem/inventory` 只改内存视觉，服务端权威在 `ClientboundSetPlayerInventoryPacket`（`handleSetPlayerInventory`，源码 1449 行）下发时覆盖。
- 合法操作（移动物品、丢出、切换手持）走包：
  - `mc.player.drop(boolean)` → `ServerboundPlayerActionPacket`（`DROP_ITEM/DROP_ALL_ITEMS`）。
  - 切换槽 → `ServerboundSetCarriedItemPacket`。
  - 容器内点击/转移 → `ServerboundContainerClickPacket`（见《容器同步机制》）。

## addon 介入点

1. **读背包**：`mc.player.getInventory().getItem(slot)`、`getSelectedItem()`、遍历 `0~35` + 装备 `36~39`。
2. **查找物品**：`findSlotMatchingItem(stack)`、`getFreeSlot()`、按 `Predicate<ItemStack>` 手写扫描。
3. **丢弃**：`mc.player.drop(true/false)`（走合法发包）。
4. **预测性改背包**（仅视觉/单机）慎用，联网会被服务端纠正。
5. **拦截背包同步**：Mixin `ClientPacketListener.handleSetPlayerInventory` / `handleContainerSetSlot` 监听背包变化（做自动补货/物品追踪）。
6. **Mixin 破坏/合成预测**：Meteor 常用 `Inventory.add` 相关 Mixin 做「自动整理/自动补货」本地逻辑。

## 常见坑

1. **空槽是 `ItemStack.EMPTY` 不是 null**：`stack.isEmpty()` 判断（`== EMPTY || count<=0`），别 `stack == null`。
2. **`ItemStack.set` 返回旧值**：别「读返回值当新物品」；改完必须 `stack = stack.set(...)`。
3. **合并要件四缺一不可**：附魔/自定义名/RepairCost 任一组件不同即 `isSameItemSameComponents=false`，不会并堆，自动捡取的物品会「看似同物却不堆叠」。
4. **槽号两套别混**：`player.getInventory().getItem(0..8)` 是快捷栏；`menu.slots` 的 0 可能是容器格而非快捷栏。跨容器转移用 `Slot.safeInsert/safeTake` 或 `menu.clicked(...)`。
5. **受损物品不堆叠**：`isStackable` 对已损耗（`isDamaged`）工具返回 false，自动合并要单独走「修理/新工具」逻辑。
6. **客户端改背包不合法**：本地 `setItem` 只改显示，服务端下次同步会覆盖；真要移动物品走 `ServerboundContainerClickPacket`。
