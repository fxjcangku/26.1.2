# 容器同步机制

> 源码依据：Minecraft原始源码/net/minecraft/world/inventory/ 与 net/minecraft/client/multiplayer/ClientPacketListener.java 及 net/minecraft/network/protocol/game/ 26.1.2 Mojang官方映射

本文讲「客户端菜单（`AbstractContainerMenu`/`InventoryMenu`）与服务端容器如何双向同步」。核心结论：**容器内容由服务端权威，客户端通过 `ClientboundContainerSetContentPacket`（全量）/ `ClientboundContainerSetSlotPacket`（单格）/ `ClientboundContainerSetDataPacket`（进度）同步；客户端操作通过 `ServerboundContainerClickPacket` 上报，`InventoryMenu` 的 `containerId == 0` 是玩家背包菜单特殊 id**。addon 模拟「打开容器、点击、转移物品」走 `menu.clicked(...)`，监听变化走 `ContainerSync` 相关收包拦截。

---

## 一、两个核心对象

### `AbstractContainerMenu`（net/minecraft/world/inventory/AbstractContainerMenu）
- 玩家敞开界面时的「菜单状态」在 `player.containerMenu`。
- `public final NonNullList<Slot> slots`：菜单内所有插槽（含玩家背包追加槽）。
- 常量：`SLOT_CLICKED_OUTSIDE = -999`、`CARRIED_SLOT_SIZE = Integer.MAX_VALUE`。
- 关键方法（源码真实签名）：
```java
public void clicked(int slotIndex, int buttonNum, ContainerInput containerInput, Player player); // 322 行，点击分发
public void initializeContents(int stateId, List<ItemStack> items, ItemStack carried);            // 631 行，全量初始化
public void setItem(int slot, int stateId, ItemStack itemStack);                                   // 626 行，单格设置
public void setCarried(ItemStack carried);                                                         // 777 行，光标携带物
public void broadcastChanges();                                                                    // 198 行，测变并同步远端
```

### `InventoryMenu`（玩家背包菜单）
- `AbstractContainerMenu` 子类，`containerId == 0`（源码 `createInventorySlotDefinitions` 相关）。
- 收包时 `packet.getContainerId() == 0` → 落在 `player.inventoryMenu`（见下）。

## 二、容器同步三组包（S→C）

### 1. 全量：`ClientboundContainerSetContentPacket` → `handleContainerContent`
```java
// ClientPacketListener  源码 1456 行
public void handleContainerContent(final ClientboundContainerSetContentPacket packet) {
    Player player = this.minecraft.player;
    if (packet.containerId() == 0) {
        player.inventoryMenu.initializeContents(packet.stateId(), packet.items(), packet.carriedItem());
    } else if (packet.containerId() == player.containerMenu.containerId) {
        player.containerMenu.initializeContents(packet.stateId(), packet.items(), packet.carriedItem());
    }
}
```
- `stateId`（同步序号）用于客户端对账乱序/过期更新。

### 2. 单格：`ClientboundContainerSetSlotPacket` → `handleContainerSetSlot`
```java
// ClientPacketListener  源码 1407 行
Player player = this.minecraft.player;
ItemStack itemStack = packet.getItem();
int slot = packet.getSlot();
this.minecraft.getTutorial().onGetItem(itemStack);
boolean creative = (this.minecraft.screen instanceof CreativeModeInventoryScreen s && !s.isInventoryOpen());
if (packet.getContainerId() == 0) {
    if (InventoryMenu.isHotbarSlot(slot) && !itemStack.isEmpty()) {
        // 快捷栏新物品 → setPopTime(5) 弹出动画
    }
    player.inventoryMenu.setItem(slot, packet.getStateId(), itemStack);
} else if (packet.getContainerId() == player.containerMenu.containerId && (packet.getContainerId() != 0 || !creative)) {
    player.containerMenu.setItem(slot, packet.getStateId(), itemStack);
}
```

### 3. 进度：`ClientboundContainerSetDataPacket` → `handleContainerData`
- 同步 `DataSlot` 值（如附魔消耗、熔炉燃烧/熔炼进度、铁砧 `cost`），客户端经 `menu` 的 `dataSlots` 读。

### 4. 光标/玩家背包
- `handleSetCursorItem`（源码 1440 行）→ `player.containerMenu.setCarried(packet.contents())`。
- `handleSetPlayerInventory`（源码 1449 行）→ `player.getInventory().setItem(packet.slot(), packet.contents())`。

## 三、客户端操作上报（`ServerboundContainerClickPacket`）

```java
// ServerboundContainerClickPacket  源码 14 行（record）
public record ServerboundContainerClickPacket(
    int containerId, int stateId, short slotNum, byte buttonNum,
    ContainerInput containerInput, Int2ObjectMap<HashedStack> changedSlots, HashedStack carriedItem
) implements Packet<ServerGamePacketListener>;
```

- 26.1.2 **点击语义参数从旧 `SlotActionType` 改名为枚举 `ContainerInput`**（`net/minecraft/world/inventory/ContainerInput`）：
  `PICKUP(0)`、`QUICK_MOVE(1)`、`SWAP(2)`、`CLONE(3)`、`THROW(4)`、`QUICK_CRAFT(5)`、`PICKUP_ALL(6)`。

### 客户端发起点击的入口
`ClientsideMenu / AbstractContainerMenu.clicked(...)`（源码 322 行）在客户端组装 `ServerboundContainerClickPacket` 并 `send`。实际生产调用点：
- 玩家手动点槽 → GUI 事件 → `gameMode` / `Minecraft` 侧菜单点击逻辑 → `menu.clicked(slotIndex, buttonNum, containerInput, player)`。
- addon 模拟：拿到 `mc.player.containerMenu`，直接调 `menu.clicked(...)`（注意 slot 是**菜单内 index**，不是玩家背包槽号）。

## 四、全程链路速记

```text
[打开容器] ClientboundOpenScreenPacket → ClientPacketListener.handleOpenScreen → new 对应 AbstractContainerMenu
[全量同步] ClientboundContainerSetContentPacket → handleContainerContent → menu.initializeContents(stateId, items, carried)
[单格变化] ClientboundContainerSetSlotPacket → handleContainerSetSlot → menu.setItem(slot, stateId, item)
[进度数据] ClientboundContainerSetDataPacket → handleContainerData → menu 的 DataSlot 更新
[玩家操作] menu.clicked(slotIndex, button, ContainerInput, player) → ServerboundContainerClickPacket → 服务端结算
[关闭容器] LocalPlayer.closeContainer → ServerboundContainerClosePacket + clientSideCloseContainer
```

## addon 介入点

1. **读容器内容**：`mc.player.containerMenu.getSlot(i).getItem()`（混用 `slots` 遍历）或 `mc.player.getInventory().getItem(...)`。
2. **模拟点击**：`mc.player.containerMenu.clicked(slotIndex, buttonNum, ContainerInput.PICKUP, mc.player)`（注意在主线程、`containerMenu.containerId` 正确）。
3. **快捷转移**：`AbstractContainerMenu.getSlot(i).safeInsert/safeTake(...)`（本地菜单语义）+ 同步需走点击。
4. **监听容器变化**：Mixin/订阅 `ClientboundContainerSetContentPacket`、`ClientboundContainerSetSlotPacket`（`ContainerSync` 概念），或 Meteor 相关事件。
5. **拦截物品**：Mixin `handleContainerSetSlot` 的 TAIL 拿 `packet.getItem()` 判断捡到什么（自动拾取/物品追踪/附魔机核心）。

## 常见坑

1. **`containerId == 0` 是玩家背包**：收包分支里 0 走 `inventoryMenu`，非 0 走当前 `containerMenu`；addon 手写判断时别漏 `containerId != 0 || !creative` 的反向条件。
2. **菜单槽号 ≠ 玩家背包槽号**：`menu.slots` 下标是菜单内部序（合成格 0~N、玩家区在后），与 `player.getInventory().getItem(0..8)` 完全不同；真实转移用 `Slot.safeInsert/safeTake` 或 `menu.clicked(...)`。
3. **`clicked` 参数是 `ContainerInput` 不是旧 enum**：26.1.2 旧 `SlotActionType` 已不存在，写 `quick-move` 用 `ContainerInput.QUICK_MOVE`。
4. **`stateId` 对账**：乱序/过期包靠 `stateId` 丢弃，`initializeContents` 会校验；addon 拦截后手动 `setItem` 用错 stateId 会越同步越乱。
5. **点击在主线程**：`menu.clicked` 内部发包 + 访问 GUI 状态，别在渲染线程之外调用。
6. **`carriedItem`（光标物）**：拿起物品后物品在 `menu.carried` 而非槽里，关容器时 `removed(player)` 会丢回；addon 移动物品要把光标物纳入考虑。
