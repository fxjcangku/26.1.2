# 附魔机制

> 源码依据：Minecraft原始源码/net/minecraft/world/item/enchantment/ 与 net/minecraft/world/inventory/EnchantmentMenu.java 及 net/minecraft/world/inventory/AnvilMenu.java 26.1.2 Mojang官方映射

本文讲「附魔从数据驱动结构、附魔台随机与消耗、到铁砧合成」的完整运行逻辑。核心结论：**26.1.2 附魔是数据驱动 `record Enchantment`（JSON 加载，互斥/效果全部数据化）；附魔台在 `EnchantmentMenu.slotsChanged/clickMenuButton` 用 `enchantmentSeed` 定点随机出 3 个消耗与线索，`EnchantmentHelper.selectEnchantment` 选附魔，应用走 `ItemStack.enchant`；铁砧在 `AnvilMenu.createResult` 按「材料修理 / 同物品合并 / 附魔书合并 / 互斥 / 经验消耗」逐条计算，超 39 级「太贵」；附魔读写以 `ItemEnchantments` + `DataComponents.ENCHANTMENTS` 组件为核心**。

---

## 一、数据驱动结构（`Enchantment` record）

```java
// net/minecraft/world/item/enchantment/Enchantment.java
public record Enchantment(
    Component description,
    Enchantment.EnchantmentDefinition definition,      // 支持物品/权重/最大等级/消耗/槽位
    HolderSet<Enchantment> exclusiveSet,                 // 互斥集合（运行时读，不硬编码）
    DataComponentMap effects                              // 效果全部数据化
) {
    public int getMaxLevel();       // definition.maxLevel()
    public int getMinCost(int level);
    public int getMaxCost(int level);
    public int getAnvilCost();      // 铁砧单本消耗
    public int getWeight();
    public boolean canEnchant(ItemStack stack);
    public static boolean areCompatible(Holder<Enchantment> a, Holder<Enchantment> b); // 双向查 exclusiveSet
}

public record EnchantmentDefinition(HolderSet<Item> supportedItems, Optional<HolderSet<Item>> primaryItems,
    int weight, int maxLevel, Enchantment.Cost minCost, Enchantment.Cost maxCost, int anvilCost, List<EquipmentSlotGroup> slots);
public record Cost(int base, int perLevelAboveFirst) { public int calculate(int level); } // base + per*(level-1)
```

- 互斥不再硬编码：`Enchantment.areCompatible(a, b)` 同时查双向 `exclusiveSet`（锋利/亡灵杀手等）。
- 旧 API（`getSlot/isTreasureOnly/getRarity`）已消失，进 `definition` 或 tag（`TREASURE`/`CURSE`）。
- `Enchantments`（`net/minecraft/world/item/enchantment/Enchantments`）里是 `ResourceKey<Enchantment>`，不是 `Holder`；判身份用 `holder.is(Enchantments.SHARPNESS)`。

## 二、附魔读写（`ItemEnchantments` 组件）

```java
// 读
ItemEnchantments enc = stack.getEnchantments();               // == get(DataComponents.ENCHANTMENTS)，可能是 null
int level = enc == null ? 0 : enc.getLevel(holder);           // getLevel 无则 0

// 写（不可变 → Mutable）
ItemEnchantments.Mutable m = new ItemEnchantments.Mutable(stack.getEnchantments());
m.set(holder, level);                                          // level<=0 删除
m.upgrade(holder, level);                                      // 取 max
stack = stack.set(DataComponents.ENCHANTMENTS, m.toImmutable());
```

- `ItemEnchantments`（`net/minecraft/world/item/enchantment/ItemEnchantments`）：不可变「附魔→等级」映射，等级 1~255。
- 附魔书存 `DataComponents.STORED_ENCHANTMENTS`（同类型 `ItemEnchantments`），物品上附魔存 `ENCHANTMENTS`。

### 应用（`clickMenuButton`，源码 148 行）
```java
if (buttonId 合法 && 青金石充足 && cost>0 && 经验足够) {
    // getEnchantmentList(registryAccess, itemStack, buttonId, cost) → selectEnchantment
    player.onEnchantmentPerformed(itemStack, enchantmentCost);   // 扣经验
    if (itemStack.is(Items.BOOK)) enchantmentItem = itemStack.transmuteCopy(Items.ENCHANTED_BOOK); // 空白书→附魔书
    for (EnchantmentInstance enchantment : newEnchantment) {
        enchantmentItem.enchant(enchantment.enchantment(), enchantment.level());  // 真正附上去
    }
    currency.consume(enchantmentCost, player);                    // 扣青金石
    this.enchantmentSeed.set(player.getEnchantmentSeed());        // 刷新种子
    this.slotsChanged(this.enchantSlots);                         // 重算
}
```

要点：
- **种子**：`enchantmentSeed` 来自 `player.getEnchantmentSeed()`，随机用 `random.setSeed(seed + slot)` 定点，保证三格附魔可复现（这是「附魔机读线索」的关键）。
- **候选**：`getEnchantmentList` 取 `EnchantmentTags.IN_ENCHANTING_TABLE` tag 内的附魔流，`selectEnchantment` 从中按权重选。
- 空白书附魔若 `list.size() > 1` 会随机去掉一个（源码 205-207 行，书最多少一个结果）。

## 四、铁砧合成（`AnvilMenu.createResult`，源码 119 行）

铁砧是「装备 + 附魔书/材料/同物品」三步合成，`createResult` 每次 `slotsChanged`/改名时重算。核心分支：

### 2. 同物品合并（`!usingBook && isDamageableItem`）

### 3. 附魔合并（核心，源码 174-215 行）
```java
ItemEnchantments additionalEnchantments = EnchantmentHelper.getEnchantmentsForCrafting(addition);
for (Entry<Holder<Enchantment>> entry : additionalEnchantments.entrySet()) {
    int current = enchantments.getLevel(holder);
    int level = entry.getIntValue();

        if (usingBook) fee = Math.max(1, fee / 2);                                 // 附魔书半价
        price += fee * level;
        if (input.getCount() > 1) price = 40;
```

## addon 介入点（自动附魔核心）

1. **读装备现有附魔**：`stack.getEnchantments()`，`getLevel(holder)`，遍历 `keySet()`。
2. **读附魔台线索/消耗**：打开 `EnchantmentMenu` 后读 `costs[]`、`enchantClue[]`、`levelClue[]`（`dataSlots` 经 `menu` 同步，容器同步机制）。种子 `getEnchantmentSeed()` 可复现随机。
3. **改附魔**：`ItemEnchantments.Mutable` + `stack.set(DataComponents.ENCHANTMENTS, ...)`（本地预测，服务端需合法操作）。
4. **铁砧成本预测**：复算 `getAnvilCost()`、`areCompatible`、`calculateIncreasedRepairCost`、`DataComponents.REPAIR_COST`，实现「AnvilPlanner 最优合并规划」。
5. **判互斥**：`Enchantment.areCompatible(a, b)`，别背表。
6. **拦截合成结果**：Mixin/instrument `AnvilMenu.createResult` 读 `resultSlots.getItem(0)` + `cost.get()`，提前知道合出什么、消耗多少经验。
7. **合法应用附魔**：附魔台实际附魔走 `clickMenuButton`（服务端结算）；addon 模拟点击而非本地 `ItemStack.enchant`（本地改只改视觉，服务端会覆盖）。

## 常见坑

1. **`Enchantments.XXX` 是 `ResourceKey` 不是 `Holder`**：`getLevel(Enchantments.SHARPNESS)` 会编译失败，要先拿 `Holder`（从 `keySet()` 或 registryAccess lookup）。
2. **`getEnchantments()` 可能返回 null**：物品无 `ENCHANTMENTS` 组件时 `stack.get(...)` 是 null（不是 `EMPTY`）；判空用 `stack.has(DataComponents.ENCHANTMENTS)` 或 `getOrDefault(..., ItemEnchantments.EMPTY)`。
3. **互斥用 `areCompatible`**：`Enchantment.areCompatible(a, b)` 双向查 `exclusiveSet`；自己写 `a!=b` 会漏互斥对。
4. **铁砧「太贵」阈值 39**：`cost >= 40 && !creative` 直接空结果，附魔机要控制 `REPAIR_COST` 与合成次数（每次合成 `REPAIR_COST = max(...)*2+1` 增长）。
5. **`EnchantmentHelper` 大量方法是服务端语义**：`getDamageProtection`（收 `ServerLevel`）等客户端只是预测展示，别当权威。
6. **本地 `ItemStack.enchant` 只改视觉**：客户端上物品附魔由服务端结算，真正附魔要走附魔台 `clickMenuButton` 或依赖服务端；本地改会被 `ClientboundContainerSetSlotPacket` 覆盖。
7. **种子可复现但会变**：`enchantmentSeed` 来自 `player.getEnchantmentSeed()`（按位置/次数变化），一次 `setSeed(seed + slot)` 决定该次三格结果，读完线索即可预测，但下次操作种子已刷新。
