# 实体机制

> 源码依据：Minecraft原始源码/net/minecraft/world/entity/Entity.java 与 net/minecraft/client/multiplayer/ClientLevel.java 及 net/minecraft/client/multiplayer/ClientPacketListener.java 26.1.2 Mojang官方映射

本文讲「客户端世界里一个实体（含本地玩家、其它玩家、生物）怎么被创建、怎么 tick、怎么移除」。核心结论：**实体生命周期由 `ClientLevel` 的实体表统一驱动（`tickEntities → tickNonPassenger → entity.tick → baseTick`），服务端通过 `ClientboundAddEntityPacket` 创建、`ClientboundRemoveEntitiesPacket` 移除、`ClientboundSetEntityDataPacket` 同步元数据，移除标记用 `Entity.RemovalReason`**。addon 遍历/筛选实体都围绕这套 tick 与移除语义展开。

---

## 一、实体表与客户端 tick 驱动

### 归属
- `ClientLevel`（`net/minecraft/client/multiplayer/ClientLevel`）持有实体存储（`entityStorage`，经 `getEntities()` 访问）。
- `Minecraft.tick()`（源码 1798 行）在「非暂停」时调用：

```java
// Minecraft.tick()
this.level.tickEntities();         // 1867 行
this.level.tickBlockEntities();    // 1869 行
// ...
this.level.tick(() -> true);       // 1892 行，世界级 tick（区块/时间/边界）
```

### `ClientLevel.tickEntities` → `tickNonPassenger`
```java
// ClientLevel  源码 383 行（tickEntities） / 352 行（tickNonPassenger）
public void tickEntities() {
    this.tickingEntities.forEach(entity -> {
        if (!entity.isRemoved() && !entity.isPassenger() && !this.tickRateManager.isEntityFrozen(entity)) {
            this.guardEntityTick(this::tickNonPassenger, entity);
        }
    });
}

public void tickNonPassenger(final Entity entity) {
    entity.setOldPosAndRot();                       // 缓存上一 tick 位置/朝向（渲染插值用）
    entity.tickCount++;                             // 存在 tick 计数
    Profiler.get().push(entity.typeHolder()::getRegisteredName);
    entity.tick();                                  // 核心：实体自身逻辑
    Profiler.get().pop();
}
```

要点：
- **骑乘实体不单独 tick**（`isPassenger()` 跳过，由载具 tick 牵引）。
- `tickRateManager.isEntityFrozen(entity)` 的实体冻结（在 tick 率管理下不推进）。
- `setOldPosAndRot()` 维护 `xo/yo/zo` 旧位置，是渲染平滑 `getKnownMovement()` 的数据来源。

## 二、`Entity.tick` 与 `baseTick`（双段结构）

```java
// Entity  源码 505 行
public void tick() { this.baseTick(); }   // 基类只做公共基础；子类（LivingEntity/Mob）覆写叠加更多

// Entity.baseTick()  源码 509 行（节选）
public void baseTick() {
    this.computeSpeed();                 // 更新已知速度
    this.inBlockState = null;
    if (this.isPassenger() && this.getVehicle().isRemoved()) this.stopRiding(); // 载具没了→下马
    if (this.boardingCooldown > 0) this.boardingCooldown--;
    this.handlePortal();                 // 传送门交互
    this.updateFluidInteraction();       // 流体/水判定
    this.updateSwimming();               // 游泳姿态
    // ... 火焰 tick（服务端 ServerLevel 分支）、骑乘位置夹逼等
}
```

子类层次（客户端 addon 拦截常用）：
- `LivingEntity.tick()`：先 `super.tick()`（含 baseTick），再处理 `hurtDuration/attackStrengthTicker`、`aiStep()` 等。
- `Mob.tick()`：再叠 AI/寻路/target。
- `LocalPlayer.tick()`：见《玩家移动机制》，额外做发包与输入。

## 三、实体创建（服务端驱动）

`ClientPacketListener.handleAddEntity(ClientboundAddEntityPacket)`（源码 575 行）：

```java
Entity entity = this.createEntityFromPacket(packet);
if (entity != null) {
    entity.recreateFromPacket(packet);
    this.level.addEntity(entity);
    this.postAddEntitySoundInstance(entity);   // 矿车/蜜蜂等特殊音效
}
```

`createEntityFromPacket`（源码 600 行）：
- `type == EntityType.PLAYER` → `new RemotePlayer(this.level, playerInfo.getProfile())`（先查 `playerInfoMap`，查不到就 warn 跳过）。
- 其它 → `type.create(this.level, EntitySpawnReason.LOAD)`。

`ClientLevel.addEntity`（源码 415 行）：
```java
public void addEntity(final Entity entity) {
    this.removeEntity(entity.getId(), Entity.RemovalReason.DISCARDED); // 先清同 id（防残留）
    this.entityStorage.addEntity(entity);
}
```

## 四、实体移除（`RemovalReason`）

`ClientPacketListener.handleRemoveEntities(ClientboundRemoveEntitiesPacket)`（源码 787 行）对每个 id 调 `this.level.removeEntity(id, ...)`。

```java
// ClientLevel.removeEntity  源码 420 行
public void removeEntity(final int id, final Entity.RemovalReason reason) {
    Entity entity = this.getEntities().get(id);
    if (entity != null) { entity.setRemoved(reason); entity.onClientRemoval(); }
}

// Entity.setRemoved  源码 3855 行
public final void setRemoved(final Entity.RemovalReason reason) {
    if (this.removalReason == null) this.removalReason = reason; // 只设一次
    if (this.removalReason.shouldDestroy()) this.stopRiding();    // destroy 型→下马
    this.getPassengers().forEach(Entity::stopRiding);             // 乘客全部下马
    this.levelCallback.onRemove(reason);                          // 回调（世界侧清理）
    this.onRemoval(reason);                                       // 子类钩子
}
```

`RemovalReason`（源码 4076 行）：`KILLED`、`DISCARDED`、`UNLOADED_TO_CHUNK`、`UNLOADED_WITH_PLAYER`、`CHANGED_DIMENSION`，各自带 `destroy`（是否停止骑乘/销毁关联）与 `save`（是否存档）两个语义位。

- **判活**：`isRemoved()`（源码 3845 行）= `removalReason != null`；`LivingEntity.isAlive()` 再加 `getHealth() > 0`。
- Yarn 旧名 `discard()` 已不存在，等价 `remove(Entity.RemovalReason.DISCARDED)`。

## 五、元数据与数据同步

- 实体数据（entityData / DataWatcher）：`ClientboundSetEntityDataPacket` → `ClientPacketListener.handleSetEntityData`（源码 641 行）按 id 更新。
- 移动同步：`ClientboundMoveEntityPacket` / `ClientboundTeleportEntityPacket`（`handleTeleportEntity` 源码 677 行）→ 远端实体插值/落位。
- addon 读实体状态用 `entity.getEntityData()` / `entity.hasPose(Pose)` / `entity.getDeltaMovement()` 等，改远端实体客户端表现可写 `setDeltaMovement`/`setPos`（仅视觉，服务端会纠正）。

## addon 介入点

1. **遍历实体**：`mc.level.getEntities(...)` 或 `ClientLevel.getEntities().getAll()`；射线拾取用 `ProjectileUtil.getEntityHitResult(...)` / `LocalPlayer` 视线射线。
2. **筛选**：`instanceof Player/LivingEntity`，`entity.getType()` 比对 `EntityType`，或用 `EntitySelector` 谓词。
3. **拦截创建/移除**：Mixin `handleAddEntity` / `handleRemoveEntities`，或订阅 Meteor `EntityEvent`（`EntitySpawn`/`EntityRemove`）与 `EntityGameEvent`。
4. **拦截 tick**：Mixin `entity.tick()` / `baseTick()`（慎用，高频）。
5. **改状态**：远端实体 `setNoAi`/`setInvisible`/`setSprinting` 等「本地表现」方法；本地玩家走《玩家移动机制》与《玩家生命周期》。
6. **读旧位置做插值**：`entity.xo/yo/zo`、`entity.setOldPosAndRot()`、`entity.getKnownMovement()`。

## 常见坑

1. **`getDeltaMovement()` 返回可变 Vec3，`setDeltaMovement` 校验有限性**：NaN/Inf 会被静默忽略。
2. **`position()` 返回内部引用**：直接改 `position().x` 无效且危险，改位置用 `setPos/setPosRaw/teleportTo`。
3. **移除即是从世界剥离，别挽留引用**：实体被移除后 `level.getEntity(id)` 返回 null；addon 缓存实体对象要在 tick 里校验 `isRemoved()`。
4. **`isAlive` 分基类/子类语义**：`Entity` 判 `!isRemoved`，`LivingEntity` 多判血量>0；跨类型调用要清楚接收者。
5. **骑乘/乘客**：乘客不单独 tick，移除一个实体时 `stopRiding` 会级联处理乘客，别在 `setRemoved` 里手动强改骑乘关系。
6. **客户端改血量/伤害是视觉**：真正结算在服务端 `LivingEntity.hurtServer(ServerLevel, DamageSource, float)`；客户端 `hurtClient(DamageSource)` 只是表现。
7. **`ClientLevel.addEntity` 会先清同 id**：同 id 重复 add 会先 discard 旧的，这是防重复的最后一道防线。
