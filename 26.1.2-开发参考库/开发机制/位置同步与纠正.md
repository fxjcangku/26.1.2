# 位置同步与纠正

> 源码依据：Minecraft原始源码/net/minecraft/client/multiplayer/ClientPacketListener.java 与 net/minecraft/network/protocol/game/ 及 net/minecraft/world/entity/ 26.1.2 Mojang官方映射

本文讲「客户端本地位置与服务端权威位置如何同步、何时被纠正」。核心结论：**本地玩家位置由客户端预测（`LocalPlayer` 每 tick 移动并 `sendPosition` 上报），服务端校验后可能下发 `ClientboundPlayerPositionPacket` 强制纠正；客户端收到后 `setValuesFromPositionPacket` 重置本地坐标并回 `ServerboundAcceptTeleportationPacket` 确认**。addon 做「飞行绕检 / 反拉回」要在这里理解「何时、因何、被拉回到哪」。

---

## 一、两个权威与两类包

| 方向 | 包 | 作用 |
|------|-----|------|
| C→S | `ServerboundMovePlayerPacket.Pos / PosRot / Rot / StatusOnly` | 客户端上报本地移动（见玩家移动机制） |
| S→C | `ClientboundPlayerPositionPacket` | 服务端强制同步/纠正玩家位置朝向 |
| S→C | `ClientboundPlayerRotationPacket` | 服务端只纠正朝向（`handleRotatePlayer`） |
| C→S | `ServerboundAcceptTeleportationPacket` | 客户端确认收到纠正（带包 id） |

位置语义：**客户端是预测权威（本地先动），服务端是校验权威（犯规就纠正）**。正常移动两套位置基本一致；飞行/加速/瞬移等异常移动让二者偏差累积，最终服务端下发纠正包把玩家「拉回」。

---

## 二、客户端上报链路（预测侧）

（详见《玩家移动机制》）每 tick `LocalPlayer.tick()` → `sendPosition()`：
- 位移超过阈值 `Mth.lengthSquared(dx,dy,dz) > (2.0E-4)^2` 或 `positionReminder >= 20`（20 tick 兜底）才发 `Pos`/`PosRot`。
- 朝向变化才发 `Rot`；只有 `onGround`/碰撞变化才发 `StatusOnly`。
- 30 秒内无输入变化仍会由兜底计数强制补发，保证服务端不会因静默超时踢人。

## 三、服务端纠正包结构（`ClientboundPlayerPositionPacket`）

```java
public record ClientboundPlayerPositionPacket(int id, PositionMoveRotation change, Set<Relative> relatives)
    implements Packet<ClientGamePacketListener> {
    public static ClientboundPlayerPositionPacket of(int id, PositionMoveRotation values, Set<Relative> relatives);
    public void handle(ClientGamePacketListener listener) { listener.handleMovePlayer(this); }
}
```

- `id`：本次纠正的序列号，客户端确认时回传。
- `change`：`PositionMoveRotation`（record），含 `position : Vec3`、`deltaMovement : Vec3`、`yRot`、`xRot`。
- `relatives`：`Set<Relative>` 相对坐标标志，逐轴决定「绝对覆盖」还是「相对当前值偏移」。`Relative`（`net/minecraft/world/entity/Relative`）含 `X/Y/Z/X_ROT/Y_ROT/DELTA_MOVEMENT` 等常量。

## 四、纠正落地（`handleMovePlayer` → `setValuesFromPositionPacket`）

```java
// ClientPacketListener.handleMovePlayer  源码 804 行
public void handleMovePlayer(final ClientboundPlayerPositionPacket packet) {
    PacketUtils.ensureRunningOnSameThread(packet, this, this.minecraft.packetProcessor());
    Player player = this.minecraft.player;
    if (!player.isPassenger()) {
        setValuesFromPositionPacket(packet.change(), packet.relatives(), player, false); // 非插值覆盖
    }
    this.connection.send(new ServerboundAcceptTeleportationPacket(packet.id()));       // 确认
    this.connection.send(new ServerboundMovePlayerPacket.PosRot(                        // 把纠正后的位置回补一针
        player.getX(), player.getY(), player.getZ(), player.getYRot(), player.getXRot(), false, false));
    this.minecraft.level.getBlockStatePredictionHandler().onTeleport();                 // 重置方块预测
}
```

`setValuesFromPositionPacket`（源码 816 行）核心逻辑：

```java
PositionMoveRotation newValues = PositionMoveRotation.calculateAbsolute(currentValues, change, relatives);
boolean tooBig = currentValues.position().distanceToSqr(newValues.position()) > 4096.0; // 距离^2 > 4096（即 64 格）不插值
if (interpolate && !tooBig) {
    entity.moveOrInterpolateTo(...);     // 平滑插值（滚回包用）
} else {
    entity.setPos(newValues.position()); // 直接落位
    entity.setDeltaMovement(newValues.deltaMovement());
    entity.setYRot(newValues.yRot()); entity.setXRot(newValues.xRot());
    entity.setOldPosAndRot(...);         // 同步旧位置，避免渲染跳变
}
```

关键点：
- `calculateAbsolute` 按 `relatives` 逐轴合并：该轴在 `relatives` 里就做「当前值 + change」的相对偏移，否则直接取 change 的绝对值。
- 骑乘时（`player.isPassenger()`）**不**套用位置纠正（因为位置由载具决定）。
- `interpolate=false` 用于「传送/首次到位」，直接 `setPos`；`interpolate=true`（首次进世界 `startWaitingForNewLevel` 相关）用 `moveOrInterpolateTo` 平滑。
- 纠正后必做三件事：回 ack、回补一针 `PosRot`（让服务端确认你「已在纠正点」）、重置方块预测处理器（避免旧的破坏/放置预测残留）。

## 五、朝向纠正（`handleRotatePlayer`）

```java
public void handleRotatePlayer(final ClientboundPlayerRotationPacket packet) {
    Set<Relative> relatives = Relative.rotation(packet.relativeY(), packet.relativeX());
    // calculateAbsolute 后 setYRot/setXRot/setOldRot
    this.connection.send(new ServerboundMovePlayerPacket.Rot(player.getYRot(), player.getXRot(), false, false));
}
```
只纠朝向、不动位置，回补一针 `Rot`。

## 六、传送的特殊路径（跨维度/重登）

- 首次进世界：`handleLogin` 创建 `ClientLevel` + `LocalPlayer`，`startWaitingForNewLevel` 等待区块加载，期间玩家位置以服务端 `CommonPlayerSpawnInfo` + `ClientboundPlayerPositionPacket` 的到达为准。
- 服务端 `teleportTo`（跨维度、末地/下界）：走 `handleRespawn`（维度变了重建 `ClientLevel`）+ 后续 `ClientboundPlayerPositionPacket`（同维度重定位）。
- `Relative.DELTA_MOVEMENT` 用于「相对速度纠正」。

## addon 介入点

1. **拦截纠正**：Mixin `ClientPacketListener.handleMovePlayer`（HEAD：可读纠正目标；RETURN：可看纠正后位置；取消整个方法可「拒绝拉回」，但会让服务端持续纠偏，高风险）。
2. **读纠正前后位置**：`player.position()` 在 `handleMovePlayer` 后被重置，可在 HEAD 时先存旧位置做差值分析。
3. **检测被纠正**：订阅 Meteor `PacketEvent.Receive`，过滤 `ClientboundPlayerPositionPacket`，`tooBig`（>64 格）即「瞬移级纠正」。
4. **主动顺滑**：`Player.moveOrInterpolateTo(...)` 是「让本地位置平滑逼近目标」的现成入口，addon 可用它做客户端平滑，而不直接 `setPos`。
5. **伪造确认**：理论上可拦截/伪造 `ServerboundAcceptTeleportationPacket` 的 id，但会导致状态机错乱，仅协议研究用。

## 常见坑

1. **`setPos` 只改本地**：不会触发 ack/回补，服务端下一帧仍按自己的权威拉你；要「合法移动」必须走 `move`/`sendPosition` 或直接认命接受纠正。
2. **纠正后必须回 ack + 回补 PosRot**：这是协议的握手语义，若 Mixin 只做一半（比如吃了纠正不回 ack），服务端会认为你没收到，反复下发/超时踢人。
3. **骑乘不纠位置**：`handleMovePlayer` 对 `isPassenger()` 直接跳过；骑乘位置由 `ServerboundMoveVehiclePacket` 走载具同步，别在骑乘状态下做位置 hack。
4. **相对坐标 vs 绝对坐标**：`relatives` 决定轴语义，读纠正包时别默认 `change.position()` 就是绝对目标，要先看 `relatives.contains(Relative.X/Y/Z)`。
5. **`distanceToSqr > 4096` 阈值**：源码硬编码 64 格距离阈值决定「能否插值」，客户端预测与服务器偏差超过这个量级会被判定为瞬移（异常检测常见指标之一）。
6. **纠正会重置方块预测**：`getBlockStatePredictionHandler().onTeleport()` 会清空挖掘/放置预测；addon 在纠正瞬间做方块交互可能因为预测被清而行为异常。
