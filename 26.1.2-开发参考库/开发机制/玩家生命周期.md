# 玩家生命周期

> 源码依据：Minecraft原始源码/net/minecraft/client/multiplayer/ClientPacketListener.java 与 net/minecraft/client/player/LocalPlayer.java 及 net/minecraft/client/Minecraft.java 26.1.2 Mojang官方映射

本文讲「本地玩家 `LocalPlayer` 从创建、进世界、死亡/重生、跨维度、到退出销毁」的完整生命周期。核心结论：**`LocalPlayer` 在 `ClientPacketListener.handleLogin` 时首次创建并挂到 `Minecraft.player`，跨维度在 `handleRespawn` 里重建 `ClientLevel` 但复用旧 `LocalPlayer`，退出世界在 `Minecraft.disconnect` 里销毁 `ClientLevel` 并把 `player` 置空**。addon 的模块/状态务必在「玩家与 level 判空 + 监听生命周期事件」上做防护。

---

## 一、创建（`handleLogin` 首次进世界）

`ClientPacketListener.handleLogin(ClientboundLoginPacket)`（源码 499 行）是「进入 PLAY 阶段、进入世界」的唯一入口。关键顺序：

```java
this.minecraft.gameMode = new MultiPlayerGameMode(this.minecraft, this);   // 先建游戏模式
CommonPlayerSpawnInfo spawnInfo = packet.commonPlayerSpawnInfo();          // 出生信息（维度/类型/种子/海平面）
// ...
this.level = new ClientLevel(...);          // 建客户端世界
this.minecraft.setLevel(this.level);        // 挂到 mc.level
if (this.minecraft.player == null) {
    this.minecraft.player = this.minecraft.gameMode.createPlayer(this.level, new StatsCounter(), new ClientRecipeBook());
    this.minecraft.player.setYRot(-180.0F);
    // 单机：同步单机服务端的 UUID
}
this.setClientLoaded(false);                 // 尚需加载
this.minecraft.player.resetPos();            // 重置姿态/找安全落脚点/清速度
this.minecraft.player.setId(packet.playerId());               // 设置实体 id
this.level.addEntity(this.minecraft.player);                   // 注册进实体表
this.minecraft.player.input = new KeyboardInput(this.minecraft.options); // 装配键盘输入
this.minecraft.gameMode.adjustPlayer(this.minecraft.player);
this.minecraft.setCameraEntity(this.minecraft.player);         // 相机切到玩家
this.startWaitingForNewLevel(this.minecraft.player, this.level, LevelLoadingScreen.Reason.OTHER);
```

要点：
- `createPlayer`（`MultiPlayerGameMode`）实际 `new LocalPlayer(...)`。
- `LocalPlayer` 赋值给 `Minecraft.player` 只在 `player == null` 时发生——**第一次进世界创建，之后复用**。
- `setClientLoaded(false)` → 等区块加载完成（`startWaitingForNewLevel`）后置 true（`setClientLoaded(true)`），期间 `LocalPlayer.tick()` 被 `hasClientLoaded()` 短路（源码 230 行 `if (this.connection.hasClientLoaded())`）。

## 二、存活期间（每 tick）

创建后每 tick 由 `ClientPacketListener` 所在世界推进：
- `Minecraft.tick()` → `this.level.tickEntities()` → `ClientLevel.tickNonPassenger(player)` → `player.tick()` → `LivingEntity.tick` → ... → `LocalPlayer.tick()`（发包）、`aiStep()`（移动逻辑）。
- 血量/饥饿由 `ClientboundSetHealthPacket`（`handleSetHealth`）同步；死亡由 `ClientboundGameEventPacket`（`handleGameEvent`，`Event.DEATH`）或客户端本地 `isDeadOrDying()` 判定。

## 三、死亡与重生

```java
// LocalPlayer.respawn()  源码 328 行
public void respawn() {
    this.connection.send(new ServerboundClientCommandPacket(ServerboundClientCommandPacket.Action.PERFORM_RESPAWN));
    KeyMapping.resetToggleKeys();
}

// LocalPlayer.resetPos()  源码 743 行 —— 重生/传送后清姿态
public void resetPos() {
    this.setPose(Pose.STANDING);
    if (this.level() != null) { /* 从当前 y 向下找安全落脚点 setPos */ }
    this.setDeltaMovement(Vec3.ZERO);
    this.setXRot(0.0F);
    this.setHealth(this.getMaxHealth());
    this.deathTime = 0;
}
```

- 死亡屏（`DeathScreen`）由 `ClientboundGameEventPacket` 触发显示；点击重生调 `LocalPlayer.respawn()` 发 `PERFORM_RESPAWN`。
- 服务端回应新的 `ClientboundRespawnPacket`（死亡重生往往维度不变）走 `handleRespawn` 的「同维度」分支刷新出生状态。

## 四、跨维度 / 重登（`handleRespawn`）

`ClientPacketListener.handleRespawn(ClientboundRespawnPacket)`（源码 1254 行）：
1. 读 `spawnInfo.dimension()`、比较 `oldPlayer.level().dimension()`。
2. `dimensionChanged` 为真 → 重建 `ClientLevel`（复用 `levelData` 的难度/硬核）、`setLevel`、`setClientLoaded(false)`。
3. 复用 `oldPlayer`（`this.minecraft.player` 不重建），更新其出生/复活位置、清缓存、重新 `addEntity` 到新 level、重新 `startWaitingForNewLevel`。
4. `dimensionChanged` 为假（同维度重生/重登）→ 只更新 `CommonPlayerSpawnInfo` 关联信息。

结论：**跨维度时 `LocalPlayer` 实例不变，`ClientLevel` 换新**——addon 里缓存的 `mc.player` 引用仍有效，但缓存 `mc.level` 必须重新获取。

---

## 五、退出世界（`Minecraft.disconnect`）

退出链路：`ClientPacketListener.onDisconnect(DisconnectionDetails)`（被踢/断连）或用户点「断开连接」→ `Minecraft.disconnect(Screen, boolean, boolean)`（源码 2199 行）：

```java
ClientPacketListener connection = this.getConnection();
if (connection != null) {
    this.dropAllTasks();
    connection.close();                              // 关连接
    if (!keepResourcePacks) this.clearDownloadedResourcePacks();
}
this.playerSocialManager.stopOnlineMode();
// ... 停记录、关集成服、清 level/player
```

- 随后 `ClientLevel.disconnect(Component)`（源码 442 行）清理世界资源，`Minecraft.player` / `Minecraft.level` 被置 null（`clearLevel` 相关逻辑 / `setLevel(null)`）。
- 脱离世界后 `mc.getConnection()` 返回 null（因 `player == null`）。
- 本地缓存的世界实体在 `ClientLevel` 里随 `removeEntity(idx, DISCARDED)`（源码 420 行）批量清理。

## addon 介入点

1. **判空铁律**：任何入口先验证 `mc.player != null && mc.level != null && mc.getConnection() != null`。
2. **监听进世界/退世界**：Meteor `WorldEvent` / `PlayerEvent`（Meteor 在 `handleLogin`、`onDisconnect` 等注入）；或直接 Mixin `ClientPacketListener.handleLogin` 的 TAIL、`Minecraft.disconnect` 的 HEAD。
3. **监听重生/维度切换**：Mixin `handleRespawn`、订阅 `ClientboundRespawnPacket` 接收事件；维度切换时刷新对 `mc.level` 的引用。
4. **玩家状态钩子**：`LocalPlayer.resetPos()`（重生定位）、`LocalPlayer.hurtTo()`（二次扣血表现）、`LocalPlayer.onUpdateAbilities()`（能力变化发包）都是可覆写/拦截点。
5. **死亡检测**：`mc.player.isDeadOrDying()`（`LivingEntity`，源码），或拦截 `ClientboundGameEventPacket` 的 `Event.DEATH`。

---

## 常见坑

1. **缓存 `mc.level` 跨维度失效**：维度切换重建 `ClientLevel`，旧引用对象被废弃；长时间持有的 `ClientLevel` 引用要每 tick 校验 `mc.level == cached`，否则操作错世界。
2. **`mc.getConnection()` 退世界后为 null**：先判 `player != null` 再拿 `getConnection()`，再判 `.getConnection().isConnected()`。
3. **`LocalPlayer` 实例跨维度复用**：别在维度切换时重建玩家级缓存（`mc.player` 引用不变），但玩家身上的 world 引用变了。
4. **进世界早期有 `hasClientLoaded()` 门槛**：`LocalPlayer.tick()` 在 `hasClientLoaded()` 为 false 时整体短路（不发移动包）；加载屏期间 addon 触发移动/交互可能不生效。
5. **`respawn` 需要主动调**：客户端死亡后玩家不会自动重生，需死亡屏点击或 addon 调 `mc.player.respawn()`。
6. **`resetPos` 会清速度与姿态**：重生/传送会 `setDeltaMovement(ZERO)`、`setHealth(max)`，addon 若在重生瞬间写速度会被立刻清掉。
